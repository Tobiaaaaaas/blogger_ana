# 06 · 推送

**管什么**：把指定博主池在回看窗口内的观点，实时、滚动地推成一张卡到飞书。
**不管什么**：怎么抓帖（见 01）／一条帖怎么读出观点信号（见 02）／单博主报告（见 03）／全博主对比（见 04）／回测（见 05）。

---

## 06§0 边界

**输入**：板块 —— `short`（超短）或 `swing`（波段）。一次只推一个板块。

**博主池是指定的** —— 每个板块一份固定名单，写在配置里（§9）。名单顺序就是卡面上的显示顺序，不重排、不按当天表现排。

| 项 | 值 |
|:---|:---|
| 命令 | `python -m push <板块>` |
| 产物 | 飞书群里的一张卡 · `data/state/push_<板块>.json` · `data/briefings/<日期>_<时刻>_<板块>.json` |

**代码包与 `blogger/` 同级** —— 推送是独立的一条线，不塞进 `blogger/` 里。

**只考察上证指数** —— 一条观点信号要上卡，`idx` 必须是 `上证指数`。与 05§0 同一口径。

**两个板块是两条独立的线**：各有各的博主池、回看窗口、状态文件、飞书群。一个失败不牵连另一个，**也绝不互相替代**。

**推送不另立一套抓法与读法** —— 每一档的抓与判走 01 与 02（§5.4、§5.5），初始化的那一遍也一样（§4）。本文只说「什么时候调、拿哪一段、怎么挑」。

**一条帖怎么读、读完怎么算，与 03 是同一套** —— 同一条规则、同一份判断缓存、同一个 `pub`、同一个参考价。**两边结果必须一致。**

| 算什么 | 06 与 03 |
|:---|:---|
| 解析（一条帖读出什么） | **一致** —— 调 02，同一套参数、共用判断缓存（§5.5） |
| 验证终点 | **一致** —— 02§4.1／03§3.2，由 `spec` 定，**终点就是博主说的那一天，不顺延** |
| 交易日跨度 | **一致** —— 03§3.4，由终点与发帖日算（§5.6 靠它分档） |
| **参考价** | **一致** —— 都是发帖时刻那根 30 分钟线（02§2.1）；推送每一档自己把它备到本档时刻（§5.3） |
| 终点价 | **不取** —— 06 这边终点还没到，没有价可读；03 取终点日最后一根 30 分钟线的收盘价 |
| 收益率、得分 | **不算** —— 推送不打分，只用方向与终点；03§3.5 |
| 复盘／过期的筛选 | **一致** —— §5.7 的淘汰就是 03§3.6 那一道；「这条是不是复盘」的语义判断归 02（02§4.2），03 那边也不重判 |

## 06§1 一图流

**初始化（`--init`，只跑一次）**

```
博主池
   │
   ▼
① 抓帖 ── 池里每位抓一次，只抓**窗口内那一段**（§5.4 的同一套）
   │
   ▼
② 解析 ── 只判**窗口内那些帖**；判过的走缓存（§5.5 的同一套）
   │
   ▼
③ 并入 ── 这一位窗口内还在的行，逐条并进初始分布（§5.6 第 2 步同一条）
   │
   ▼
④ 落状态 ── data/state/push_<板块>.json
```

**每一档推送**

```
被计划任务叫醒
   │
   ▼
① 不在档上？ ──► 打印一行、退出（不碰任何状态、不发任何东西）
   │
   ▼
② 拿进程锁 ── 已有进程在跑？ ──► 直接退出
   │
   ▼
③ 备料行情 ── 把七个主指数的 30 分钟线补到本档时刻（§5.3）
   │
   ▼
④ 抓增量帖 ── 每位从**各自的续抓起点**往后抓（01§5）
   │
   ▼
⑤ 解析增量 ── 只判这一轮新抓回来的帖；判过的走缓存
   │
   ▼
⑥ 淘汰 ── 状态里滑出窗口的、终点不成立的、终点已过的，逐条丢掉
   │
   ▼
⑦ 并入 ── 这一轮新产出、符合标准的信号并进状态
   │
   ▼
⑧ 计数 ── 每位取窗口内 `pub` 最大的那条，再数几个人看多、几个人看空
   │
   ▼
⑨ 渲染卡片 → 推送 → 落档 → 推进状态
```

**只有 ⑤ 与 ⑨ 里那一段总结会用模型**（初始化那一次也调模型 —— 用在 §4 的解析里）—— 卡片上的每一行都从状态里现成取，一个字都不经模型重写。

**初始化是一次性的，之后全是增量**：初始化把窗口内那些帖判一遍、攒出初始分布；此后每一档只处理新帖，靠 `pub` 把滑出窗口的旧条目丢掉（§5.7）。滚动语义就是这么来的。

状态里存的是「窗口内还在有效期的那几条」，不是每位一条。他最新的判断过期时要能退回次新那条 —— 见 §5.6。

**推送是实时增量，回测是事后重算** —— 两条路，**同一套规则，结果必须一致**（05§2）。

## 06§2 两个板块

| 项 | 超短 | 波段 |
|:---|:---|:---|
| 卡面上写着的名字 | 超短 | 波段 |
| 卡内标签 | `超短(0-1日)` | `波段(2日+)` |
| 标记 | ⏱️ | 🌊 |
| 收哪些信号 | 交易日跨度 ≤ 1 | 交易日跨度 ≥ 2 |
| 回看窗口 | 前 3 个交易日 | 前 3 个交易日 |
| 什么时候推 | 交易日 20 档 · 非交易日 5 档 | 同左 |

**分档按交易日跨度**（03§3.4），与 04§3.4 同一口径 —— 不是卡片上的周期词。

**算不出跨度的信号两张卡都上不了**：`long` 没有验证终点；**终点落不到交易日的**、终点超出日历覆盖的，跨度同样是 `None`。来源见 03§3.4。其中终点落不到交易日的这一类，§5.7 另有一道同判据的机械兜底（与 03§3.6 ② 同一条）。

**上不了卡的信号照进报告** —— 推送是报告（03）在时间轴上的一个切片，不是另一套统计；卡上没有它，报告里照样有。

## 06§3 回看窗口

**起点 = max(前 N 个交易日的 00:00, 下限)**，下限是 `push.window.floor`（§9）。

| 板块 | 取前几个交易日 | 交易日起点 |
|:---|:---:|:---|
| 超短 | 3 | 往前数第 3 个交易日的 00:00 |
| 波段 | 3 | 往前数第 3 个交易日的 00:00 |

举例：运行当日 2026-09-17 周四，交易日起点是 09-14 周一 00:00；下限 `09-17 02:00` 压过它，窗口起点就是 09-17 02:00。

**下限是给「盘外大事落地」留的** —— 落地之前的观点，背景已经换过一轮了。现设 2026-09-17 02:00（美联储决议落地）。下限压过交易日起点时，卡面覆盖行改写成起点时刻（§6.2）。**它早晚失效** —— 前 N 个交易日的 00:00 一旦晚过它就不再起作用，键留着还是删掉都行。

**推送当天不是交易日** → 先退到它之前最近的那个交易日，再往前数。举例：2026-09-05 周六那一档，交易日起点是 09-01 周二 00:00。

**交易日历**：官方日历，含未来（01§10.3）。窗口起点每一档现算，不存进状态 —— 存了就会随时间失真。日历覆盖不到那么早 → 窗口算不出来 → 本档不推。

**下限只有推送吃** —— 回测（05§2）的窗口是纯交易日口径。

## 06§4 初始化

**这是一个显式动作 —— 一个板块跑一次；读法改了再跑一次（本节末条）。**

**行情先备到本档时刻**（§5.3）—— 与每一档同一条；备不到就整条命令停下。

带 `--init` 时：

| 步 | 动作 |
|:---:|:---|
| ① | 池里每一位抓一次帖 —— **只抓窗口内那一段**；起点取「他的续抓起点」与「窗口起点」里晚的那个（§5.4、01§5） |
| ② | 解析 —— **只判窗口内那些帖**，判过的走判断缓存（§5.5） |
| ③ | 取这一位窗口内还在的全部行，逐条并入初始分布（筛法与 §5.6 第 2 步同一条） |
| ④ | 落 `data/state/push_<板块>.json` |

不带 `--init` 时：

| 状态文件 | 结果 |
|:---|:---|
| 在 | 正常推一档（§5） |
| 不在 | 报错退出 —— 窗口没建过，没有分布可推，也不替你猜 |

几条：

- **不写报告产物** —— `data/signals/` 与 `reports/per_blogger/` 全归 03（03§0）；这边只用判断缓存（03§2.2），与报告链共用同一份、同一套读法
- **起点被窗口掐了头的才不推进「抓取截止」**（01§5）—— 掐了头就不算抓全了，不推进，下一档才会从原处接着抓，窗口起点之前那一段不会被永久跳过；续抓起点本来就落在窗口里的（刚抓过的），照常推进
- 推送的池子与报告链的名单各自独立、互不干涉，不约定谁先跑。报告链要用这批人当样本，得删净重引（03§7）
- 状态里只记初始化标记与分布本身（每位若干条，窗口内还活着的那几条），不记「上次推送时刻」 —— 窗口起点每档现算（§3），不依赖上次跑没跑过。停机几天再恢复，不需要对账
- **读法一改（02§11 的规则指纹变），`--init` 要重跑一次** —— 判断缓存整批作废，分布也得按新读法重建。不带 `--init` 的档只并入「这一轮新判出来的」行（§5.5），指纹变后的**第一跑**才并得进窗口内全部；那一跑要是没落到状态（`--dry-run`、中途报错退出），留的就还是旧读法的行，往后每档都并不进新的，直到那些帖自己滑出窗口

> **窗口之外的一概不碰** —— 不抓、不判、不并。这样攒出的分布只覆盖窗口内那几天；报告链要那份全量，自己跑 03（03§0）。

## 06§5 每一档推送

### 5.1 在不在档上

现刻（北京时间）对照本板块的时刻表（§9）。不在档上 → 打印一行说明是哪个规则挡下的，退出。

**两张表都不含现刻时，不碰任何东西就退** —— 用不着日历也判得出不在档上。落进表里的才去确保日历可用（01§10.3，过期要联网补一张），再定是交易日还是非交易日。

这一步在拿锁、抓帖、发消息之前 —— 不在档上时不碰状态、不发消息。

**`--force` 与 `--init` 都不走这道检查**（§4、§8）：`--force` 把此刻当成一档推出去。漏了一档又不想等下一档时用；落档与卡面写的都是实际执行的时刻（§6.2）。

| 日子 | 时刻表 | 档数 |
|:---|:---|:---:|
| 交易日 | 09:00～15:00 每 30 分钟；16:00～22:00 每整点 | 20 |
| 非交易日 | 09:00、12:00、15:00、18:00、21:00 | 5 |

**两个板块都是这两张表** —— 非交易日也推超短。

**日子按交易日历分**（01§10.3），不按星期几。

### 5.2 拿进程锁

上一档还没跑完 → 直接退出，不做任何事。免得两档同时抓帖。

### 5.3 备料行情

解析新帖要用行情注记（02§2.2），注记取的是**发帖时刻那根 30 分钟线**（02§2.1） —— 与 03 同一条口径，不是另一套算法（§0）。所以每一档在解析之前，先把七个主指数的 30 分钟线备到**本档时刻**。

| 情形 | 怎么办 |
|:---|:---|
| 已经到本档时刻 | 跳过，不重复抓 |
| 没到 | 补一次（01§10 的同一套） |
| 补完还不到 | **本档不推**（§7） |

**要的是「结束时刻不晚于本档时刻」的最后一根** —— 档落在整点整半（§5.1），本档时刻正是某根的收盘时刻；本档落在当天第一根收出来之前（`09:00`、`09:30` 这两档，以及盘前、非交易日）就退到上一交易日末根。

**这条线只服务注记** —— 卡上不显示行情；交易日历另有官方日历（01§10.3），不靠它倒推。

### 5.4 抓增量帖

博主池里每一位从各自的续抓起点（01§5）往后抓到此刻，并入 `data/posts/`。

- 起点是该博主 `scrape_time` 所在那一日的零点，不是上一次推送的时刻 —— 与报告链走的是同一个水位、同一处算法
- **某一位抓失败只影响他自己**：他不中断本档，状态里那条旧条目照留；他的 `scrape_time` 没推进，下一档还会从原处接着抓。**抓完就地校验一次**（01§9），硬失败按抓失败同样处置
- 从没抓全过的博主（文件里没有 `scrape_time`）退回默认起始时间全量重抓（01§4、01§5）

### 5.5 解析增量

**只判窗口内还没判过的帖**。判过的帖走判断缓存（03§2.2），不重判。

**窗口之外的一条不判** —— 与这一档的分布无关，判了白花模型钱。真要判它们，报告链自己会判（判断缓存两边共用，03§2.2）。这一条与 §4 初始化是同一口径。

批的大小、字数预算、单帖上限、批与批之间的间隔，照 03§2.2 同一套参数 —— 推送与报告读帖的方式必须一致。

**「复盘／过期」这类全归 §5.7 的淘汰** —— 02 只判「这处表述是不是对未来的承诺」（02§4.2），按时间的判据在 §5.7，与 03§3.6 同一条。

### 5.6 更新分布

对池里每一位，按先筛后取三步走：

| 步 | 动作 |
|:---:|:---|
| 1 | 淘汰（§5.7）：状态里滑出窗口的、终点不成立的、终点已过的，逐条丢掉 |
| 2 | 并入：这一轮新产出的信号里，`idx` 是 `上证指数`、交易日跨度落在本板块（§2）的，逐条并进状态 |
| 3 | 取值：这位博主取状态里窗口内 `pub` 最大的那条 —— 就是他本档的立场 |

**第 2 步并入的也要先过第 1 步那三条判据** —— 这一轮新产出里终点不成立的、已经过期的，当场丢掉，不留到下一档去淘汰。两处是同一条判据（§5.7）。

**「最新」怎么比**（要确定、可复现）：

| 顺序 | 比什么 |
|:---:|:---|
| 1 | `pub` 大的赢 |
| 2 | `pub` 并列 → 验证终点更晚的赢（同一帖出了两条同板块信号，如「今天涨，明天也涨」） |
| 3 | 仍并列 → 先出现的赢 —— 信号文件与状态文件按同一个顺序排（`pub`／`idx`／`spec`），两条链在这条判据上同序 |

**状态里留窗口内的好几条** —— 取值时从新到旧逐条退：最新那条过期，就退到次新那条。

> **「先筛后取最新」不是「先取最新再淘汰」。** 回测走的是同一套规则（05§3），**两边结果必须一致**。

**这一轮没有新帖 → 第 1、3 步照走**（该淘汰的照样淘汰、取值照样取），只是第 2 步无新可并。

### 5.7 淘汰

每次推送前，把状态里这三类条目丢掉：

| 丢哪类 | 判据 |
|:---|:---|
| **滑出窗口** | `pub` 早于本档现算的窗口起点 |
| **终点没开市** | 验证终点落不到交易日 —— 这条表述不成立（03§3.6 ②） |
| **终点已过** | 本档时刻不早于验证终点的收盘时间（含正好收盘那一刻） —— 03§3.6 ③ 的实时版 |

第一条让「回看窗口」真的在滚动；后两条让卡上只留**终点确实存在、且还没到**的观点 —— 判据与 03§3.6 的状态机是同一条（次序也一样），两边不能各判各的。

**另有一道前视** —— 本档只看 `pub` ≤ 本档时刻的帖，与 05§3 同一条。它不是「淘汰哪一类」，是「哪些帖这一档还看不见」。

**算不出跨度的压根进不来**（§2） —— 这三条只判跨度落得进本板块的信号。

被丢掉的条目，本档就不上卡。一位博主所有条目都被丢光了，他本档才不显示、不计数；他下次发了新帖再回来。

### 5.8 计数

```
看多 = 上卡的条目里 d = +1 的条数
看空 = 上卡的条目里 d = −1 的条数
```

没表态的博主不计入。计数只在上了卡的条目上算 —— 淘汰掉的不算。

### 5.9 渲染卡片

见 §6。

### 5.10 推送、落档、推进状态

- 卡片发到本板块自己的群。失败连同首次一共试 3 次（超时 20 秒，间隔 3 秒起递增）
- 重试仍失败 → 往同一个群发一条纯文本的失败提醒（不检查这条提醒自己是否成功）
- **不补发**：本档就丢了，下一档带的是最新的分布
- 落档 `data/briefings/<日期>_<时刻>_<板块>.json`；同一档重跑就覆盖同一份
- **最后才推进状态文件** —— 抓帖的水位不归它（那是抓取自己写的 `scrape_time`，01§7）

## 06§6 卡片

### 6.1 一张波段卡

**这一张是示意卡** —— 不是某一档的实跑产物：名字、引文、时刻都取自库里的真帖，但条数与多空比不等于任何一档的真实分布。

```
📊 波段 14:00 · 09-09 周三
🕐 覆盖：波段板块 前3个交易日到现在（09-04 起）
🌊 **波段(2日+)** · 2多/2空
🔴 **故乡的云ZYH** 看多 · 终点 09-11 收盘
　重点原话：“下周A股大概率打破震荡格局，迎来结构性行情修复”（09-05 10:58）
🟢 **知行合一** 看空 · 终点 09-11 收盘
　重点原话：“宣告下周的破位大跌已经箭在弦上”（09-04 17:46）

### 6.2 逐行从哪来

**第 1 行 · 标题**

| 内容 | 从哪来 |
|:---|:---|
| 📊 | 固定 |
| `波段` | 板块名（超短板块这里就是「超短」） |
| `14:00` | 这一次推送实际执行的时刻（不是应该执行的时刻） |
| `09-09 周三` | 当期日期与星期 |

**第 2 行 · 覆盖范围**

```
🕐 覆盖：波段板块 前3个交易日到现在（09-14 起）
```

`前3个交易日` 与 `09-14` 都从回看窗口现算（§3）。**下限压过交易日起点时换一种写法** —— 不写「前N个交易日」，直接写起点时刻（§3）：

```
🕐 覆盖：波段板块 09-17 02:00 起到现在
```

**第 3 行 · 板块头**

```
🌊 **波段(2日+)** · 2多/2空
```

`2多/2空` 是本档的计数（§5.8）。不写分母 —— 卡上不给「多少人没表态」这个数。

**每位博主两行**

第 1 行 —— 谁、什么态度、什么时候见分晓：

```
🔴 **故乡的云ZYH** 看多 · 终点 09-11 收盘
```

- 🔴 = 看多（`d = +1`），🟢 = 看空（`d = −1`） —— 红涨绿跌，A 股习惯
- 加粗的是博主名，顺序就是池子里的顺序
- 后面跟验证终点：`终点 MM-DD 收盘`。日历含未来（01§10.3），所以「明天」「下周」这类终点都算得出

第 2 行 —— 原话：

```
　重点原话：“下周A股大概率打破震荡格局，迎来结构性行情修复”（09-05 10:58）
```

- 括号里是这句话所属帖子的发布时间（精确到分钟），不是这张卡的发布时间
- 引文逐字来自帖子的标题或正文（02§9），截断长度照 `parse.quote_limit`（02§12）
- **这一行是整张卡里唯一能自己回去核对的证据**

**底部 · 总结**

```
🧭 波段板块2多2空，多空对短期节奏与空间的判断对立。…
```

**再调一次模型**写的，喂给它的是本档已经算好的分布与计数。写失败 → 兜底成一行计数（`多空版图：2多2空`），不整张卡报废。

### 6.3 零表态时的最小卡

本板块一个人都没上卡时：

```
📊 超短 14:00 · 09-17 周四
🕐 覆盖：超短板块 前3个交易日到现在（09-14 起）
⏱️ **超短(0-1日)** · 0多/0空
（前3个交易日内无人给出本档的上证方向观点）

**不渲染名单、不渲染总结** —— 没有人可讲，就不占地方。末句按窗口天数现算，不写死。**下限压过交易日起点时**，覆盖行与末句都跟着换成起点时刻（§3、§6.2）。

## 06§7 出错

**总原则：宁可少显示，不可显示错的。**

| 情形 | 怎么办 |
|:---|:---|
| **不在档上** | 直接退出，不碰任何状态（§5.1） |
| **上一档还在跑** | 直接退出，不做任何事（§5.2） |
| **池里某位库里没有**（`data/posts/` 下没有他的文件，也就没有 `source_url`） | 跳过他自己，本档照出（01§6） |
| **30 分钟线备不到本档时刻** | 本档不推（§5.3） |
| **某位博主抓帖失败／校验硬失败** | 只影响他自己，本档照出；状态里那条旧条目照留（§5.4） |
| **某位博主解析失败** | 同上 —— 他那一条不动，其余照常 |
| **总结段写失败** | 兜底成一行计数，卡片照发（§6.2） |
| **发卡失败** | 连同首次一共试 3 次；仍失败往同一个群发一条纯文本提醒（§5.10） |
| **某板块没配推送地址** | 该板块失败 —— 不转投另一个群，也不发提醒（提醒也得有地址才能发） |
| **状态文件不在、又没带 `--init`** | 报错退出（§4） |
| **交易日历补不上** | 整条命令到此为止（§5.1） |
| **回看窗口算不出来** | 本档不推（§3） |
| **池子里一位都没有** | 用法错误退出（§0） |

## 06§8 怎么跑

```bash
# 初始化一个板块 —— 建分布，读法改了要重建；池里每位抓一次帖、判窗口内那些帖，慢（§4）
python -m push swing --init
python -m push short --init

# 推一档
python -m push swing
python -m push short

# 补一档：不在时刻表上，也当一档推出去（§5.1）
python -m push swing --force

# 只看不发：打印卡片，不碰飞书、不写状态、不留档
python -m push swing --dry-run
```

- 一道命令只推一个板块
- **叫醒它的调度器是 Windows 任务计划**：按 §5.1 的两张时刻表各注册一批任务，每次带上板块名。注册脚本归部署层，不在本文
- **被叫醒但那一下不在档上，命令自己退出**（§5.1） —— 时刻表在两边各有一份，判据以命令里这份为准
- `--force` 只跳过早退检查，其余一步不省：行情照备、增量照抓、窗口照算，该硬失败的还是硬失败（§5.3）
- `--dry-run` 供手动核对卡面用；正式调度一律不带。状态与留档都不落；抓帖与行情照走、照写 `data/posts/` 与 `data/market/`（`scrape_time` 会推进），下一次真推照常。带 `--init` 时抓帖与解析照走、照写 `data/posts/` 与判断缓存（`scrape_time` 不推进，§4）
- `--force` 与 `--dry-run` 可以同时带 —— 补一档的内容只看不发

## 06§9 可调参数

**下表这些阈值从仓库根的 `config.json` 读**。改参数只改这一份文件，不碰代码。

**另有五样写死在 `push/conf.py` 里** —— 两个板块名（`short`／`swing`）、板块名与卡内标签（超短／超短(0-1日)、波段／波段(2日+)）、行首标记（⏱️／🌊）、两个 `FEISHU_*` 环境变量名、以及「只看上证指数」这个 `idx`。

| 键 | 管什么 | 本文哪一节 | 现值 |
|:---|:---|:---|:---|
| `push.pools.short` / `push.pools.swing` | 两个板块的博主池（名单顺序＝显示顺序） | §0、§6.2 | 21 位 / 29 位 |
| `push.window.short` / `push.window.swing` | 回看窗口（交易日） | §3 | 3 / 3 |
| `push.window.floor` | 窗口起点下限（`YYYY-MM-DD HH:MM`，空串＝不限） | §3 | `2026-09-17 02:00` |
| `push.grid.trading` | 交易日的推送时刻表 | §5.1 | 20 档 |
| `push.grid.restday` | 非交易日的推送时刻表 | §5.1 | 5 档 |
| `push.retries` / `push.retry_delay` | 发卡失败连同首次一共试几次、间隔几秒起 | §5.10 | 3 / 3 |
| `push.webhook_timeout` | 发卡的接口超时（秒） | §5.10 | 20 |
| `push.summary_limit` | 底部总结段的字数上限 | §6.2 | 240 |
| `report.bucket_span` | 两档边界：跨度到几算波段 | §2 | 2 |
| `parse.quote_limit` | 引文的截断长度（字） | §6.2 | 60 |

- `report.bucket_span` 与 03／04 是同一个键 —— 两档边界只有一处；引文长度只有 `parse.quote_limit` 一处（02§12），一份配置喂三处
- 抓取的参数见 01§12；全博主对比的参数见 04§8。**推送与报告读帖的方式必须一致**，所以解析的参数（批大小、字数预算、单帖上限、批间隔）不在这里另配一份，直接照 03§2.2 那一套
