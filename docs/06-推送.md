# 06 · 推送

**管什么**：把指定博主池在回看窗口内的观点，实时、滚动地推成一张卡到飞书。
**不管什么**：怎么抓帖（见 01）／一条帖怎么读出观点信号（见 02）／单博主报告（见 03）／全博主对比（见 04）／回测（见 05）。

---

## 06§0 边界

**输入**：板块 —— `short`（超短）或 `swing`（波段）。一次只推一个板块。

**博主池是指定的** —— 每个板块一份固定名单，写在配置里（§9）。名单顺序就是卡面上的显示顺序，不重排、不按当天表现排。

| 项 | 值 |
|:---|:---|
| 命令 | `python -m push <板块>` |
| 产物 | 飞书群里的一张卡 · `data/state/push_<板块>.json` · `data/briefings/<日期>_<时刻>_<板块>.json` |

**代码包与 `blogger/` 同级** —— 推送是独立的一条线，不塞进 `blogger/` 里。

**只考察上证指数** —— 一条观点信号要上卡，`idx` 必须是 `上证指数`。与 03§4 的榜、04§3.1 同一口径（04§3.1）。

**两个板块是两条独立的线**：各有各的博主池、回看窗口、状态文件、飞书群。一个失败不牵连另一个，**也绝不互相替代**。

**推送自己不抓帖、不解析** —— 抓法全归 01，读法全归 02。本文只说「什么时候调、拿哪一段、怎么挑」。

## 06§1 一图流

**初始化（`--init`，只跑一次）**

```
博主池
   │
   ▼
① 抓帖 ── 每位从**回看窗口起点**抓到今天（01）
   │
   ▼
② 解析 ── 逐帖调 02；判过的走缓存，不重判
   │
   ▼
③ 攒分布 ── 每位取窗口内最新的「上证 + 本档」信号
   │
   ▼
④ 落状态 ── data/state/push_<板块>.json
```

**每一档推送**

```
被计划任务叫醒
   │
   ▼
① 不在档上？ ──► 打印一行、退出（不碰任何状态、不发任何东西）
   │
   ▼
② 拿进程锁 ── 已有进程在跑？ ──► 直接退出
   │
   ▼
③ 备料行情 ── 补到今天并核对（01§10）；已到今天就跳过
   │
   ▼
④ 抓增量帖 ── 每位从**各自的续抓起点**往后抓（01§5）
   │
   ▼
⑤ 解析增量 ── 只判这一轮新抓回来的帖；判过的走缓存
   │
   ▼
⑥ 淘汰 ── 状态里滑出窗口的、终点已过的，逐条丢掉
   │
   ▼
⑦ 并入 ── 这一轮新产出、符合标准的信号并进状态
   │
   ▼
⑧ 计数 ── 每位取窗口内 `pub` 最大的那条，再数几个人看多、几个人看空
   │
   ▼
⑨ 渲染卡片 → 推送 → 落档 → 推进状态
```

**只有 ②⑤ 与 ⑨ 里那一段总结会用模型** —— 卡片上的每一行都从状态里现成取，一个字都不经模型重写。

**初始化是一次性的，之后全是增量**：回看窗口内的帖子只在初始化时读一遍、判一遍；此后每一档只处理新帖，靠 `pub` 把滑出窗口的旧条目丢掉（§5.7）。滚动语义就是这么来的。

状态里存的是「窗口内还在有效期的那几条」，不是每位一条。他最新的判断过期时要能退回次新那条 —— 见 §5.6。

**推送是实时增量，回测是事后重算** —— 两条路，**同一套规则，结果必须一致**（05§2）。

## 06§2 两个板块

| 项 | 超短 | 波段 |
|:---|:---|:---|
| 卡面上写着的名字 | 超短 | 波段 |
| 卡内标签 | `超短(0-1日)` | `波段(2日+)` |
| 标记 | ⏱️ | 🌊 |
| 收哪些信号 | 交易日跨度 ≤ 1 | 交易日跨度 ≥ 2 |
| 回看窗口 | 前 1 个交易日 | 前 5 个交易日 |
| 什么时候推 | 交易日 20 档 · 非交易日 5 档 | 同左 |

**分档按交易日跨度**（03§3.4），与 04§3.4 同一口径 —— 不是卡片上的周期词。

**算不出跨度的信号两张卡都上不了**：`long` 没有验证终点，跨度是 `None`；终点超出日历覆盖的，同样算不出跨度。两种来源见 03§3.4。

**上不了卡的信号照进报告** —— 推送是报告（03）在时间轴上的一个切片，不是另一套统计；卡上没有它，报告里照样有。

## 06§3 回看窗口

**按交易日算，起点是那一天的 00:00。**

| 板块 | 取前几个交易日 | 起点 |
|:---|:---:|:---|
| 超短 | 1 | 上一个交易日的 00:00 |
| 波段 | 5 | 往前数第 5 个交易日的 00:00 |

举例：今天 2026-09-09 周三，波段窗口的起点是 2026-09-02 周三 00:00。

**超短那个 1 是够的** —— 跨度 ≤1 的信号发帖日到终点最多隔 1 个交易日，窗口取 1 天正好把它兜住：周五盘后说的「下周一」（跨度 1），到周一盘中也仍在窗口内、终点未到。

**推送当天不是交易日** → 先退到它之前最近的那个交易日，再往前数。举例：2026-09-05 周六那一档，「前 1 个交易日」的起点是 09-03 周四 00:00。

**交易日历**：官方日历，含未来（01§10.3）。窗口起点每一档现算，不存进状态 —— 存了就会随时间失真。

## 06§4 初始化

**这是一个显式动作，只跑一次。**

带 `--init` 时：把博主池里每一位从回看窗口起点抓到今天，逐帖判一遍，攒出初始分布（窗口内符合标准的那几条）落进状态文件。

不带 `--init` 时：

| 状态文件 | 结果 |
|:---|:---|
| 在 | 正常推一档（§5） |
| 不在 | 报错退出 —— 窗口没建过，没有分布可推，也不替你猜 |

几条：

- 起点是窗口起点，不是 `begin_date` —— 推送只关心窗口内那几天
- 抓回来的帖照常并进 `data/posts/`，永不覆盖（01§4）
- 判过的帖走判断缓存（03§2.2） —— 与报告链共用同一份，两边同一套读法、同一批参数
- 状态里只记初始化标记与分布本身（每位若干条，窗口内还活着的那几条），不记「上次推送时刻」 —— 窗口起点每档现算（§3），不依赖上次跑没跑过。停机几天再恢复，不需要对账
- 判断缓存整批作废时要重跑一次 `--init`（03§2.2：读帖规则文本或模型名一改，旧判断不再作数） —— 重判会得出新的信号，而分布是增量攒出来的，不重头攒一遍就会留着旧规则下的结论

> **连带后果**：初始化之后，池子里这几十位在 `data/posts/` 里只有窗口内那几天。
>
> 推送的池子与报告链的名单各自独立、互不干涉 —— 不约定谁先跑。报告链要用这批人当样本，得删净重引（03§7）：库里已经有他们，`report` 只会走「旧博主更新」，起点是续抓起点（01§5），永远补不回历史。

## 06§5 每一档推送

### 5.1 不在档上就直接退出

现刻（北京时间）对照本板块的时刻表（§9）。不在档上 → 打印一行说明是哪个规则挡下的，退出。

这一步在拿锁、抓帖、发消息之前 —— 不在档上时它什么都不碰。

**`--force` 是这条规矩唯一的例外**（§8）：带上它就跳过早退检查，把此刻当成一档推出去。漏了一档又不想等下一档时用；落档与卡面写的都是实际执行的时刻（§6.2）。

| 日子 | 时刻表 | 档数 |
|:---|:---|:---:|
| 交易日 | 09:00～15:00 每 30 分钟；16:00～22:00 每整点 | 20 |
| 非交易日 | 09:00、12:00、15:00、18:00、21:00 | 5 |

**两个板块都是这两张表** —— 非交易日也推超短。

**日子按交易日历分**（01§10.3），不按星期几。

### 5.2 拿进程锁

上一档还没跑完 → 直接退出，不做任何事。免得两档同时抓帖。

### 5.3 备料行情

调 01§10 的行情命令，补到此刻并核对。已经补到就跳过，不重复抓。

卡上不显示行情，但要行情有两个硬用途：

| 用途 | 为什么 |
|:---|:---|
| **行情注记** | 解析新帖的前提 —— 注记取不到的帖压根不解析（02§2.2）。注记取的是发帖时刻的现值，从 30 分钟线来（02§2.1） |
| **交易日历** | 判今天是不是交易日、本档用哪张时刻表、窗口起点从哪天起（01§10.3） |

核对基准就一句话：把本档时刻当成一个「发帖时刻」，看注记取不取得到（02§2.1） —— 取不到就补一次行情，补完还取不到 → 硬失败、本档不推。

换个说法：本档要的那根 K 线，是「结束时刻不晚于本档时刻」的最后一根。
`10:30` 档要 `10:30` 那根；`12:00` / `12:30` / `13:00` 档要 `11:30` 那根；`09:30` 档当天一根都还没有，退到上一交易日末根；`15:00` 及之后的档要 `15:00` 那根。

> 要的是已经收出来的那根，不是「本档时刻所在那根」 —— 后者在 `09:30` 与 `13:00` 两档上根本还不存在（当天第一根要到 `10:00` 才收出来，下午要到 `13:30`），那两档每天都会白白硬失败。

> 不核这一下的话，盘前跑或当天行情还没补上时，核对会拿「上一交易日」当基准、判成齐了 —— 而这时候新帖的注记取的是昨天的收盘，卡只会静静地变陈。

### 5.4 抓增量帖

博主池里每一位从各自的续抓起点（01§5）往后抓到此刻，并入 `data/posts/`。

- 起点是该博主 `scrape_time` 所在那一日的零点，不是上一次推送的时刻 —— 与报告链走的是同一个水位、同一处算法
- **某一位抓失败只影响他自己**：他不中断本档，状态里那条旧条目照留；他的 `scrape_time` 没推进，下一档还会从原处接着抓

### 5.5 解析增量

**只判这一轮新抓回来的帖**。判过的帖走判断缓存（03§2.2），不重判。

批的大小、字数预算、单帖上限、排序方向，照 03§2.2 同一套参数 —— 推送与报告读帖的方式必须一致。

### 5.6 更新分布

对池里每一位，按先筛后取三步走：

| 步 | 动作 |
|:---:|:---|
| 1 | 淘汰（§5.7）：状态里滑出窗口的、终点已过的，逐条丢掉 |
| 2 | 并入：这一轮新产出的信号里，`idx` 是 `上证指数`、交易日跨度落在本板块（§2）的，逐条并进状态 |
| 3 | 取值：这位博主取状态里窗口内 `pub` 最大的那条 —— 就是他本档的立场 |

**「最新」怎么比**（要确定、可复现）：

| 顺序 | 比什么 |
|:---:|:---|
| 1 | `pub` 大的赢 |
| 2 | `pub` 并列 → 验证终点更晚的赢（同一帖出了两条同板块信号，如「今天涨，明天也涨」） |
| 3 | 仍并列 → 信号文件里先出现的赢 |

**为什么状态里要留好几条**：最新那条过期时要能退回次新那条。他最新的短周期判断刚过期时，更早的长周期观点往往还活着 —— 如「`t2`」的终点已收盘，而「`month`」的还在有效期。只存一条，就会把他整档丢掉，明明他还有一个活着的老观点。

> **「先筛后取最新」不是「先取最新再淘汰」** —— 后者正是上面那个丢人的做法。回测走的是同一套规则（05§3），**两边结果必须一致**。

**这一轮没有新帖 → 第 1、3 步照走**（该淘汰的照样淘汰、取值照样取），只是第 2 步无新可并。

> **第一条淘汰不必回头重扫窗口**：最新那条滑出窗口了，比它早的必然也滑出去了。
>
> **第二条淘汰没有这个性质** —— 最新那条终点已过时，更早的长周期观点可能还没过期。所以状态里必须留着窗口内那几条（§5.6）。

### 5.7 淘汰

每次推送前，把状态里这两类条目丢掉：

| 丢哪类 | 判据 |
|:---|:---|
| **滑出窗口** | `pub` 早于本档现算的窗口起点 |
| **终点已过** | 验证终点已经收盘（含正好收盘那一刻） |

第一条让「回看窗口」真的在滚动；第二条让卡上只留还没到验证时间的观点。

**终点算不出的**（超出日历覆盖，见 §2）不按第二条淘汰 —— 只等第一条把它带出去。日历含未来一年，所以这只在「终点超过日历末日」时发生。

被丢掉的条目，本档就不上卡。一位博主所有条目都过期了，他本档才不显示、不计数；他下次发了新帖再回来。

### 5.8 计数

```
看多 = 分布里 d = +1 的条数
看空 = 分布里 d = −1 的条数
```

没表态的博主不计入。计数只在上了卡的条目上算 —— 淘汰掉的不算。

### 5.9 渲染卡片

见 §6。

### 5.10 推送、落档、推进状态

- 卡片发到本板块自己的群。失败重试 3 次（超时 20 秒，间隔 3 秒起递增）
- 重试仍失败 → 往同一个群发一条纯文本的失败提醒（不检查这条提醒自己是否成功）
- **不补发**：本档就丢了，下一档带的是最新的分布
- 落档 `data/briefings/<日期>_<时刻>_<板块>.json`；同一档重跑就覆盖同一份
- **最后才推进状态文件** —— 抓帖的水位不归它（那是抓取自己写的 `scrape_time`，01§7）

## 06§6 卡片

### 6.1 一张波段卡

```
📊 波段 14:00 · 09-09 周三
🕐 覆盖：波段板块 前5个交易日到现在（09-02 起）

🌊 **波段(2日+)** · 2多/2空
🔴 **故乡的云ZYH** 看多 · 终点 09-18 收盘
　重点原话：“下周A股大概率打破震荡格局，迎来结构性行情修复”（09-05 10:58）
🟢 **知行合一** 看空 · 终点 09-11 收盘
　重点原话：“宣告下周的破位大跌已经箭在弦上”（09-04 17:46）
🔴 **子房论市** 看多 · 终点 09-11 收盘
　重点原话：“沪指3900点是多空分水岭，守住还能反弹”（09-08 22:07）
🟢 **我觉醒了** 看空 · 终点 09-11 收盘
　重点原话：“向上去突破4000点是痴人说梦，向下各方面的条件都成熟”（09-08 17:47）

🧭 波段板块2多2空，多空对短期节奏与空间的判断对立。…
```

### 6.2 逐行从哪来

**第 1 行 · 标题**

| 内容 | 从哪来 |
|:---|:---|
| 📊 | 固定 |
| `波段` | 板块名（超短板块这里就是「超短」） |
| `14:00` | 这一次推送实际执行的时刻（不是应该执行的时刻） |
| `09-09 周三` | 当期日期与星期 |

**第 2 行 · 覆盖范围**

```
🕐 覆盖：波段板块 前5个交易日到现在（09-02 起）
```

`前5个交易日` 与 `09-02` 都从回看窗口现算（§3）。超短板写「前1个交易日」。

**第 3 行 · 板块头**

```
🌊 **波段(2日+)** · 2多/2空
```

`2多/2空` 是本档的计数（§5.8）。不写分母 —— 卡上不给「多少人没表态」这个数。

**每位博主两行**

第 1 行 —— 谁、什么态度、什么时候见分晓：

```
🔴 **故乡的云ZYH** 看多 · 终点 09-18 收盘
```

- 🔴 = 看多（`d = +1`），🟢 = 看空（`d = −1`） —— 红涨绿跌，A 股习惯
- 加粗的是博主名，顺序就是池子里的顺序
- 后面跟验证终点：`终点 MM-DD 收盘`。日历含未来一年（01§10.3），所以「明天」「下周」这类终点都算得出 —— 只有终点超过日历末日时才退回写档位（`spec` 的字段值，如 `week`）

第 2 行 —— 原话：

```
　重点原话：“下周A股大概率打破震荡格局，迎来结构性行情修复”（09-05 10:58）
```

- 括号里是这句话所属帖子的发布时间（精确到分钟），不是这张卡的发布时间
- 引文逐字来自帖子的标题或正文（02§9），截断长度照 `report.quote_limit`（03§8）
- **这一行是整张卡里唯一能自己回去核对的证据**

**底部 · 总结**

```
🧭 波段板块2多2空，多空对短期节奏与空间的判断对立。…
```

**再调一次模型**写的，喂给它的是本档已经算好的分布与计数。写失败 → 兜底成一行计数（`多空版图：2多2空`），不整张卡报废。

### 6.3 零表态时的最小卡

本板块一个人都没上卡时：

```
📊 超短 14:00 · 09-09 周三
🕐 覆盖：超短板块 前1个交易日到现在（09-08 起）

⏱️ **超短(0-1日)** · 0多/0空
（前1个交易日内无人给出本档的上证方向观点）
```

**不渲染名单、不渲染总结** —— 没有人可讲，就不占地方。末句按窗口天数现算，不写死。

## 06§7 出错

**总原则：宁可少显示，不可显示错的。**

| 情形 | 怎么办 |
|:---|:---|
| **不在档上** | 直接退出，不碰任何状态（§5.1） |
| **上一档还在跑** | 直接退出，不做任何事（§5.2） |
| **某位博主抓帖失败** | 只影响他自己，本档照出；状态里那条旧条目照留（§5.4） |
| **某位博主解析失败** | 同上 —— 他那一条不动，其余照常 |
| **总结段写失败** | 兜底成一行计数，卡片照发（§6.2） |
| **发卡失败** | 重试 3 次；仍失败往同一个群发一条纯文本提醒（§5.10） |
| **某板块没配推送地址** | 该板块失败 —— 不转投另一个群，也不发提醒（提醒也得有地址才能发） |
| **状态文件不在、又没带 `--init`** | 报错退出（§4） |

## 06§8 怎么跑

```bash
# 初始化一个板块 —— 只跑一次（§4）
python -m push swing --init
python -m push short --init

# 推一档
python -m push swing
python -m push short

# 补一档：不在时刻表上，也当一档推出去（§5.1）
python -m push swing --force

# 只看不发：打印卡片，不碰飞书、不写状态、不留档
python -m push swing --dry-run
```

- 一道命令只推一个板块
- **叫醒它的调度器是 Windows 任务计划**：按 §5.1 的两张时刻表各注册一批任务，每次带上板块名。注册脚本归部署层，不在本文
- **被叫醒但那一下不在档上，命令自己退出**（§5.1） —— 时刻表在两边各有一份，判据以命令里这份为准
- `--force` 只跳过早退检查，其余一步不省：行情照核、增量照抓、窗口照算，该硬失败的还是硬失败（§5.3）
- `--dry-run` 供手动核对卡面用；正式调度一律不带。它不写任何东西 —— 状态与留档都不落，下一次真推照常
- `--force` 与 `--dry-run` 可以同时带 —— 补一档的内容只看不发
