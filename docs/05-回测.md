# 05 · 回测

**管什么**：把指定博主池在回看窗口内的观点，按推送那张时刻表逐档判成一个仓位，算出一条净值。
**不管什么**：怎么抓帖（见 01）／一条帖怎么读出观点信号（见 02）／单博主报告（见 03）／全博主对比（见 04）／推送（见 06）。

---

## 05§0 边界

回测自己不抓帖、不解析。输入是 `data/signals/<博主名>.json`（6 键）与 `data/market/`。

**跑之前先把全库刷新到同一时点**。这一步回测自己调 04 的全库更新（04§2），不用手动先跑别的命令（§8）。

**这一步可以关掉**（`backtest.update`，§9.1） —— 关掉只省抓帖解析那一段，行情照刷。

| 项 | 值 |
|:---|:---|
| 命令 | `python -m backtest` |
| 产物 | `backtest/runs/<日期>_<时刻>/` 一个夹子：`回测.md` · `净值.png` · `参数.json` |

**代码包与 `blogger/` 同级** —— 回测是独立的一条线，不塞进 `blogger/` 里。产物落在包内的 `runs/` 下，与代码分开一层。

只考察上证指数，只取波段。`idx` 必须是 `上证指数`；交易日跨度必须 ≥ 2（03§3.4）。超短期不进回测。与 06§0、06§2 同一口径。

回测不看得分。03／04 要的是「这位博主准不准」（终点价、收益率、得分），回测要的是「他此刻站在哪边」 —— 只用 `d`。回测从 03§3 借三样：验证终点、交易日跨度、状态机的判据与次序（§3）。

池子是参数，不是机制。换一批博主 = 改一次 `backtest.pool` 再跑一遍，落成另一份档。不同的回测互相独立，谁也不覆盖谁 —— 每份档的 `参数.json` 完整记着它是怎么跑出来的。

## 05§1 一图流

```
① 全库更新 ── 调 04 那一步（04§2）：库里每一位刷到同一时点
   │            └─ 关了（backtest.update = false）──► 只刷行情，不动库
   ▼
交易日 20 档，逐档推进
   │
   ▼
② 取窗口 ── 前 N 个交易日到现在（§2）
   │
   ▼
③ 攒分布 ── 池里每一位取「窗口内最新的一条」（§3）
   │            └─ 取不到的 ──► 不进 e
   ▼
④ 计数 ── e = 有观点的人数｜ρ = 多方 / e
   │
   ▼
⑤ 状态机 ── 平仓门 → 开仓门 → 目标仓位（§4）
   │
   ▼
⑥ 成交 ── 按本档现值，两个标的各管一边（§5）
   │
   ▼
⑦ 盯市 ── 记一次净值 → 下一档
```

**每一档都从头重算窗口与分布** —— 不增量、不缓存。

## 05§2 与推送同源的四样

回测与推送是同一套逻辑，差别只在「推送往外发卡，回测往内记净值」。四处口径直接引用，本文不写第二套：

| 哪一样 | 归谁 | 本文用在哪 |
|:---|:---|:---|
| **推送档** | `push.grid.trading`（06§5.1） | §4 判定与成交 |
| **回看窗口** | `push.window.swing`（06§3） | §3 取哪一段的帖 |
| **观点取舍** | 06§5.6 先筛后取最新、06§5.7 三条淘汰 | §3 |
| **验证终点** | 03§3.2（由 `spec` 定，不顺延） | §3 淘汰「终点没开市」「终点已过」 |

**窗口与推送共用同一个键** —— 一个窗口喂两处，不会分叉。

**规则同一套，机制两条路，结果必须一致。**

| 哪条路 | 怎么拿到分布 |
|:---|:---|
| **推送**（06） | 实时增量 —— 状态里带着「窗口内那几条」，每档淘汰过期的、并入新的、取最新（06§5.6） |
| **回测**（本文） | 事后重算 —— 每档从信号文件从头筛一遍（§3） |

两者结果不同就是有 bug。

## 05§3 攒分布

每一档各攒一次 —— 对池里每一位，按先筛后取最新三步走（与 06§5.6 同一套规则）：

| 步 | 动作 |
|:---:|:---|
| 1 | 筛：留下 `idx` = `上证指数`、交易日跨度 ≥ 2（03§3.4）、且过了下面三条淘汰的 |
| 2 | 取最新：留下的里面 `pub` 最大的那条 |
| 3 | 计数：那一条进分布 |

**三条淘汰**（06§5.7，判据与次序照 03§3.6 的状态机）：

| 丢哪类 | 判据 |
|:---|:---|
| **滑出窗口** | `pub` 早于本档现算的窗口起点 |
| **终点没开市** | 验证终点落不到交易日 —— 这条表述不成立（03§3.6 ②） |
| **终点已过** | 本档时刻不早于验证终点的收盘时间（含正好收盘那一刻） —— 03§3.6 ③ 的实时版 |

**算不出跨度的压根进不来** —— 这三条只判跨度落得进本板块的信号（06§5.7 同一条）。

**「最新」三级判据**（06§5.6）：`pub` 大 → 验证终点更晚 → 信号文件里先出现。

**先筛后取，不是先取后筛** —— 他最新那条过期时，会退回次新那条，而不是把他整档丢掉（06§5.6 记了这件事的来历）。

一位都没留下 → 这位博主本档不进 `e`。没表态是正常状态，不是缺数据。

```
e  = 分布里的条数 = 看多 + 看空
ρ  = 多方 / e        多方 = d = +1 的条数
```

（`d` 只有 `+1` 与 `−1` 两个取值 —— 与 06§5.8 的计数口径一致。）

`e = 0` → ρ 无定义，本档不动作，持仓照留。

**前视**：本档只看 `pub` ≤ 本档时刻的帖。窗口按时间算、不按档算 —— 档走得越密，同一批帖会被反复看到，这是对的。

## 05§4 状态机

判定与成交只发生在交易日的 20 档。非交易日那 5 档不成交 —— 状态机只看「当前持仓 + 本档 ρ」，不看别的；非交易日那几档不产生任何可积累的东西。那期间发的帖，由下一交易日各档的窗口自然带上（窗口按时间算）。

**输入**：现持仓 `pos ∈ {+1, 0, −1}`、本档 `e` 与 `ρ`。

**第一步 · 平仓门**（`pos ≠ 0` 才走）

| 持 | 条件 | 动作 |
|:---|:---|:---|
| 多 | `ρ < TX_LONG` 且 `e > Q_exit` | 平多 → 0 |
| 空 | `ρ > TX_SHORT` 且 `e > Q_exit` | 平空 → 0 |

其余不平。

**第二步 · 开仓门**（`pos = 0`，或第一步刚平完）

| 条件 | 动作 |
|:---|:---|
| `ρ > TO_LONG` 且 `e > Q_open` | 开多 → +1 |
| `ρ < TO_SHORT` 且 `e > Q_open` | 开空 → −1 |

其余不开。

**所有比较都是严格不等** —— ρ 恰等于阈值不触发，维持原持仓。四个阈值在配置里存成分数（`[分子, 分母]`），代码按整数比：`ρ > 2/3` 就是 `3 × 多方 > 2 × e`，恰好 2/3 时不触发。

**同档换向**：第一步平出后，第二步同一档再判 —— 两门都过且方向相反，就在同一个档完成 +1 ↔ −1，中间不隔空仓。只过平仓门 → 平到持币；只过开仓门 → 从持币开出。

**换向在账上算两次改仓**：平掉旧的那一笔、开出新的那一笔 —— 逐笔表上是两行（§6），换手率计 2，中间不隔空仓。

## 05§5 成交与净值

### 5.1 成交价

**那一档时刻本档标的（§5.2）的现值** —— 调 02§2.1 的取价函数，与 03§3.1 的参考价同源。

| 档时刻 | 取到哪根 |
|:---|:---|
| 09:00（盘前） | 上一交易日收盘 |
| 09:30 ~ 11:00 | 当根 30 分钟 K 线的开盘 |
| 11:30 · 12:00 · 12:30（午休） | 11:30 收盘 |
| 13:00 ~ 14:30 | 当根 30 分钟 K 线的开盘 |
| 15:00 ~ 22:00（盘后） | 15:00 收盘 |

不计成本。手续费与滑点整个不进来 —— 净值、逐笔收益、各项指标全是毛数。逐笔表里那列「收益」就是标的在持仓区间按方向算的变化率。

### 5.2 两个标的

| 标的 | 现值 |
|:---|:---|
| 多头标的 `backtest.long_symbol` | 中证1000 |
| 空头标的 `backtest.short_symbol` | 中证1000 |

`pos = +1` 持多头标的，`pos = −1` 持空头标的。

**多空不可能同时存在**，所以整体净值是两段的纯分解：

```
整体净值 = 多头段净值 × 空头段净值
```

**逐档盯市** —— 每档按当档现值记一次净值。

### 5.3 区间

`backtest.begin` ~ `backtest.end`。两端都是参数。

| 键 | 空着时取什么 |
|:---|:---|
| `backtest.begin` | 信号能覆盖到的最早那天 |
| `backtest.end` | 行情末日 |

区间末尾还持着仓 → 按末档现值强行平掉，记成完整一笔。

**年化用的「交易日数」**：`[begin, end]` 闭区间内的交易日个数，按官方日历数（01§10.3）。两端落在非交易日就自然不计。

## 05§6 报告

**每次跑落一个夹子** `backtest/runs/<日期>_<时刻>/`：

| 文件 | 内容 |
|:---|:---|
| `回测.md` | 报告正文 |
| `净值.png` | 净值图 |
| `参数.json` | 本次跑的全部参数快照 |

**`参数.json` 是这份档的一部分**：§9 两节列的那些键一个不少 —— 池子名单、`update` 开关、窗口、档表、四个阈值、两个法定人数、两个标的、区间、两档边界。两份档要能只靠自己的 `参数.json` 说清「我是怎么跑出来的」。

**报告正文的顺序**：

| 顺序 | 一节 |
|:---|:---|
| ① | 头部 —— 数据截止（= 区间末端，`backtest.end` 配了就是它、空着就是行情末日）、回测区间、池子几位、实际有数据的是谁 |
| ② | 本次参数 —— 与 `参数.json` 同一份内容，表格化 |
| ③ | 净值图 |
| ④ | 指标表 —— 整体／多头段／空头段，三列并排 |
| ⑤ | 逐笔 —— 一笔一行 |

**净值图**：横轴按档 —— 交易日一天 20 个点，非交易日那 5 档不画。

| 线 | 是什么 |
|:---|:---|
| 整体 | 多头段 × 空头段 |
| 多头段 | 只在 `pos = +1` 期间变动，其余时间持平的净值 |
| 空头段 | 只在 `pos = −1` 期间变动 |
| 多头标的买持 | 多头标的从区间首到末的买持 |
| 空头标的的反向买持 | 空头标的买持取负 —— 做空的对照 |

**逐笔表的列**：

| # | 开仓档 | 开仓价 | 平仓档 | 平仓价 | 方向 | 标的 | 收益 | 持仓档数 |
|:---:|:---|:---|:---|:---|:---:|:---|:---|:---|

**一笔 = 一段连续同向持仓**（+1 段或 −1 段），从开仓档到平仓档。

- **收益** = 标的在 `[开仓价, 平仓价]` 上按方向算的变化率 —— 持多就是 `平/开 − 1`，持空就是它的相反数。不计成本（§5.1）
- **换向档出两行**：旧的一笔在本档收尾（平仓档 = 换向档），新的一笔在本档开张（§4）
- **区间末尾那一笔**按末档平掉，照常入表（§5.3）

## 05§7 指标定义

**整体／多头段／空头段各算一套。**

| 指标 | 怎么算 |
|:---|:---|
| **累计收益** | 末值 / 初值 − 1 |
| **年化收益** | `(末值 / 初值) ^ (242 / 交易日数) − 1` |
| **波动率** | 日收益的标准差 × √242 |
| **夏普** | 年化收益 ÷ 波动率（无风险利率取 0） |
| **最大回撤** | 日净值上的最大峰谷跌幅 |
| **卡玛比** | 年化收益 ÷ 最大回撤 |
| **笔数** | 逐笔表的行数 |
| **胜率** | 赚钱的笔数 ÷ 总笔数 |
| **改仓次数** | 逐笔表的行数 —— 换向那一档出两行，就计 2 |
| **换手率** | 改仓次数 ÷ 回测年数 —— 「年均改仓多少次」 |

**两段的指标只看自己那一段的账**：多头段的笔与改仓只数持多的，空头段只数持空的。

**整体那一列把两向合起来算** —— 胜率 = 两向所有笔里赚钱的占比；换手率 = 两向改仓次数合计 ÷ 年数。

- **跟净值有关的那几项一律按「日序列」算**：每天取收盘档（15:00）那一档的净值 —— 累计与年化取它的首末两点，波动率、夏普、最大回撤都在它上面算。**不按档**（一天 20 个点）：按档年化会大 √20 倍，没法跟外部策略比
- **日序列的第一个点不是 1.0** —— 那是第一个交易日 15:00 的净值。净值图上那个 1.0 是当天 09:00 的第一档（§6），两者不是一条线
- **一年按 242 个交易日**；「交易日数」按 §5.3 数
- **不做 VaR**

## 05§8 怎么跑

```bash
python -m backtest
```

就这一条。回测自己先调 04 的全库更新（04§2），把库里每一位刷新到同一时点，再开始逐档推进 —— 不必手动先跑别的命令。

**这一步可以关掉**：`backtest.update` 设成 `false`（§9.1），回测就跳过抓帖解析那一段，直接拿 `data/signals/` 里现成的开跑 —— 行情照刷，那是 §5 算价的前提。

**回测自己不抓帖、不解析、不写单博主报告** —— 那些都是它调的那一步在做。那一步的说明见 04§2，本文不写第二套。

**除这一个开关，回测不开别的口子**：调 04 那一步时三个值都写死 —— 新博主的抓取起点走 `scrape.begin_date`（01§12）、一条帖跑几遍走 `parse.runs`（02§12）、先刷行情。要改这些就改配置，不在回测命令上开口子。

库里没有的博主，全库更新也不会替你引进（引进新博主只有一条路，见 03§0）。
