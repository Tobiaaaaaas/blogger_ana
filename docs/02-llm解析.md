# 02 · llm解析

**管什么**：解析**一条帖** —— 从这条帖里捕捉**观点信号**。
**不管什么**：一次解析几条、哪些帖进来、判几次、结果怎么存 —— 都是调用方的事。

---

## 02§0 这一步做什么

**输入**：**一条帖** —— 连它的编号、发帖时间（含周几）、标题正文、行情注记（见 §2）。
**输出**：**零到多条结构化数据**。产不出就是**零条**，没有什么「声明」这回事。

**本文只描述「解析一条帖」这一个动作。** 下列都不归本文：

| 不归本文 | 归哪 |
|:---|:---|
| 哪批帖送进来、一次送几条、按什么顺序 | **03**（报告，全量）／**06**（推送，增量） |
| 怎么保证每条帖都被读过、一条都不漏 | 同上 —— **本文不产出任何「我读过这条帖」的标记** |
| 要不要缓存、缓存在哪 | 同上 |
| 结果存到哪、怎么存、什么时候作废 | 同上 |
| 判出来的观点信号说对了没有、算不算分 | **03** |
| 怎么摆到卡片上 | **06** |

> **两条链用的是同一套读法。** 报告全量读、推送增量读，**一条帖怎么读、读出来长什么样，一字不差**。

---

## 02§1 观点信号 ＝ 三元组

**观点信号** ＝ 博主给出的**明确方向**、说的是**哪一段时间**、落在**哪只宽基指数**。

**三个分量在同一层。** 序号只是**下笔的先后** —— 先写 `d`、再写 `spec`、最后写 `idx`。**判读时三个互相参照、常常要同时看**，不是筛完一道再进下一道：

| 下笔先后 | 分量 | 问什么 | 必须有吗 |
|:---|:---|:---|:---|
| **①** | **方向** `d` | 是不是一个**明确的、无条件的**方向观点 | **必有** |
| **②** | **周期** `spec` | 说的是**未来**吗 —— 还是复盘、还是已经过期 | **可缺**（缺了落第 5 个交易日） |
| **③** | **对象** `idx` | 说的是哪只宽基指数，归到哪一类 | **必有** |

**为什么要互参**

| 互参在哪 | |
|:---|:---|
| 判 `d` 要依赖 `idx` | 「目标 4260」是看多还是看空 —— 得先知道那是哪只指数、它现在多少点 |
| 判 `idx` 要对着上证现值比合理范围 | 未点名指数时，点位对上证现值——明显不在上证短期合理范围 → 不产；**不靠点位反查归到别的指数** |
| 判 `spec` 要看整句在预测什么 | 「本周」指向哪一段行情（是否已走完），取决于整句说的是哪只指数的哪件事 |
| 判 `spec` 反过来框住 `d` 与 `idx` | 同一对象同周期同方向的重复表述只算一条 —— 得先知道周期 |

**先定位核心预测句。** 一条帖有多个语句构成，要分开判断——逐条提取前，先按博主的帖子结构特征快速定位**核心预测句**（一帖可能有 **0 个或多个**）；只有核心预测句才看三元组，其余语句（背景、铺垫、闲聊）不产出。

**这条帖能不能读出观点信号、能读出几条 —— 就是看它包不包含这个三元组，包含了几个。**

```
一条帖（含发帖时间、周几、行情注记）
   │
   ▼
┌──────────────────────────────────────────────┐
│  找观点信号                                    │
│  三个分量在同一层，互相参照着一起定下来          │
│                                              │
│     ① 方向 d  ◄────────────►  ② 周期 spec    │
│          ▲                          ▲        │
│          └──────► ③ 对象 idx ◄──────┘        │
└──────────────────────────────────────────────┘
   │
   ├──► 定得下来 ──► 产出结构化数据（一条或几条）─┐
   │                                            │
   └──► 定不下来 ──► 零条 ──────────────────────┤
                                                ▼
                                      输出前自查 + 强校验（§10）
```

## 02§2 输入：一条帖长什么样

模型只依据**帖子的原文**，加上**系统备好的外部事实**。外部事实模型**只读不写**。

```
[3] 发帖 2026-09-01 周一 10:00｜缩量横盘别慌，九月行情可期！
<正文…>
[行情@发帖 2026-09-01 10:00] 10:00盘中(30分钟线当根开盘)：上证指数≈… 创业板指≈… 沪深300≈… 上证50≈… 中证500≈… 中证1000≈… 科创50≈…
```

| 带上什么 | 为什么非它不可 |
|:---|:---|
| **编号** `[N]` | 模型指认是哪条帖 |
| **发帖时间 + 周几** | 判定「本周／今天」这类周期词的语义（§4.2 的 spec 拦截）离不开发帖时间与周几，不能让模型从日期自己推 |
| **标题 + 正文** | 判断的唯一文本依据；引文从这里逐字取。**标题与正文并列呈现、同等重要**——标题常直接给出预测结论；**疑问句/引流话术式标题不代表预测**，去正文找结论 |
| **行情注记** | ① 未点名指数时，对照上证现值判「合理范围」（§5.4）② 「目标点位高于现值 → 看多」（§3.1）③ 「低开／高开」这类相对说法 |

### 2.1 行情注记的口径

| 项 | |
|:---|:---|
| 喂哪几个指数 | **七个主指数** —— 上证指数／创业板指／沪深300／上证50／中证500／中证1000／科创50。**双创不单列**，它是创业板指与科创50 的组合 |
| 取哪一刻 | **发帖时刻** |
| 快照性质 | **盘中** → 所处 30 分钟 K 线的开盘价；**午休** → 11:30 收盘；**盘后** → 当日 15:00 收盘；**盘前或休市** → 上一交易日收盘 |
| 注记头 | 标明这一份是哪一种（`盘中(30分钟线当根开盘)` 等），模型据此知道这个数字的分量 |

### 2.2 注记必须在场 —— 这是硬前提

> **解析任何一条帖之前，行情必须已经覆盖到这条帖的发帖时刻。取不到 → 这条帖不解析。**

调用方负责把行情备到这一步：报告链跑之前先补齐行情，推送链解析之前先刷一次行情。

**为什么不许「取不到就跳过注记接着解析」**：点位类判断会退回「模型凭旧记忆猜」，而旧记忆里的点位和发帖时的点位常常差几百点 —— 那正是这套注记当初要修掉的毛病。

### 2.3 与 03 的参考价同源

> 注记里的数字，**就是 03 事后打分时用的那个参考价** —— 同一个口径、同一个值。
>
> **两处口径一旦分叉，模型判对的会被算成判错。**

## 02§3 ① 方向 `d` —— 必有

### 3.1 什么算方向

**只有两个取值：`1` 看多 ／ `-1` 看空。** 认不认，就看这处表述能不能落成「涨」或「跌」这一对反义。

| 帖里怎么说的 | 算不算 | 落成 |
|:---|:---|:---|
| 涨／看多／偏多／大方向向上 | **算** | `1` |
| 跌／看空／偏空 | **算** | `-1` |
| **震荡上涨** ／ **震荡下跌** | **算** —— 形态词里就带着涨跌 | `1` ／ `-1` |
| 预期点位高于参考价 ／ 低于参考价 | **算**（参考价见 §2 的行情注记） | `1` ／ `-1` |
| 震荡／筑底／洗盘／蓄势／拉锯／考验支撑 | **不算** —— 只说形态，不承诺往哪走 | — |
| 先抑后扬／先跌后涨／冲高回落／探底回升 | **不算** —— 描述了路径，没说终点在哪 | — |

其余取值一律丢掉。

### 3.2 必须是无条件的

**方向不能挂在一个博主并未承诺会发生的前提上。**

> 「破了3900就减仓」「守住4000不破才能…」「3900是多空分水岭」「放量就站稳，否则转震荡」

**不产。** 博主明显倾向某一分支 ≠ 方向。

**自测**：这处表述能否不改意思地改写成「博主**无条件**预测 〔某指数〕在 〔某周期〕 〔涨／跌／到某点位〕」？不能 → 不产。

### 3.3 操作动词就是方向

**博主做出或建议一个操作动作，等于表了态**，即使没有单独一句「大盘要涨/要跌」：

| 动作 | 方向 |
|:---|:---|
| 减仓／清仓／轻仓／止盈／逢高抛／卖出 | 看空 |
| 加仓／重仓／补仓／逢低买／抄底 | 看多 |

- 有明确时间词 → 按该周期；**无时间词 → 落第 5 个交易日，正常计分**
- **条件式里内嵌的操作不算**（「破了3900就减仓」）—— 见 §3.2
- **过去时的操作报告不算**（「今天我把仓位加到了创业板」）—— 那是仓位状态自述，见 §6

### 3.4 方向词必须出自原帖

产出一条结构化数据之前，逐字核对 —— 要把某个方向词安到这个三元组上，**那个词必须在原帖的 `title` 或 `content` 里搜得到**。

> **搜不到 = 编造**，比「无方向硬凑」更严重：硬凑是判读过宽，编造是凭空造出博主没说的话。**严禁**替博主补一个他没说的方向词，**严禁**把本文的示例措辞搬进引文 —— 示例只示形状，不是可复制的原文。

## 02§4 ② 周期 `spec` —— 可缺

### 4.1 全表

**周期必须通过语义理解读出，不是关键词匹配。** 帖里出现「明天」二字，不代表这就是对明天的预测。

**博主说什么周期就落什么档——不扩展、不缩短、不随意假设。** 每档锁定一个精确验证终点，不从宽泛分类里挑。

- 「明天会怎样，先看4000反击」→ 条件/观察句，不是对明天的预测

| `spec` | 什么时候用 | 验证终点 |
|:---|:---|:---|
| `today` | 今天／今日／下午／午后／尾盘 | **发帖当天**收盘（必须交易日发布） |
| `t1` | 明天／明日／次日 | 发帖后第 **1** 个交易日 |
| `t2` | 后天 | 发帖后第 **2** 个交易日 |
| `tN` | 「N天后／N日内」中 N≤20 | 第 N 个交易日 |
| `t5` | 近期／短期／很快／马上／即将／不久／临近／**未来几天**；**没说周期** | 发帖后第 **5** 个交易日 |
| `monday`～`friday` | 周一～周五（指**本周**的那一天） | 发帖当周的那一天 |
| `week` | 本周／本周内 | **发帖日所在那一周**的最后交易日 |
| `nweek` | 下周／下周末 | **下一周**的最后交易日 |
| `nmonday`～`nfriday` | 下周一～下周五 | 下周的那一天 |
| `month` | 月底前／月末前 | 当月最后交易日 |
| `nmonth` | 下个月／下月 | 下月最后交易日 |
| `d:YYYY-MM-DD` | 具体日期（**引擎认，模型不写**） | 该日期，非交易日顺延 |
| `long` | 落不进上面任何一档的远期说法（见 §4.4） | 无 |

- 表里的「交易日」一律指 A 股交易日，不是自然日
- 「信号日」= 发帖自然日；「发帖后第 N 个交易日」一律从发帖日往后数——周五盘后说「明天」→ 验证周一（顺延由系统算，模型只落档）
- **验证终点落在非交易日 → 顺延到之后最近的一个交易日**（`today` 除外：必须交易日发布）
- 「1-2天」「3-5天」这类 **X-Y天取窗口最后一天** → `t2`／`t5`

### 4.2 这一档的作用：分清未来 / 复盘 / 过期

| 这处表述是 | 怎么办 |
|:---|:---|
| 对**未来**的承诺 | **捕捉** |
| 对已发生行情的**回顾**（复盘） | 不捕捉 |
| 说**现在**是什么样（状态描述：「已经进入调整期」「顶背离已经出现」） | 不捕捉 |

**「过期」不在这里判。** 本文只管**语义**上是不是对未来的承诺 —— 那是模型能判的。而「发帖时间已经晚于验证终点」是**纯按时间**的机械判断，与博主说了什么无关，归 **03**（见 03§3.6）。

**但有三个 spec 的过期在提取端就要拦**（发帖时间晚于终点收盘，这条表述只能是回顾）：

| 情形 | 怎么办 |
|:---|:---|
| pub 在交易日收盘后 且 spec=`today` | 视为回顾/复盘 → 不产 |
| pub 时间晚于当周最后一个交易日收盘 且 spec=`week` | 视为回顾/复盘 → 不产 |
| pub 时间晚于当月最后一个交易日收盘 且 spec=`month` | 视为回顾/复盘 → 不产 |

**同一条帖既有复盘又有未来预测 → 只捕捉未来预测那部分。**

### 4.3 帖里出现日期不等于预测

是对未来的窗口（「8月7日之前都是磨底」）还是对过去的回顾（「2月8日我还提醒了一次」）？只有预测语境才落档。

### 4.4 没给周期时怎么办

| 情形 | 落哪 |
|:---|:---|
| 有方向、**没给时间** | `t5`，**正常计分**（「减仓为主」「随时会涨」「肯定要涨但不知道什么时候」） |
| 有点位、**没给时间** | `t5`，**正常计分**（「目标是 4260 点」「还有 X 点空间」） |
| 有点位、给了时间 | 跟时间走（「今天下午能站上 4000」→ `today`；「明天站上 4100」→ `t1`；「下周到 4000」→ `nweek`） |

**只有这三种落 `long`**：**年度预测**（「下半年」「全年」「今年」「2026年」）／**中长期远期**（「中长期」「未来几个月」「三年」「长线」）／「N天后」且 **N > 20**。

## 02§5 ③ 对象 `idx` —— 必有

### 5.1 只能是这八个

> 上证指数 ／ 上证50 ／ 沪深300 ／ 中证500 ／ 中证1000 ／ 创业板指 ／ 科创50 ／ **双创**

- **别名归一**：上证综指／上证／综指 → 上证指数
- **「双创」是组合** = 创业板指与科创50 各占一半
- **深证成指、北证50、行业指数都不在其中** → 博主只谈这些，**捕捉不到观点信号**
- **核心预测句未点名指数/板块 → 按 §5.4 的映射规则定 `idx`**（给了点位按上证合理范围判、没给点位默认上证；不让 AI 判断指数归属，不靠点位反查归到别的指数）

### 5.2 映射表

| 帖里出现 | 预测对象 | 代码 |
|:---|:---|:---|
| 创业板／创业板指／创业板ETF | 创业板指 | 399006 |
| 科创／科创50／科创板／**半导体／芯片** | 科创50 | 000688 |
| 小盘／成长／中证1000 | 中证1000 | 000852 |
| 中证500 | 中证500 | 000905 |
| 上证50／50ETF／老登／大金融／银行／保险／券商／证券／白酒／酒 | 上证50 | 000016 |
| 沪深300 | 沪深300 | 000300 |
| 上证综指／上证／综指／大盘 | 上证指数 | 000001 |
| 双创 | 双创 | 399006/000688 |

**其余板块一律忽略**：有色／钢铁／医药／创新药／恒科／电池／航天／军工／房地产等。

### 5.3 对象跟着这一处表述走

**预测对象是这一处表述里博主给出方向/时段/点位的那个对象**，不跟着帖子主题、论据里提到的别的指数、或市场氛围漂移。

- 一条帖对上证和创业板各说一句 → 那是**两个三元组**，各成一条，不许揉成一条上证
- 同一指数、同一周期的**重复表述** → 只算一个三元组

### 5.4 未点名指数时的映射规则

**核心预测句未点名板块或指数时，`idx` 按下表定**（对着 §2 行情注记里上证指数的发帖时刻现值比）：

| 情形 | 怎么办 |
|:---|:---|
| 给了预测点位，点位属于**上证指数短期未来的合理范围** | `idx` = 上证指数 |
| 给了预测点位，点位**不属于**上证指数短期未来的合理范围（如点位差出发帖时刻上证现值几成以上、明显是另一个指数的量级） | **不视为信号，不产** |
| 没给点位 | `idx` = 上证指数（默认：对上证综指/大盘的判断） |

**不靠点位反查归到别的指数** —— 不让 AI 判断「这其实是哪只指数」。博主没点名对象、点位又对不上上证 → 这条预测作废，不猜。

> 判「合理范围」用的参照是**注记里的上证现值**，不是模型记忆里的旧点位。

### 5.5 上证的「背景句」不成三元组

只描述上证现状、或把上证当论据背景（「在趋势之上」「无顶背离」「创新高」「很安全」「强势」「安心持股」「整理蓄势」，或「等 XX 筑底后上证走强」里上证只是受益方），而主谓**不是**在预测上证未来涨跌的。

> **自测**：这句能不能不改意思地改写成「博主预测上证在〔某周期〕〔涨／跌／到某点位〕」？不能 → 不是上证。

## 02§6 凑不成观点信号的情形

按**缺哪个分量**归类。这些说的是「**这段话**不算数」，不是「**这帖**作废」；一条帖里可以同时有几处各缺各的。

| 缺哪个 | 哪些情形 | 例子 |
|:---|:---|:---|
| **① 缺方向**<br>（没有博主本人的明确方向） | **条件式** | 「破了3900就减仓」 |
| | **路径形态**（先A后B） | 「明天冲高回落」「下周先抑后扬」 |
| | **周期词不救形态** | 「这周高开低走」「今天冲高回落」「下周探底回升」——带周期词的形态句仍是形态句，无净方向承诺就不产 |
| | **模棱两可** | 「可能涨也可能跌」「边走边看吧」「即将变盘」 |
| | **仓位状态自述** | 「还剩4成」「满仓持股」「我把仓位加到了创业板」 |
| | **投资理念** | 「长期持有优质公司」——理念自述，不是方向 |
| | **转述他人** | 「机构认为底部在3700-3800」「券商觉得…」 |
| **② 缺周期**<br>（不是对未来的承诺） | **纯复盘** | 「昨天猜中了开头，却没猜中结尾」 |
| | **状态描述** | 「已经进入调整期」「顶背离已经出现」 |
| | **过期** | 见 §4.2 的三条 spec 拦截（其余过期机械判断归 03） |
| **③ 缺对象**<br>（落不到宽基指数） | **只谈行业板块** | 全帖只谈有色、房地产、军工 |
| | **未点名指数且点位不在上证合理范围** | 只说「市场」「行情」给了点位，但点位明显对不上上证短期合理范围 → 不产 |
| **三个都缺** | **无实质内容** | 只有话题标签（`#晒图笔记大赛#`）、平台活动、与股市无关的日常 |

**两条放宽（有这两样，就以那一样成三元组）**

| 放宽 | 例子 |
|:---|:---|
| 该周期另有**独立无条件的方向句**（须原帖逐字存在） | 帖内既有形态句「下周先抑后扬」，又有独立方向句「对于下周周线个人看涨」→ 产一条 `nweek`／看多，引文取方向句 |
| 该周期另有明确的**逢跌买入承诺** | 「回踩就是机会」「逢低加仓」→ 按操作动词算看多 |

**引文必须连同方向词一起截**，不许只截前半句形态。

> **「先抑后扬」在语料里是高频表述**，绝大多数是**看多路径**（形态半句 + 回踩买入半句）。不许因为它是形态就把这类真看多帖整条漏掉；也不许把「先抑后扬」自行解读成看多。

**整条帖立场含糊但夹带明确预测句 → 捕捉那句**（「后市难料，但明天我看涨」→ 捕捉「明天看涨」）。

**机构/券商的看法不是博主本人表态**；博主以自己口吻明确背书才认。

## 02§7 一条帖能出几条观点信号

| 情形 | 几条 |
|:---|:---|
| 同一对象 + 同一周期 + 同一方向，在帖里重复说了几遍 | **一条** |
| **不同周期** | **各一条**（「今天市场会大涨」＋「这周市场启动的判断不变」= 两条） |
| 同一周期但**不同对象** | **各一条** |
| 同一对象同一周期但**方向相反** | **各一条** |

- 各条的引文从**载各自时间词的原句**逐字截取
- **不得只取近端周期、把远端丢掉**，也不得把两个周期并成一条
- **不做乘法** —— 别拿「一句话 × 几个周期 × 几个指数」去组合。「上证明天涨，创业板这周看好」是**两条**，不是四条

## 02§8 输出：结构化数据长什么样

| 组 | 谁填 | 字段 |
|:---|:---|:---|
| **A 读帖判断** | 模型 | `d` · `spec` · `idx` · `quote` |
| **B 帖子身份** | 系统 | `post_id` · `pub` |

- **模型只写 A 组。** `post_id`／`pub` 由系统按帖子补上，模型一律不写 —— 避免模型誊写编号、时间出错
- 所以**一条结构化数据 = 6 个键**
- **计分与否不在这里判** —— 那是报告统计环节从 `spec` 与 `pub` 算出来的（见 03）
- **怎么攒成文件、`blogger` 写在哪，都不是本文的事** —— 本文只产出这一条一条的数据（见 03）

```json
{"post_id": "1874751803693056", "pub": "2026-01-04 15:16",
 "d": 1, "spec": "t1", "idx": "上证指数",
 "quote": "明天大盘大概率高开"}
```

**一条帖产出零条 → 就是一个空列表。** 没有「我读过这条帖」这种标记 —— **保证一条不漏是调用方的责任**（见 §0）。

## 02§9 `quote` 佐证原话

**这个三元组在帖子里的原话，用来佐证博主确实这么说过。**

| 规则 | |
|:---|:---|
| **必填** | 每条结构化数据都要有引文 |
| **逐字** | 不许改写、润色、编造 |
| **可以是不连续的两段拼起来** | 段与段之间在原文里可以不挨着；每一段都要能逐字搜到 |
| **必须能佐证这个三元组** | 载明方向；带时间承诺的，时间词要在里面 |
| **截取起点** | 从载有时间承诺那句的**句首附近**截起，别只截丢掉时间词的后半句 |
| 来源 | `title` 或 `content`，**两边都可以** |

> 引文是**证据**，不是容器 —— 两条可以引同一句原文。引文宽窄不影响出几条。

## 02§10 输出前：自查与强校验

### 10.1 强校验：不合格的丢掉

**在一条帖的产出上就地做**，不合格的直接丢：

| 检查 | 处置 |
|:---|:---|
| `d` 不是 `1`／`-1` | 丢掉 |
| `idx` 不在八个合法对象里 | 丢掉 |
| `spec` 不在档位表里，或语义荒谬（`t0`／`t99`／`d:2026-13-99`） | 丢掉 |
| `quote` 有任一段在**这条帖**的 `title`／`content` 里搜不到 | 丢掉 |
| 同帖内同对象同周期同方向重复 | 只留一条 |

### 10.2 同一帖跑多次，最后交模型定夺

**同一条帖跑 N 遍**，拿到 N 份产出。输出前的最后一步：**把 N 份产出连同原文交给模型，由它定夺最终取哪一份**（或取哪几份的并集）。

- **N 由调用方给**（见 03§2.2）。**N = 1 时没有分歧可定夺，这一步退化成单纯的自查**
- 定夺要拦这三样：

| 拦什么 | 怎么认 |
|:---|:---|
| **形态被读成方向** | 引文里的方向词在原帖里搜不到 → 一律丢掉 |
| **周期编码错** | 「本周」已走完却编了 `week` → 按 §4.2 该表述丢掉；「下周一」~「下周五」落错 `t1`／`nweek` → 改回 `nmonday`~`nfriday`，**方向与引文一字不动** |
| **条件式硬凑方向** | 方向是从「守住/跌破/分水岭」或路径形态里压出来的，而帖内没有独立无条件的方向句 → 丢掉 |

**能系统性修掉漏结论、周期误套，但不能保证每条语义都对** —— 方向冲突的帖仍会偶发分歧。

**跑几遍、怎么定夺，归本文** —— 它是「解析一条帖」这个动作的一部分。**批的大小、排序、缓存不归本文**（见 §0）。
