# 02 · llm解析

**管什么**：解析一条帖 —— 从这条帖里捕捉观点信号。
**不管什么**：一次解析几条、哪些帖进来、判几次、结果怎么存 —— 都是调用方的事。

---

## 02§0 这一步做什么

**本文写的就是「判断规则」** —— 判定「哪句话算一条观点信号」、以及「怎么给它定周期」的规则集（§1～§10）。它落成一份规则文本喂给模型（§11），也进判断缓存的指纹（03§2.2） —— 改规则就是改本文。

**输入**：一条帖 —— 连它的编号、发帖时间（含周几）、标题正文、行情注记（见 §2）。
**输出**：零到多条结构化数据。产不出就是零条。

本文只描述「解析一条帖」这一个动作。下列都不归本文：

| 不归本文 | 归哪 |
|:---|---|
| 哪批帖送进来、一次送几条、按什么顺序 | 03（报告，全量）／06（推送，增量）；回测经 04 那一步读（05§8） |
| 怎么保证每条帖都被读过、一条都不漏 | 03／06 —— 本文不产出任何「我读过这条帖」的标记 |
| 要不要缓存、缓存在哪 | 03／06 |
| 结果存到哪、怎么存、什么时候作废 | 03／06 |
| 判出来的观点信号说对了没有、算不算分 | 03 |
| 怎么摆到卡片上 | 06 |

两条链用的是同一套读法 —— 报告全量读、推送增量读（回测沿用报告那条），一条帖怎么读、读出来长什么样，一字不差。

### 0.1 一图流

```
一条帖（含发帖时间、周几、行情注记）
   │
   ▼
┌──────────────────────────────────────────────┐
│  找观点信号                                    │
│  三个分量在同一层，互相参照着一起定下来          │
│                                              │
│     ① 方向 d  ◄────────────►  ② 周期 spec    │

   │                                            │
   └──► 定不下来 ──► 零条 ──────────────────────┤
                                                ▼
                                      输出前自查 + 强校验（§10）
```

## 02§1 观点信号

**一条帖能读出几条观点信号，就看它包含几个三元组。**

### 1.1 核心预测句

一条帖由多个语句构成 —— 逐条提取前，先按博主的帖子结构特征定位**核心预测句**（一帖可能有 0 个或多个）；只有核心预测句才看三元组，其余语句（背景、铺垫、闲聊）不产出。

| 帖里同时有 | 挑哪一句 |
|:---|---|
| 复盘 ＋ 未来预测 | 只捕捉未来预测那部分 |
| 形态句 ＋ 该周期的独立无条件方向句 | 以方向句成条 —— 帖内既有形态句「下周先抑后扬」，又有独立方向句「对于下周周线个人看涨」→ 产一条 `nweek`／看多，引文取方向句 |
| 立场含糊 ＋ 夹带明确预测句 | 捕捉那句 —— 「后市难料，但明天我看涨」→ 捕捉「明天看涨」 |
| 疑问句／引流式标题 ＋ 正文里的结论 | 只捕捉正文那句 —— 「明天A股会怎么走？」「下周要变天？」问了不等于答了 |

> **不许因为「先抑后扬」是形态就把这类真看多帖整条漏掉；也不许把它自行解读成看多。**

### 1.2 三元组

**观点信号** ＝ 博主给出的明确方向、说的是哪一段时间、落在哪只指数。

三个分量在同一层。序号只是下笔的先后 —— 先写 `d`、再写 `spec`、最后写 `idx`。判读时三个互相参照、常常要同时看，不是筛完一道再进下一道：判 `d` 要拿 `idx` 的现值比点位，判 `idx` 要对着上证现值比合理范围，判 `spec` 要看整句在预测什么、又反过来框住 `d` 与 `idx`（同一对象同周期同方向的重复表述只算一条）。

| 下笔先后 | 分量 | 问什么 | 必须有吗 |
|:---|---|---|---|
| **①** | 方向 `d` | 是不是一个明确的、无条件的方向观点 | 必有 |
| **②** | 周期 `spec` | 说的是未来吗 —— 还是复盘、还是已经过期 | 可缺（缺了落第 5 个交易日） |
| **③** | 对象 `idx` | 预测的是哪个板块或指数，映射到哪一类（详见 §5.2） | 必有 |

## 02§2 输入

输入是一条帖的原文，加上系统备好的外部事实 —— 外部事实模型只读不写。

```
[3] 发帖 2026-09-01 10:00 周二｜缩量横盘别慌，九月行情可期！
<正文…>
[行情@发帖 2026-09-01 10:00] 盘中(30分钟线当根开盘)：上证指数≈… 创业板指≈… 沪深300≈… 上证50≈… 中证500≈… 中证1000≈… 科创50≈…
```

| 带上什么 | 用来判什么 |
|:---|---|
| **编号** `[N]` | 模型指认是哪条帖 |
| **发帖时间 + 周几** | 判定「本周／今天」这类周期词的语义（§4.2 的 spec 拦截）离不开发帖时间与周几，不能让模型从日期自己推 |
| **标题 + 正文** | 判断的唯一文本依据；引文从这里逐字取。标题与正文并列呈现、同等重要 —— 标题常直接给出预测结论；疑问句/引流话术式标题不代表预测，去正文找结论 |
| **行情注记** | ① 未点名指数时，对照上证现值判「合理范围」（§5.4）② 「目标点位高于现值 → 看多」（§3.1）③ 「低开／高开」这类相对说法 |

### 2.1 行情注记的口径

| 项 | 说明 |
|:---|---|
| 喂哪几个指数 | 七个主指数 —— 上证指数／创业板指／沪深300／上证50／中证500／中证1000／科创50。双创不单列，它是创业板指与科创50 的组合 |
| 取哪一刻 | 发帖时刻 |
| 取哪个价 | 那一刻**可获取的最新价格** |
| 报告、回测 | 事后取 30 分钟线：**盘中**（交易日 `9:30~11:30`、`13:00~15:00`）→ **结束时刻严格晚于发帖时刻的第一根**的开盘价（10:20 发布 → `10:30` 那根；整点发布不回落：`10:00:00` 取 `10:30` 那根，不是刚收完的 `10:00` 那根）；**其余**（`11:30`、`15:00` 本身，以及午休、盘后、盘前、休市）→ **结束时刻不晚于发帖时刻的最后一根**的收盘价（午休 → `11:30` 收盘；盘后 → 当日 `15:00` 收盘；盘前或休市 → 上一交易日末根） |
| 推送 | 实时取**现价**，不读 30 分钟线 |
| 注记头 | 标明这一份是哪一种（报告、回测 `盘中(30分钟线当根开盘)` ／ `上一根(30分钟线收盘)`；推送 `现价(推送时刻)`），模型据此知道这个数字的分量 |
| 30 分钟线结构 | 每指数每日 **8 根**（`10:00`／`10:30`／`11:00`／`11:30`／`13:30`／`14:00`／`14:30`／`15:00`），**bar 时间 = 收盘时间**；首根就是 9:30 那根（覆盖 9:30~10:00，标为 `10:00`），其开盘 ≈ 9:30 开盘价；末根收盘 = 当日收盘价 |

### 2.2 注记必须在场

> **解析任何一条帖之前，行情必须已经覆盖到这条帖的发帖时刻。取不到 → 这条帖不解析。**

这一条管报告、回测 —— 调用方负责把行情备到这一步（01§10）。推送的注记取现价，不依赖行情覆盖，与 30 分钟线无关（§2.1）。

### 2.3 与 03 的参考价同源

报告、回测的注记，就是 03 事后打分时用的那个参考价 —— 同一个口径、同一个值。**终点价也从这套 30 分钟线来**：验证终点日**最后一根 30 分钟 K 线的收盘价**（见 03§3.3）。推送的注记取的是推送时刻的现价，03 事后按发帖时刻的口径重算，这两个数可以不等。

> **两处口径一旦分叉，模型判对的会被算成判错。**

## 02§3 ① 方向 `d` —— 必有

### 3.1 什么算方向

只有两个取值：`1` 看多 ／ `-1` 看空。认不认，就看这处表述能不能落成「涨」或「跌」这一对反义。

| 帖里怎么说的 | 算不算 | 落成 |
|:---|---|---|
| 涨／看多／偏多／大方向向上 | 算 | `1` |
| 跌／看空／偏空 | 算 | `-1` |
| 震荡上涨 ／ 震荡下跌 | 算 —— 形态词里就带着涨跌 | `1` ／ `-1` |
| 弱势震荡 ／ 震荡调整 ／ 高位震荡回调 ／ 调整 | 算 —— 形态词带上了方向补语 | `-1` |
| 收阳 ／ 收阴 | 算 —— 单一收法就是涨跌的同义表达 | `1` ／ `-1` |
| 预期点位高于参考价 ／ 低于参考价 | 算（参考价见 §2 的行情注记） | `1` ／ `-1` |
| 不看空／不看跌／不要悲观；不会深跌／不会跌破 | 算 —— 否定一个方向，给的就是它的反面 | `1` |
| 不看多／不看涨；不会大涨／不会创新高；没有好的行情 | 算 | `-1` |
| 有望涨／有望冲击 4200 点／还有反弹空间／反弹修复 | 算 —— 不必等一个「涨」字 | `1` |
| 需防备再次跳水／要小心杀跌 | 算 —— 告诫要防的那个方向就是方向 | `-1` |
| 高位反复筑顶／反复的诱多 | 算 —— 都是说往下 | `-1` |
| 震荡／筑底／洗盘／蓄势／拉锯／考验支撑 | 不算 —— 光一个形态词，不承诺往哪走 | — |
| 无净方向收法（「收小阳线或十字星」） | 不算 —— 两种收法摆在一起，等于没选 | — |
| 先抑后扬／先跌后涨／冲高回落／探底回升 | 不算 —— 整条并列摆着，没说终点在哪；落点明确偏在后段的算（「熬过了先抑的阶段，后扬才刚刚开始」） | `1` |
| 其余取值 | 一律丢掉 | — |

### 3.2 必须是无条件的

**方向不能挂在一个博主并未承诺会发生的前提上。**

> 「破了3900就减仓」「守住4000不破才能…」「3900是多空分水岭」「放量就站稳，否则转震荡」

不产。博主明显倾向某一分支 ≠ 方向。

**自测**：这处表述能否不改意思地改写成「博主无条件预测 〔某指数〕在 〔某周期〕 〔涨／跌／到某点位〕」？不能 → 不产。

**带「若／如果」的整句一律不产** —— 不分从句与主句，条件挂在指数自己的走势上（「破了3900就减仓」「如果明天低开」）与挂在指数之外（外盘、政策、消息）一样丢。

### 3.3 操作动词就是方向

**博主做出或建议一个操作动作，等于表了态**，即使没有单独一句「大盘要涨/要跌」 ——**条件式里内嵌的操作不算**（「破了3900就减仓」，见 §3.2）；**过去时的操作报告不算**（「今天我把仓位加到了创业板」，那是仓位状态自述，见 §6）。

| 动作 | 方向 |
|:---|---|
| 减仓／清仓／轻仓／止盈／逢高抛／卖出 | 看空 |
| 加仓／重仓／补仓／逢低买／抄底 | 看多 |

### 3.4 方向词必须出自原帖

产出一条结构化数据之前，逐字核对 —— 要把某个方向词安到这个三元组上，**那个词必须在原帖的 `title` 或 `content` 里搜得到**。

> **搜不到 = 编造。** 编造（凭空造出博主没说的话）与硬凑（把不是方向的读成方向）**同样严重，都不允许**。
>
> 严禁替博主补一个他没说的方向词，严禁把本文的示例措辞搬进引文 —— 示例只示形状，不是可复制的原文。

## 02§4 ② 周期 `spec` —— 可缺

**「档」在本文＝周期档位**（`spec`），说的是一段时间；推送那个「档」是时刻表上的一个点（06§5.1） —— 同一个字，两回事。

### 4.1 全表

**周期必须通过语义理解读出，不是关键词匹配** —— 帖里出现「明天」二字，不代表这就是对明天的预测（「明天开始至本周五」说的是本周，「明天」只标起点）。博主说什么周期就落什么档：不扩展、不缩短、不随意假设，每档锁定一个精确验证终点。

| `spec` | 什么时候用 | 验证终点 |
|:---|---|---|
| `today` | 今天／今日／下午／午后／尾盘 | 发帖当天收盘（必须交易日的收盘前发布） |
| `t1` | 明天／明日／次日 | 发帖后第 1 个交易日 |
| `t2` | 后天 | 发帖后第 2 个交易日 |
| `tN` | N天后／N日内 且 N≤20 | 第 N 个交易日 |
| `t5` | 近期／短期／很快／马上／即将／不久／临近／未来几天／接下来／当前阶段；没说周期 | 发帖后第 5 个交易日 |
| `monday`～`friday` | 周一～周五（指本周的那一天；「本周初」→ `monday`） | 发帖当周的那一天 |
| `week` | 本周／这周／本周内 | 发帖日所在那一周的最后交易日 |
| `nweek` | 下周／下周末 | 下一周的最后交易日 |
| `nmonday`～`nfriday` | 下周一～下周五（「下周初」→ `nmonday`） | 下周的那一天 |
| `month` | 月底前／月末前 | 当月最后交易日 |
| `nmonth` | 下个月／下月 | 下月最后交易日 |
| `d:YYYY-MM-DD` | 博主给了具体日期（「8 月 20 日会涨」） | 该日期 |
| `long` | 下半年、全年、今年、明年、中长期、未来几个月、三年、长线、最终、始终、N天后／N日内（N > 20） | 无 |

**区间的两头只算末** —— 「1-2天」「3-5天」这类 X-Y 天、「今天和明天」「最快下周一最迟下周二」这类明说两头的，一律取窗口最后那一天的那一档（→ `t2`／`t5`／`t1`／`ntuesday`），不两头各出一条。

**「明天」压过「周几」** —— 同一处表述里「明天」与「周五」指的是同一天时，落 `t1`；明天正好是周五也一样。

**时间词要出自承诺方向的那一句** —— 引文里别处（铺垫、复盘）的时间词不作数。方向那半句自己没带时间词的落 `t5`（「今天开盘之后个股一度出现了普跌，我认为……并非是行情结束」里，「今天」只是回顾）。

表里的「交易日」一律指 A 股交易日，不是自然日。**「信号日」＝发帖自然日** —— 「发帖后第 N 个交易日」一律从发帖日往后数（周五盘后说「明天」→ 验证周一）。

**验证终点就是博主说的那一天，不顺延。** 它落在非交易日（周末、节假日）的话，这条表述没有可验证的终点 —— 不成立，不产（§4.2）。整周、整月一个交易日都没有的，同理：那一格说的「最后交易日」根本不存在。

### 4.2 未来 / 复盘 / 过期

| 这处表述是 | 怎么办 |
|:---|---|
| 对未来的承诺 | 捕捉 |
| 对已发生行情的回顾（复盘） | 不捕捉 |
| 说现在是什么样（状态描述：「已经进入调整期」「顶背离已经出现」） | 不捕捉 |

**「这处表述是不是对未来的承诺」是语义判断，归本文；「发帖时间是否已晚于验证终点收盘」是按时间的机械判断。** 机械那半的判据：`pub` 晚于对应 `spec` 验证终点的收盘时间（**任何档位**） —— 边界取等，发帖正好是收盘那一刻（15:00:00）算「晚于」。

本文拦两类：**终点落不到交易日**（说的那天没开市，见 §4.1），以及**当场能定下终点的三档过期** —— `today` → 交易日收盘后；`week` → 当周最后一个交易日收盘后；`month` → 当月最后一个交易日收盘后。其余档位的过期同理（对照 §4.1 的终点列），但它们的终点要摊开交易日历才算得出来、本文拿不到，归 03 机械兜底（03§3.6，同一判据）：

| 情形 | 怎么办 |
|:---|---|
| 验证终点落在非交易日 | 说的那天没开市 → 不成立，不产 |
| pub 在交易日收盘后 且 spec=`today` | 视为回顾/复盘 → 不产 |
| pub 时间晚于当周最后一个交易日收盘 且 spec=`week` | 视为回顾/复盘 → 不产 |
| pub 时间晚于当月最后一个交易日收盘 且 spec=`month` | 视为回顾/复盘 → 不产 |

`today` 的终点就是发帖当天，所以第一行对它就是「非交易日发布」。这一行与第二行合起来，是 `today` 的成立条件：**发帖日必须是交易日，且发帖时刻在收盘前**。

**同一条帖既有复盘又有未来预测 → 只捕捉未来预测那部分**（挑哪一句见 §1.1）。

### 4.3 帖里出现日期不等于预测

是对未来的窗口（「8月7日之前都是磨底」）还是对过去的回顾（「2月8日我还提醒了一次」） —— 只有预测语境才落档，落成 `d:YYYY-MM-DD`（§4.1）；回顾 → 不产。**日期与周期词同现时跟周期词走** —— 「本周到 8 月 20 日」落 `week`，不落 `d:`。

这一判断由模型做，强校验与脚本再兜一道（§10）。

### 4.4 没给周期时

| 情形 | 落哪 |
|:---|---|
| 有方向、没给时间 | `t5`，正常计分（「减仓为主」「随时会涨」「肯定要涨但不知道什么时候」） |
| 有点位、没给时间 | `t5`，正常计分（「目标是 4260 点」「还有 X 点空间」） |
| 有点位、给了时间 | 跟时间走（「今天下午能站上 4000」→ `today`；「明天站上 4100」→ `t1`；「下周到 4000」→ `nweek`） |

## 02§5 ③ 对象 `idx` —— 必有

### 5.1 只能是这八个

**上证指数 ／ 上证50 ／ 沪深300 ／ 中证500 ／ 中证1000 ／ 创业板指 ／ 科创50 ／ 双创** —— 只有这八个，其余一律落不到对象上。其中**双创是组合**（创业板指与科创50 各占一半）；**深证成指、北证50、行业指数都不在其中**，博主只谈这些的话捕捉不到观点信号。

别名归一与「帖里出现什么算什么」见 §5.2；核心预测句未点名指数/板块 → 见 §5.4。

### 5.2 映射表

| 帖里出现 | 预测对象 | 代码 |
|:---|---|---|
| 创业板／创业板指／创业板ETF | 创业板指 | 399006 |
| 科创／科创50／科创板／半导体／芯片 | 科创50 | 000688 |
| 小盘／成长／中证1000 | 中证1000 | 000852 |
| 中证500 | 中证500 | 000905 |
| 上证50／50ETF／老登／大金融／银行／保险／券商／证券／白酒／酒 | 上证50 | 000016 |
| 沪深300 | 沪深300 | 000300 |
| 上证综指／上证／综指／大盘 | 上证指数 | 000001 |
| 双创 | 双创 | 399006/000688 |

**其余板块一律忽略**：有色／钢铁／医药／创新药／恒科／电池／航天／军工／房地产等。

### 5.3 对象跟着这一处表述走

预测对象是这一处表述里博主给出方向/时段/点位的那个对象，不跟着帖子主题、论据里提到的别的指数、或市场氛围漂移 —— 一条帖对上证和创业板各说一句，那是两个三元组，各成一条，不许揉成一条上证（去重与条数见 §7）。

### 5.4 未点名指数时的映射规则

核心预测句未点名板块或指数时，`idx` 按下表定。参照是注记里上证指数的发帖时刻现值，**不是模型记忆里的旧点位**；**「合理范围」＝ 上证现值 ± `parse.band`**（§12，现值 0.10 —— 现值 3900 时即 3510～4290），**边界取等** —— 比大小时取等，边界一律归严的那一侧，正好差到半宽算带外。**不靠点位反查归到别的指数**：博主没点名对象、点位又对不上上证 → 这条预测作废，不猜。

| 情形 | 怎么办 |
|:---|---|
| 给了预测点位，点位属于上证指数短期未来的合理范围 | `idx` = 上证指数 |
| 给了预测点位，点位不属于上证指数短期未来的合理范围（差出发帖时刻上证现值 ± `parse.band` 以上、明显是另一个指数的量级） | 不视为信号，不产 |
| 没给点位，给了方向预测 | `idx` = 上证指数（默认：对上证综指/大盘的判断） |

## 02§6 凑不成观点信号的情形

按缺哪个分量归类。这些说的是「这段话不算数」，不是「这帖作废」；一条帖里可以同时有几处各缺各的。

| 缺哪个 | 哪些情形 | 例子 |
|:---|---|---|
| ① 缺方向<br>（没有博主本人的明确方向） | **条件式** | 「破了3900就减仓」「守住3900看反弹」「放量突破才追」「冲高回落转守4000」「接下去每跌50点加0.5成」 |
|  | **状态假设**（与条件式同类） | 「在大家情绪再次上头的时候」「下周科技再高开或者再冲高的时候」「科创50指数大涨高潮之后」「短期跌多了反弹修复一下」 —— 把方向挂在「……的时候」「……之后」上，和挂在「若／如果」上是一回事 |
|  | **观察句** | 「明天会怎样，先看4000反击」 —— 说的是看哪里，不是承诺往哪走 |
|  | **路径形态**（先A后B） | 「明天冲高回落」「下周先抑后扬」 |
|  | **周期词不救形态** | 「这周高开低走」「今天冲高回落」「下周探底回升」 —— 带周期词的形态句仍是形态句，没有一句独立无条件的方向句就不产 |
|  | **开盘形态** | 「周一我们的市场无疑会高开」「明天低开」 —— 说的是开盘那一刻，不是收盘（验证终点在收盘）；方向看同一句里有没有承诺走高，「继续创新高」照产 |
|  | **模棱两可** | 「可能涨也可能跌」「边走边看吧」「即将变盘」「不好说」「看市场情绪」 |
|  | **骑墙** | 「不会大涨，但再创新低的可能性不大」「指数或许不会深跌，但会有很多人在个股上亏钱」 —— 把同一处表述里的每个否定式翻成它的反面再数，数出方向相反的两个方向词就是骑墙，等于没选；后面再补一句主句也不算把它了结，「不会大跌，也不会大涨，而是缓慢爬升」仍是骑墙，不许读成「排除极端 ＋ 承诺温和上行」；同一个方向说了两遍不算骑墙 |
|  | **表态度不给动作** | 「多看少动」「观望吧」「控制好仓位」 —— 是态度、不是动作，不算 §3.3 的操作动词 |
|  | **立场自述** | 「看法不变」「维持观点」 —— 单说没变不算；同一帖里引出了具体论证的，按那个论证产 |
|  | **仓位状态自述** | 「还剩4成」「满仓持股」「我拿着不动」「我把仓位加到了创业板」 |
|  | **投资理念** | 「长期持有优质公司」 —— 理念自述，不是方向 |
|  | **转述他人** | 「机构认为底部在3700-3800」「券商觉得…」 —— 机构/券商的看法不是博主本人表态，博主以自己口吻明确背书才认 |
| ② 缺周期<br>（不是对未来的承诺） | **纯复盘** | 「昨天猜中了开头，却没猜中结尾」「今天这波下跌说明……」「这次探底回升很标准」 |
|  | **状态／背景句** | 「已经进入调整期」「顶背离已经出现」「目前处于上升趋势」「在趋势之上」「创新高」「很安全」「强势」「安心持股」；「等 XX 筑底后上证走强」里上证只是受益方 —— 说现在是什么样，或主谓不是在预测上证未来涨跌 |
|  | **过期** | 见 §4.2 的拦截表（其余过期机械判断归 03） |
| ③ 缺对象<br>（落不到指数） | **只谈行业板块** | 全帖只谈有色、房地产、军工 |
|  | **未点名指数且点位不在上证合理范围** | 只说「市场」「行情」给了点位，但点位明显对不上上证短期合理范围 → 不产 |
| 三个都缺 | **无实质内容** | 只有话题标签（`#晒图笔记大赛#`）、平台活动、与股市无关的日常 |

## 02§7 一条帖能出几条观点信号

| 情形 | 几条 |
|:---|---|
| 同一对象 + 同一周期 + 同一方向，在帖里重复说了几遍 | **一条** |
| 不同周期 | **各一条**（「今天市场会大涨」＋「这周市场启动的判断不变」= 两条） |
| 同一周期但不同对象 | **各一条** |
| 同一对象同一周期但方向相反 | **各一条** |
| 同一天的另一条帖说了同样的话 | **不去重** —— 本文只判一条帖，两条帖各算各的 |

**不做乘法** —— 别拿「一句话 × 几个周期 × 几个指数」去组合：「上证明天涨，创业板这周看好」是两条，不是四条。**不得只取近端周期、把远端丢掉，也不得把两个周期并成一条。** 各条的引文从载各自时间词的原句逐字截取（§9）。

## 02§8 输出字段

| 组 | 谁填 | 字段 |
|:---|---|---|
| **A 读帖判断** | 模型 | `d` · `spec` · `idx` · `quote` |
| **B 帖子身份** | 系统 | `post_id` · `pub` |

模型只写 A 组；`post_id`／`pub` 由系统按帖子补上，模型一律不写 —— 避免模型誊写编号、时间出错。所以一条结构化数据 = 6 个键。**计分与否不在这里判** —— 那是报告统计环节从 `spec` 与 `pub` 算出来的（见 03）。

```json
{"post_id": "7514028836195041826", "pub": "2026-01-04 15:16",
 "d": 1, "spec": "t1", "idx": "上证指数",
 "quote": "明天大盘大概率高开"}
```

一条帖产出零条 → 就是一个空列表。

## 02§9 `quote` 佐证原话

**这个三元组在帖子里的原话，用来佐证博主确实这么说过。**

| 规则 | 说明 |
|:---|---|
| **必填** | 每条结构化数据都要有引文 |
| **限长** | **≤ `quote_limit` 字**（超了截到限长内，**不许为凑长度改写**；宁可短也不能改字） |
| **逐字** | 不许改写、润色、编造 |
| **可以是不连续的两段拼起来** | 段与段之间在原文里可以不挨着；每一段都要能逐字搜到 |
| **重复的几处并成一份** | 同一条重复出现（§10.1 去重）：各段按在帖里的先后接起来，段间用省略号；重复的、与别的段重叠的（同一处只留最长的那段）、接上就超 `quote_limit` 的，都不要 |
| **必须能佐证这个三元组** | 引文里得摆出三样：`idx` 的原话（点名的指数，或 §5.2 映射表里那个别名／板块词）、`d` 的原话、`spec` 的原话（时间词）。帖里没给的两样不要求 —— 没点名指数（§5.4 落默认的）与没说周期（§4.4 落 `t5` 的） |
| **与这条的方向无关的句子不算佐证** | 哪怕它在原文里、哪怕它载着时间词 |
| **截取起点** | 从载有时间承诺那句的句首附近截起，别只截丢掉时间词的后半句 |
| **来源** | `title` 或 `content`，两边都可以 |
| **引文宽窄不影响条数** | 引文是证据，不是容器 —— 两条可以引同一句原文 |

## 02§10 自查与强校验

### 10.1 强校验

**在一条帖的产出上就地做**，不合格的直接丢：

| 检查 | 处置 |
|:---|---|
| `d` 不是 `1`／`-1` | 丢掉 |
| `idx` 不在八个合法对象里 | 丢掉 |
| `spec` 不在档位表里，或语义荒谬（`t0`／`t99`／`d:2026-13-99`） | 丢掉 |
| `d:` 的具体日期早于发帖日 —— 是回顾，不是预测（§4.3） | 丢掉 |
| `quote` 缺失或为空 | 丢掉 |
| `quote` 超过 `quote_limit` 字（§9） | 截到限长内（**不丢行**；截断后仍须逐字可搜） |
| `quote` 有任一段在这条帖的 `title`／`content` 里搜不到 | 丢掉 |
| 点位是否落在「上证现值 ± `parse.band`」内 —— 脚本按注记现值复算（§5.4） | 与模型结论不符时以脚本为准 |
| 同帖内同对象同周期同方向重复 | 只留一条 —— 引文并成一份（§9） |

### 10.2 同一帖跑多次，分歧才交模型定夺

**同一条帖跑 N 遍**，每遍独立过 §10.1 强校验。各遍的产出再**按帖比三元组**（`d`／`spec`／`idx`，**不看 `quote`**）：

| 比出来 | 怎么办 |
|:---|---|
| 各遍一样，或只差引文 | **不送模型** —— 直接取；同一条的引文**并成一份**（§10.1 去重那条） |
| 某一份多一条、或少一条 | 这一帖**送模型** |
| 条数相同，但三元组对不上 | 这一帖**送模型** |

**一批里一处对不上的都没有 → 整批不调模型。** 送的是**整条帖**，连同各遍在它上面的**全部**产出 —— 四关要落在这条帖的每一处产出上，不只落在对不上的那几处。**一份产、另一份不产也算对不上。**

N 取 §12 的 `parse.runs`（现值 2）；**N = 1 时无从可比，这一步退化成单纯的自查** —— 一份产出也照样交模型复核一遍。**回喂时每一处产出都要带着「出自哪条帖」** —— 模型只能靠这个认出引文属于谁，少了它会把 A 帖的引文安到 B 帖头上。定夺要拦这四样：

| 拦什么 | 怎么认 |
|:---|---|
| **形态被读成方向** | 引文里的方向词在原帖里搜不到 → 一律丢掉 |
| **周期编码错** | 「本周」已走完却编了 `week` → 按 §4.2 该表述丢掉；「下周一」~「下周五」落错 `t1`／`nweek` → 改回 `nmonday`~`nfriday`，方向与引文一字不动 |
| **条件式硬凑方向** | 方向是从「守住/跌破/分水岭」或路径形态里压出来的，而帖内没有独立无条件的方向句 → 丢掉 |
| **骑墙** | 同一处表述里正反都说（§6）→ 丢掉；句尾补的那半句不算把它了结 |

**怎么定**：**逐遍审每遍列出的每一处** —— 过不了上面四关的是**错的**，剔掉；剩下的**并起来**。不是从几遍里挑一份，也不是取交集。**每遍还要分清是错了还是漏了** —— 漏掉的那处要捞回来。

| 情形 | 怎么定 |
|:---|---|
| 同一条在几份里都有 | 留下，引文并成一份（§9） |
| 只有一份提到、其余都没有 | 先当成别的遍**漏了** —— 过得了四关就留，过不了才丢 |
| 几遍的三元组对不上 | 逐个审它站不站得住：错的剔掉，对的都留 |

**每一条都要与 N 份里的某一条逐字一致**（除了被改过的 `spec`，以及 §9 并起来的引文）—— 不许新造引文。**不改 `d`**（方向词在原帖搜不到是丢，不是改），**不做乘法**，也不许把 N 份里没有的东西凭空补上。

能系统性修掉漏结论、周期误套，但不能保证每条语义都对 —— 方向冲突的帖仍会偶发分歧。

## 02§11 模型网关

读一条帖这件事由谁来做、做不通怎么办。**规则文本就是本文 §1～§10**，落在 `blogger/parse/prompts.py`。参数值见 §12。

| 项 | 规矩 |
|:---|---|
| **调哪个** | `parse.model`；网关地址 `parse.base_url` |
| **怎么调** | 温度固定 `0`、`max_tokens` 固定 `8192`、思考开关按调用点给 —— 三样写死在网关里，不是配置键 |
| **要什么回来** | 一律要求返回 JSON。回来的不是 JSON → 算这次调用没成，走重试 |
| **调不通** | 连同首次一共试 `parse.max_retries` 次，间隔从 `parse.retry_delay` 秒起、逐次递增 |
| **硬超时** | 单次调用超过 `parse.call_deadline` 秒就断，按「没成」处理 |
| **全失败** | 抛错，不做「静默跳过」 —— 这一批判不出来就是这一轮没跑成，交给调用环节处置（03§6）。绝不把「没判出来」当成「这条帖没有观点」 |

**模型名与「一条帖跑几遍」都进判断缓存的指纹**（03§2.2） —— 换模型、换跑几遍，都是换了个读法，旧的判断全部作废、重判一遍。

## 02§12 可调参数

**本文每一条判据都不写死** —— 全部从仓库根的 `config.json` 的 `parse` 一节读。改参数只改那一份文件，不碰代码。

| 键 | 管什么 | 本文哪一节 | 现值 |
|:---|---|---|---|
| `parse.band` | §5.4「合理范围」的半宽 | §5.4 | 0.10 |
| `parse.quote_limit` | 引文限长（字） | §9 | 60 |
| `parse.runs` | 一条帖跑几遍 | §10.2 | 2 |

| `parse.base_url` | 模型网关地址 | §11 | `https://api.deepseek.com` |
| `parse.max_retries` | 一次调用连同首次一共试几次 | §11 | 3 |
| `parse.retry_delay` | 两次之间的间隔（秒，逐次递增） | §11 | 5 |
| `parse.call_deadline` | 单次调用的硬性超时（秒） | §11 | 180 |
| `parse.batch_size` | 一次喂几条帖 | 03§2.2 | 15 |
| `parse.batch_char_budget` | 一批的字数预算 | 03§2.2 | 30000 |
| `parse.per_post_limit` | 单帖正文截断长度（字） | 03§2.2 | 4000 |
| `parse.batch_pause` | 批与批之间的间隔（秒） | 03§2.2 | 0.5 |

- `band`／`quote_limit`／`runs` 是本文自己用的；`model` 到 `call_deadline` **五个**归 §11（模型网关）
- 后四个键归 03 定、归 03 用（03§2.2） —— 列在这里只是为了「解析的参数」有个地方一次看全

- 同一份 `config.json` 里，抓取／单博主报告／全博主对比／回测／推送各自的参数各占一节（见 01§12、03§8、04§8、05§9、06§9）
