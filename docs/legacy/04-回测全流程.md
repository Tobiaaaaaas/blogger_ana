# 04 · 回测全流程

**这份文档管什么**：把「波段板块每天的看多比例」当成一个交易信号，用一套带开仓线/平仓线的规则跑出来的净值。
**这份文档不管什么**：判断规则（见 01）、推送（见 02）、报告（见 03）、榜单（见 05）。

---

## 04§0 边界：系统里有三个回测单元 〔主干〕

它们**各回答一个不同的问题**，用的数据、节奏、基准**都不一样**：

| 单元 | 回答什么问题 | 本文覆盖吗 |
|:---|:---|:---|
| ① **超短板块逐档进出场** | 按超短板块的信号进出场能赚多少 | **否** |
| ② **信号本身的质量** | 这些判断**准不准**（方向命中率、平均分），以及和 30 位波段成员的横向对比 | **否** |
| ③ **波段看多比例跑滞回** | 把当天的看多比例当成仓位信号，按开仓/平仓线跑出来的净值 | **是 —— 本文只写这个** |

**三者的数字不能互相比较。** 节奏（逐档 vs 每日）、交易标的、基准都不同，放在一张表里比会得出错误结论。同一个「赚的比例」，在回测里叫「**往返盈利比例**」、在报告里叫「**正确率**」，是两回事（见 §7.3）。

另两个单元的入口与产物位置，见本文 §6 末尾。

## 04§1 回测与实盘的三个根本区别 〔主干〕

### 1.1 不允许用未来信息

每个决策时刻**只看那之前发的帖**。

实现上有一条硬规矩：某个决策日的窗口里，**发布时间必须严格早于决策时刻** —— 卡在决策时刻那一分钟发的帖不算数。这条是为了防止「用当天收盘后才知道的消息，做当天盘中的决策」。

### 1.2 只在「语料齐全的交易日」上跑

缺料的日子**直接跳过**，不参与回测。

**什么叫「语料齐全」**（这个概念容易被望文生义，先说清）：它管的**不是「有没有人表态」**，而是**「帖子有没有抽完」**。

具体判据是：某位博主**已经抽取到的最新日期**，早于决策日；但帖库里显示他在此之后还发过帖、且那些帖可能落进窗口 —— 这就是**右侧漏抽**，那天不干净。

- **有人整天没观点 ≠ 不干净** —— 那是正常的，回测照样跑。
- **入册之前的历史也不算漏抽** —— 只要求「入了册之后别漏」。

> **当前值**：波段板块有 **149** 个语料齐全的交易日，区间 **2026-01-05 → 2026-08-14**。08-17 起因右侧漏抽被剔除。（这个数字随抽取进度变化，见 `research/combo/reports/combo_hyst.md` 头部。）

### 1.3 样本内结论，不是显著性

本文所有数字都是**在已知历史上调出来的结果**，不是统计检验。

换句话说：阈值是在这段数据上挑的，它在这段数据上表现好是**必然的**。要判断它是不是真的有效，得看 §5 的换池与参数敏感性 —— 而那些也只能说明「稳不稳」，不能说明「未来行不行」。

## 04§2 地基 〔主干〕

### 2.1 跑之前必须先重建语料

回测**不直接读原始信号**。原始信号是另一套格式，要先**重建**成回测能用的语料。

```
python -m research.corpus
```

它做的事情：把原始信号目录下的文件规范化成回测语料，**不重跑模型**（读的是已经判断好的结果）。

**不跑会怎样**：不是跑出空结果，是**直接崩** —— 语料缺失的博主会被当成「无从判定」，导致没有任何一个交易日是干净的，最后在算指标时越界出错。

### 2.2 语料每条记录有哪些字段〔细节〕

| 字段 | 含义 |
|:---|:---|
| 博主 | 谁 |
| 发帖时间 | 精确到分钟 |
| 方向 | 看多 / 看空 |
| 强度 | 强 / 中（只有计分行有） |
| 目标指数 | 见 01§5 |
| 周期档位 | 见 01§6 |
| 计不计分 | |
| 摘要 | |
| **板块归属** | 周期档位是 `today`／`t1` 之外的 → 波段 |
| **验证终点** | 绝对日期；无期限的为空 |
| **终点文案** | 给人看的说法 |

**唯一一条剔除规则**：`today` 档但**发帖日不是交易日**的行 —— 它没有可交易的目标日。（当前实测剔除 2 条。）

### 2.3 每位博主每天怎么被压成一票

每个决策日，对板块里的每位成员**各算一票**：

1. 取**回看窗口**以内的帖。窗口按交易日算，波段是**前 5 个交易日**的 00:00 起到决策时刻。
2. 按发帖时间**从新到旧**逐条扫。
3. 取**第一条通过全部条件**的 —— 这就是他这一天的表态。

**哪些行会被跳过**：

| 跳过条件 | 为什么 |
|:---|:---|
| 目标指数不是**上证指数** | 回测的投票口径固定看上证（见 §2.4） |
| 板块不符（这条信号不属于波段） | 各算各的 |
| **不计分**的行（`long`／年度目标之类） | 它们没有验证终点，不构成当天的态度 |
| **验证终点已经过去** | 说过期的话不算今天的表态。**注意：跳过它之后继续往旧扫**，不是到此为止 |
| 该成员当天被「覆盖缺口」整档剔除 | 见 1.2 |

全部跳完、一条都不剩 → **这位博主今天不算数**（不是算中立），不进分母。

**同一分钟的多条帖**：按语料里的原始行序，取最后一条。（语料的时间只精确到分钟，没有秒。）

### 2.4 信号看的指数与交易的标的为什么不是同一个


- **看什么**：上证指数 —— 因为板块里的博主绝大多数在谈上证，观点口径统一。
- **交易什么**：**中证1000** —— 因为中证1000 弹性更大，用上证的观点去交易中证1000，是这个策略**刻意选的**增益设计。

这条**必须记住**：净值曲线是**中证1000** 的，不是上证的。看到「基准 +0.2%」时，那是中证1000 买持在这段时间的涨幅，不是上证。

## 04§3 滞回状态机 〔主干〕

### 3.1 为什么要开仓线 ≠ 平仓线

如果开仓和平仓用同一条线（比如都是 2/3），看多比例在阈值附近来回抖时，策略会**反复买卖**，被噪声牵着走。

所以把两条线**分开**：**开仓要 2/3 以上，平仓要跌破 1/2 才触发**。中间那一段（1/2 到 2/3 之间）**什么都不做，维持现状** —— 这个中间区间就叫「继续持有的中间区间」。

### 3.2 状态机三步

每个决策日按**固定顺序**检查三步：

```
第一步 · 平仓门（先看现在持的仓）
    持多 且 表态人数够 且 看多比例 < 1/2  →  平掉，空仓
    持空 且 表态人数够 且 看多比例 > 1/2  →  平掉，空仓
        │
        ▼ 没平掉
第二步 · 继续持有，本日结束
        │
        ▼ 已经空仓（原本就空仓，或刚被第一步平掉）
第三步 · 开仓门
    表态人数够 且 看多比例 > 2/3  →  做多
    表态人数够 且 看多比例 < 1/3  →  做空（仅双向模式）
    否则                          →  继续空仓
```

**同一天可以换向。** 因为第三步对「刚刚平完仓」也生效 —— 持多时看多比例掉到 1/3 以下，**同一天**就能从持多直接变成持空，中间没有空仓的隔夜。

（仅做多模式下，平掉之后最远只到空仓，不会开空。）

### 3.3 阈值表

| 参数 | 当前值 | 含义 | 「恰好等于」怎么算 |
|:---|:---|:---|:---|
| 看多开仓线 | **2/3** | 看多比例 **>** 2/3 才开多 | **严格大于** —— 恰好 2/3 **不触发** |
| 多头平仓线 | **1/2** | 看多比例 **<** 1/2 才平多 | **严格小于** —— 恰好 1/2 **继续持有** |
| 开仓法定人数 | **10** | 表态人数 **>** 10（即**至少 11 人**）才允许开仓 | 严格大于 |
| 平仓法定人数 | **10** | 表态人数 **>** 10 才允许平仓 | 严格大于 |
| 回看窗口 | **5** 个交易日 | 见 §2.3 | — |
| 看空开仓线 | **1/3** | 看多比例 **<** 1/3 才开空 | 严格小于 |
| 看空平仓线 | **1/2** | 看多比例 **>** 1/2 才平空 | 严格大于 |

**空腿的阈值是从多头阈值算出来的**，不是单独设的：**看空开仓线 = 1 − 看多开仓线**、**看空平仓线 = 1 − 多头平仓线**。所以改多头阈值时，两条腿会**一起动**。

> **名字的坑**：这个参数组合叫「Q10」，字面看像「≥ 10」，实际是**严格大于 10**，也就是**至少 11 人**。

**比较时用整数运算，不用小数。** 看多比例是个分数（看多人数 / 表态人数），跟 2/3 比的时候，系统会把它改写成**两边整数相乘**的比较，避免浮点误差让「恰好 2/3」被判错边。

### 3.4 现状实证（当前语料）〔细节〕

- 表态人数 `e` 的分布：**8 到 27，均值 18.6**
- 被**开仓门**（`e > 10` 不成立）拦掉的日数：**4 天**
- 恰好 50%（偶数人数下正好一半）的日数：**14 天** —— 这些日子落在「继续持有」侧，不平不开
- 两步门唯一出现分歧的段落：`2026-01-08`（表态 10 人、7 多 3 空、看多比例 70%）—— 开仓门把「另一步会放行」的这次开仓拦了下来，这段分歧跨 7 个交易日

> **这组数字说明什么**：法定人数这道门**不是摆设** —— 它真的拦掉了几次开仓。如果去掉它，净值会不一样。

### 3.5 成交与净值口径


- **决策时刻**：每个语料齐全的交易日**一次 14:30 快照**
- **成交时刻**：**当天 15:00 收盘**
- **成交价**：**中证1000 的日线收盘价**

**成本为零。** 没有手续费、没有滑点、没有冲击成本、没有融券费。**全仓进出（0 或 1）**。

> **这一条必须记住**：净值曲线是**理论上限**，不是「实盘能赚这么多」。§7 还会再强调一次。

**净值怎么算**：
- 用**上一个收盘之后的目标持仓**，承担**这一段**的涨跌幅（收盘到收盘），逐日复利
- 决策日当天的涨跌**不由当天的决策承担**（因为 14:30 才拍板、15:00 才成交，当天的行情已经走完了）
- 样本结束时若还持仓，**按最后一天收盘强制平掉**

**空头按指数期货式的线性收益计算**（跌多少就赚多少），不计融券费和保证金。

### 3.7 换池与参数敏感性〔细节〕

- **换池**：换一批委员会成员跑同样的规则，看结论是否还成立。当前设了 9 个池（含 30 人基线、各种 12/15/18/21/24 人的子集）。
- **参数扫描**：窗口取 3/5/7/10，门槛取多组对称与不对称组合，开平仓线取多组取值，共 23 个参数格子 × 2 种模式。

> **⚠️ 见待定 #15** —— 参数扫描的说明里声称「不同窗口长度下**日期集合不变**」，但代码里**没有任何检查**保证这一点。窗口长度变了，窗口起点就变，「某位博主的帖是否落进窗口」的判定也跟着变，**日期集合理论上可能变**。换池脚本对同一件事**是有**一致性检查的，扫描脚本漏了 —— 意味着窗口那一轴的对比可能建立在一个悄悄失效的前提上。

### 3.8 三项尚未实现的指标

旧文档要求、**系统目前还没做**。按本次裁决写进规格，作为**待实现需求**：

| 指标 | 衡量什么 | 建议口径 |
|:---|:---|:---|
| **换手率** | 这套规则的交易频率有多高、交易成本会吃掉多少 | 每年往返次数；或「在场天数 / 总天数」的补数。**当前在场比例：仅做多 25.7%、双向 43.2%** |
| **卡玛比** | 每承担一单位回撤能换来多少年化收益 | 年化收益 ÷ 最大回撤。**当前值：仅做多 31.0%/7.2% ≈ 4.3；双向 81.5%/7.2% ≈ 11.3**。⚠️ 见待定 #16：回撤 7.2% 这个数在两种模式下**完全相同**，值得先确认是不是巧合 |
| **VaR** | 单日可能亏多少（在某个置信度下） | 对逐日收益取历史分位数（如 5% 分位），或参数法。**需要先定置信度与持有期** |

> **这三项的算法要你认可**才算数 —— 写清了就等于替你定了口径。特别是 **VaR 的置信度与持有期**、**卡玛比用哪条回撤**（最大回撤 / 年化回撤）。

## 04§5 常见误解 〔主干〕

**「+42% 是实盘能赚到的吗？」**
不是。这是**零成本、全仓、无滑点**的理论净值，而且阈值是在这段数据上挑出来的。**它是一条上限，不是预期。**

**「基准 +0.2%，所以这段时间大盘没动？」**
不是上证没动，是 **中证1000** 这段时间几乎没动。信号看的是上证，交易的是中证1000，基准跟着交易标的走。

**「所有交易日都参与回测？」**
不是。只在**语料齐全的交易日**上跑 —— 当前 149 天。缺料的日子直接跳过。

**「语料齐全 = 那天大家都发言了？」**
**不是。** 它管的是「帖子抽完了没有」，不是「有没有人表态」。有人整天没观点完全正常，那天照样算数。见 §1.2。

**「看多比例 2/3 就开仓？」**
不是。要**严格大于** 2/3。恰好 2/3 **不开**。

**「表态人数 10 人就能开仓？」**
不是。要**严格大于** 10，即**至少 11 人**。参数名叫「Q10」容易误读。

**「平仓之后要等一天才能开空？」**
不用。**同一天就能换向** —— 持多时看多比例崩到 1/3 以下，当天收盘就从持多变成持空。

**「一天里会看很多次吗？」**
不会。每个语料齐全的交易日**只看一次**（14:30 快照）。这跟推送链一天 20 档**完全不同** —— 回测和推送的节奏是故意不同步的（见 §7）。

**「回测里 80% 那个数和报告里的正确率是一回事吗？」**
**不是。** 见 §7。

**「净值曲线的波动 = 风险？」**
净值波动只是一部分。回测里没有算过「最坏单日会亏多少」（VaR 尚未实现），也没有算过交易成本会吃掉多少（换手率尚未实现）。

## 04§6 另两个回测单元（不展开）

各用一段话交代，免得以后误以为不存在：

**① 超短板块逐档进出场**（`research/backtest/`）
回答「按超短板块的信号、在每个推送档位进出场能赚多少钱」。入口 `python -m research.backtest.run_backtest`，产物 `research/backtest/reports/short_report.md` 等。与滞回的区别：**逐档**决策（不是每日一次）、基准是**上证买持**（不是中证1000）、可设手续费与成交延迟。样本是超短板块的 158 个语料齐全交易日（2026-01-05 → 08-27）。

**② 信号质量**（`research/quality/`）
回答「这批判断**准不准**」，并把它和 30 位波段成员放在同一张表里横向比较。入口 `python -m research.quality.run_compare`，产物 `research/quality/reports/composite_swing_compare.md`。它与滞回**不共享任何指标口径** —— 它的「强度」是按共识占比现算的代理值，不是博主自述的强度。

> **三个单元的数字不能放一张表里比。** 节奏、标的、基准都不同，而且「赚的比例」在三处的算法也不一样。

## 04§7 已知的过时设计与同名不同义 〔细节〕

### 7.1 死代码与遗留物

| 遗留物 | 情况 |
|:---|:---|
| 「波段一天 3 档」（09:30 / 11:00 / 14:30）这套设定 | 早已不用 —— 波段回测现在是**每个语料齐全日一次 14:30**。这套档位常量还留在配置里，标注着「遗留」 |
| 一个「列出决策时刻」的工具函数 | 没有任何调用者 |
| 「列出语料里的博主名」的方法 | 没有任何调用者 |
| 模块级的空腿阈值常量 | 只是说明性的 —— 真正生效的是每天现算的那两个，改这几个常量**不会改变任何行为** |
| 日期上下文里的几个字段（参考价、终点、终点收盘价、原始收益） | 没有消费者；另一个「半期切分下标」字段也没有 —— 真正切半用的是「净值长度除以 2」 |
| 超短板块回测的决策网格 | 是**冻结的更早基线**，与推送链现在的 20 档/日**故意不同步** |
| 超短回测的手续费参数 | 在滞回单元里**完全没用**（滞回没有成本参数） |
| 编译缓存里的一批旧模块 | 对应的源文件早已不在或已搬家 |

### 7.2 同一份文档里前后打架的地方

- `research/README.md` 那张「板块/网格/窗口」表里，波段的两列（一天 3 档、回看窗口 3 个交易日）**都写错了**，而它自称「单一事实源」。同一份 README 靠后的位置又写对了（每日一票、窗口 5）—— **同一份文档自相矛盾**。
- `research/README.md` 对超短语料齐全日的天数写了两个互相打架的数字，且给出的解释（「受行情数据覆盖截断」）是错的 —— 分钟线覆盖到 09-04，08-28 之后那几天没进样本只能是**漏抽门**剔的。
- `research/README.md` 说目标指数口径「可调、换成 any 几乎不变」，但代码是**精确相等**判断，而且语料里**根本没有 `any` 这个值** —— 真按它说的改，会过滤出 0 行，策略空转到不产生任何效果，且不报任何错。
- `research/README.md` 让读者「详见敏感性表」，但那张表**只打印到屏幕、没有存成文件**，仓库里不存在，无法复核。
- 有一份榜单产物是更早的快照，却与号称「同源重算」的专项榜**大面积对不上**（同一个人 N 和平均分都不一样）。两者确实调同一个算分函数，但产物不同步，且**没有任何地方标注它已过时**。
- 换池脚本的成员质量排序，与它自己引用的来源文件**对不上**（其中一位的分数被写成另一个值，且排序与来源文件的顺序相反）。这个排序决定了好几个池的边界。

### 7.3 同名不同义的词（**重要**）

同一个词在三处意思不同，**读的时候必须看清是哪一份产物**：

| 词 | 在滞回/超短回测里 | 在报告/榜单里 |
|:---|:---|:---|
| **旧文档说的「胜率」** | 指**往返盈利比例**：一次完整买卖毛收益 > 0 的比例 | 指**正确率**：单条信号得分 > 0 的比例 |
| **强度** | 不适用 | 信号明细里的「强度」是按**共识占比**现算的代理值，**不是**博主自述的强度 |
| **N** | 干净**交易日**数（149） | 计分**信号条数**（如 172 条）；专项榜里又是**信号日数** |

> 这正是 `00-术语对照表.md` 要解决的问题 —— 但存量产物的列名还没跟着改。
