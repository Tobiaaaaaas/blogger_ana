# 06 · 抓取

**管什么**：把博主发的帖子从今日头条搬进 `data/posts/`，并让全库的数据保持齐。
**不管什么**：怎么从帖子里读出信号（见 01）；推送和报告拿这批帖做什么（见 02 / 03）。

---

## 06§0 边界

| 谁用 | 抓谁 | 抓法 | 起始时间 |
|:---|:---|:---|:---|
| **单博主报告** | 那一位 | **全量** | 固定日期（如 `2026-01-01`） |
| **全博主对比报告** | 库里所有博主 | **补齐** | 各自的「抓取截止」所在那一日的零点 |
| **推送** | 名单内每位博主 | **增量** | 同上 |

三者用的是**同一套代码**，只差「抓谁」和「起始时间」两个参数。

---

## 06§1 一图流

```
一位博主 + 一个起始时间
   │
   ▼
抓 [起始时间 , 抓取那一刻] 区间内的帖（含正文）
   │
   ▼
按 post_id 去重，并入主文件 ── 旧帖原样保留，永不覆盖
   │
   ▼
把这次的两个时间写进主文件：起始时间 / 抓取截止
   │
   ▼
扫一遍所有主文件的「抓取截止」→ 离现在远的，各自补一段
```

一次抓取只做三件事：**抓、并、记**。它不判断、不打分、不推送。

---

## 06§2 三个时间

| 时间 | 是什么 |
|:---|:---|
| **起始时间** | **参数**：往回翻到哪，由调用方给 |
| **抓取截止** | **字段**：这次抓取**发生的时刻**，写进主文件 |
| **重叠余量** | **规则**，不是参数：续抓时退到「抓取截止」所在那一日的零点 |

- 起始时间由调用方给：**单博主报告**给固定日期，**对比报告的补齐**与**推送**给该博主自己的抓取截止
- 起始时间只决定「往回翻到哪」，**不决定「保留哪些帖」**
- 「抓取截止」是**抓取那一刻**的挂钟时间（形如 `2026-09-11 14:30`），**不是最后一条帖的发布时间**
- 「抓取截止」同时是**下次续抓的起点依据**（§4）和**判断谁的数据不齐的依据**（§5）
- 续抓时**退到**「抓取截止」**所在那一日的零点**
- 重叠部分靠 `post_id` 去重，**重复抓没有副作用**

---

## 06§3 抓取＝合并，永不覆盖

- 抓到的帖按 `post_id` 去重后**并入**主文件；**原有的帖原样保留**
- 起始时间只影响**翻页什么时候停**，不影响**文件里留下什么**
- 主文件的帖子数**只增不减**（除非博主自己删帖）
- 因此不存在「强制覆盖」这个开关
- 抓取**幂等**：同一位博主、同一个区间抓两次，结果完全一样

> 传一个很短的区间（如 `2026-09-01`）**不会**删掉历史。这与旧做法相反 —— 旧做法整文件重写，实测把 2191 条写成 61 条。

---

## 06§4 续抓

```
新起始时间 = 该博主「抓取截止」所在那一日的零点
```

（举例：他的抓取截止是 `2026-09-08 10:14` → 新起始时间取 `2026-09-08 00:00`）

- 没有抓取记录的博主（新博主），退回用调用方给的固定起始时间
- 每位博主**各记各的**，互不影响。**不存在一份全局的「抓到哪了」**

---

## 06§5 对齐与补全

「谁的数据不齐」= 把所有人的「抓取截止」放在一起，比**距现在多久**。

有一个**只读的查看命令**，打印对齐总览。**它不抓取、不修改任何东西。**

```
博主              起始         抓取截止            帖数   距今
张大坤            2026-01-01   2026-09-11 10:14   2191   0 天
白猫财眼          2026-01-01   2026-09-10 18:40   1847   1 天
稀豹              2026-01-01   2026-08-28 09:12   1582   14 天
```

- 总览只显示时间差，**不划落后线**
- **补齐** = 扫描全部博主，对「抓取截止」离现在较远的**各自补一段**（只从自己的截止往后抓）
- 补齐能**点名**补，也能**一把扫全部**（两者是同一个动作，只差有没有传博主名）

---

## 06§6 产物：主文件记什么

- 文件名**永远是** `<博主名>.json`，**不含时间**
- 主文件顶层记两个字段：`起始时间` / `抓取截止`
- 顶层**已经记着**、但语义要重新明确的：`时间范围`（帖子的**发布时间**跨度，是内容的属性）／`停止原因`（翻页为什么停）
- 每条帖子记：编号 / **标题** / **正文** / 发布时间 / 链接 / 互动数（两个文字字段的分工见 §7）

---

## 06§7 标题、正文与视频帖

**一条帖存两个文字字段，分开存。**

| 字段 | 是什么 | 从哪来 |
|:---|:---|:---|
| **标题** | 列表接口给的那段文字 | 翻列表时就有 |
| **正文** | 帖子详情页里的内容 | **逐帖再取一次** |

- 取正文在**同一条命令内部**完成，**不是另一道工序**
- 取正文走三条路径，逐级降级：移动端 info 接口 → 移动端页面渲染 → 把页面里的段落拼起来
- 抓到风控页（文案含「当前网络环境无法查看」）→ 该帖**没取到正文**，记为没抓到并重试

**「标题」有时就是全文**

- **微头条没有单独的正文** —— 列表接口给的标题**就是它全部的内容**，详情页也取不到更多。这类帖的**正文位置留空**
- 所以**「没有正文」不等于「没有内容」**：一条帖只要有标题就有内容，照常送进模型（见 01§2.2）
- 抓取侧只丢掉**标题不足 5 个字**的条目

**列表页噪声不入库**

- 形如「`博主名`：发布了一篇内容-今日头条」的条目**不是博主的帖子**，是列表页的占位条，直接丢掉

**视频帖**

- **不做内容解析**，正文位置写一个字面量标记 `[视频帖]`
- **三重识别**，任一命中即判定：info 接口返回**视频播放凭证**／页面 HTML 里出现**播放器标记**／正文是「**视频加载中**」
- 一经判定就写入**已完成记录**，**永不重抓**
- **标题照常存进库里，但两边都不喂给模型** —— 推送不参与判断，报告抽取时也跳过。理由不是「标题不是正文」，而是**博主在视频里到底怎么说的无从得知**，标题可能只是引流话术（不进抽取的口径见 01§2.2）
- ⚠️ **待定 #41**：现在的三重识别**漏判**。库里 575 条视频帖有 **573 条**的链接域名是 `toutiaoimg`，而域名**根本没用进识别** —— 漏掉的两条是真视频，另外还漏进了一批退化条目。要不要把域名加作第四条判据？

## 06§8 抓完必须校验

抓取完成后、在把数据交给任何下游之前，**必须**跑一次完整性校验。

校验分两类：

| 类别 | 含义 | 例子 |
|:---|:---|:---|
| **硬失败** | 客观数据损坏，必须处理 | 编号重复、关键字段为空、该抓到的区间没抓到 |
| **仅提示** | 可能完全正常 | 博主停更造成的日期空档、帖子数变少 |

- 「帖子数变少」永远是**仅提示**
- 校验**报出问题不等于抓取失败** —— 它只负责说清楚哪里可疑

## 06§9 怎么跑

```bash
# 全量：单博主报告，从固定日期往回抓到底
python -m scripts.pipeline.crawl_posts <博主名> --from 2026-01-01

# 补齐：只补这一位
python -m scripts.pipeline.crawl_posts <博主名> --align

# 补齐：全博主对比报告，库里所有博主各接一段
python -m scripts.pipeline.crawl_posts --align

# 只看不抓：打印对齐总览
python -m scripts.utils.crawl_status

# 抓完校验（必做）
python -m scripts.utils.verify_posts <博主名>
```

抓帖只有**一条命令**，正文在内部一起取 —— 没有分步调的第二道工序。

推送那一档的**增量**由推送流程内部调用，不是手动跑的命令。
