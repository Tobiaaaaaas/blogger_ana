# 03 · 新博主报告

**管什么**：给一位博主出一页纸成绩单 —— 他的历史预测准不准。
**不管什么**：抓取（见 06）；什么叫一条信号、有哪些字段、怎么定周期、怎么算分（见 01）；全博主对比（见 05）；回测（见 04）。

---

## 03§0 一图流

```
① 抓帖 + 行情数据补充
        │
        ▼
② 抽取 → 信号记录（A + B 组）
        │        └─ 报告链续填 C 组（事后验证）
        ▼
③ 统计打分
        │
        ▼
④ 输出报告 → reports/<博主名>_direction.md   ← 一页纸成绩单
```

- 产物是一份份**信号记录**：字段分 A / B / C 三组，**定义见 01§3**
- **A + B 是抽取的产物，推送链也产出同样的东西**；C 组是报告链独有的追加
- **②要花钱**（调模型），**③④不要钱**（纯算数）

---

## 03§1 抓帖 + 行情数据补充

这一步只干一件事：**把报告要用的两份原料弄齐** —— 帖子与行情。两份都不齐，后面全是错的。

### 1.1 抓帖：全量

单博主报告**一律全量** —— 无论这位博主是新入库的还是早就在库里。

| 项 | 值 |
|:---|:---|
| 抓谁 | 就这一位 |
| 抓法 | **全量**：从固定起始时间（如 `2026-01-01`）往回抓到底 |
| 起始时间 | **参数**，由调用方给（见 06§2） |
| 抓完必做 | **完整性校验**（见 06§8） |

抓帖的规范、三个时间、合并与去重、视频帖识别，**全部见 06**，本文不重抄。

### 1.2 行情数据补充

| 要什么 | 在哪 | 缺了会怎样 |
|:---|:---|:---|
| **行情日线** | `data/market/market_data.json`，7 只指数 | **直接崩** —— 交易日历和参考价都靠它 |
| **行情 30 分钟线** | `data/market/intraday/<指数>_30min.json` | 该指数**退回日线口径**，只打印提示、不中止 |
| **拐点表** | `knowledge/market_analysis.md` 的顶／底拐点列表 | 「抄底 / 逃顶」两行恒为 0 条 |

- 「补充」= 跑报告**之前**把这三样拉到最新（命令见 §5）
- ⚠️ **待定 #24**：缺 30 分钟数据时的**日线降级路径**自带两条与主路径不同的口径，且零测试覆盖
- 拐点表**人工维护**，表里没标的顶底，系统不知道

### 1.3 不参与抽取的帖

**只有两类：**

| 类型 | 为什么 |
|:---|:---|
| **2026-01-01 之前**发的帖 | 超出评价区间 |
| **视频帖** | 博主在视频里怎么说的无从得知，标题也不作数（识别见 06§7） |

**⚠️ 「没有正文」不是不抽取的理由。** 微头条根本没有单独的正文，**标题就是它全部的内容** —— 库里**一万多条**帖是这样的（此数会随抓取变化），其中不少标题里带着完整观点：

> 易平｜2026-09-07：`…上证大体的走势是：前半月继续在3900点至4000点之间来回震荡，下旬有望突破4000点展开新的上升行情。`

把「没有正文」当成过滤条件，这批帖会被整批丢掉。**引文可以来自标题，也可以来自正文；逐字核验时两个字段都要搜。**

## 03§2 抽取 → 信号记录

**产物是一条信号的完整记录，字段分三组，定义见 01§3。** 这一步两条链跑的是同一套规则：

| 组 | 谁填 | 推送链 | 报告链 |
|:---|:---|:---:|:---:|
| **A 读帖判断**（8 个） | 模型 | 填 | 填 |
| **B 帖子身份**（3 个） | 系统 | 填 | 填 |
| **C 事后验证**（7 个） | 系统 | 全为 `null` | 填 |

**A + B 两组两链逐字同构**；报告链在这一步**多填 C 组**。

### 2.1 A + B：读帖判断

#### 2.1.1 分批

| 项 | 值 |
|:---|:---|
| 一批最多 | **15 条帖** |
| 一批的字符预算 | **标题与正文**累计约 **3 万字**，超了就切 |
| 单帖文字最多取 | **4000 字**（标题与正文合计） |
| 顺序 | **从新到旧** —— 信号要回指自己出自第几条帖，顺序错了引文就会张冠李戴 |

#### 2.1.2 交代：每条帖都要有去向

模型读一批帖时，**每一条帖要么产出至少一行信号，要么声明「本帖没有可判读的表述」**。

**为什么必须有这一句**：没有它，「模型读完了、帖里确实没观点」和「模型压根没读这条帖」，在数据上长得一模一样 —— 漏看的帖从此查不出来。有了它，系统能逐帖核对，两种情况各记一条错：**帖没交代**（零行且未声明）／**帖既出行又声明没有**。

行这一级的核验是**逐字引文**（见 01§2.1、01§7.4）：引文对不上原文 → 丢掉这一行。

#### 2.1.3 强校验

模型给的每一行都要过下面的检查。**不过的一律丢掉整行**；只有「有唯一正确处理方式」的才自动改写。拒因只用于打印诊断，不写进数据。

| 检查 | 规则 | 不过怎么办 |
|:---|:---|:---|
| `d` | 必须是 `1` 或 `-1`。别的值（含文字「看多」）都不行 | 丢整行 |
| `idx` | 先在别名表里归一（上证综指／上证／综指 → 上证指数），再必须落在 01§5.1 的八个合法对象里 | 丢整行 |
| `cat` | 只能是 `scored`／`unscored` | 丢整行 |
| `spec` 语法 | 必须是 `today`／`tN`／`week`／`nweek`／`nweek_first`／`month`／`nmonth`／`long`／`d:YYYY-MM-DD` 之一 | 丢整行 |
| `spec` 语义 | `tN` 的 N 必须在 **1～30** 之间；`d:` 后面必须是**真实存在的历法日期** —— `d:2026-13-99` 这种「格式对、日期荒谬」的，只查语法拦不住，得另查一道 | 丢整行 |
| `spec`=`long` | 一律强制转成不计分，不论模型填的 `cat` 是什么 | 自动改写 |
| `horizon` × `spec` | 必须同档，合法搭配见 01§6.1 表 | 丢整行 |
| `s` | 不是 `1`／`2` | 归为 `1` |
| `summary` | 不能为空 | 丢整行 |
| `summary` | 超过 50 字 | 截断 |
| `目标点位` | 必须是个合理的数 | 丢该字段、留行。**⚠️ 该字段已决定删除，这一档可能再无适用对象，见待定 #39** |

**去重分两套**：

| 行 | 判定重复 |
|:---|:---|
| **计分行** | 同一天 + 同一周期档位 + 同一方向 + 同一指数 → 只留**当天最晚**的那条 |
| **不计分行** | 同一天 + 同一方向 + 同一指数 + **摘要逐字相同** |

#### 2.1.4 自查复核

抽完把**判断结果连同帖子原文**再喂给模型独立审一遍。四类裁决：

| 裁决 | 意思 |
|:---|:---|
| **保留** | 判得对，不动 |
| **修正** | 某个字段判错了，给出正确值（新值仍要过全部校验，过不了就退回原值） |
| **剔除** | 这条根本不该存在 |
| **补漏** | 漏了一条，补上 |

- 没被审到的行**一律保留** —— 复核的沉默不等于否定
- 整批复核失败（超时、接口挂）→ **保留这一批的全部原信号**
- ⚠️ **待定 #33**：记「交代」时重试第二发若失败，会把第一发已判好的有效行一起丢掉，与上一条原则相反

#### 2.1.5 多次运行取共识

| 项 | 值 |
|:---|:---|
| **默认跑几次** | **1 次** |
| **投票门槛** | `N ÷ 2 + 1`（向下取整）：2 次→2 票，3 次→2 票，4 次→3 票 |
| **谁投票** | **只有计分行**；不计分行逐条并入，最后统一去重 |
| **摘要** | 取出现次数最多的那个 |
| **目标点位** | 多数一致才保留（平局时偏向不保留）。**⚠️ 本字段已决定删除，见待定 #39** |

**哪两行算同一行**：**（日期，方向，对象，周期）四样一致**就是同一行 —— 去重和投票都用这把钥匙，与引文怎么截无关。

> 引文不参与比对：它是**证据**，不是身份。两次运行的引文边界差半句、或两行引同一句原文，都不影响「这四样一致就是同一行」。

#### 2.1.6 落盘

`data/direction_signals/<博主名>.json`。

⚠️ **待定 #36**：库里现有文件**只存了 A 组**，B 组（`blogger` / `post_id` / `pub`）与 C 组都没有。要不要按本文的结构**全量重跑一次**补齐？

### 2.2 C 组：事后验证（只有报告链）

把 A + B 接到行情上，补出「他说的这条到底对不对」。

```
pub                →  ref     参考价        发帖那一刻的现价
pub                →  ref_bar 取价依据      取自哪根 30 分钟 K 线
spec + pub         →  ep      验证终点      周期档位落到哪一天
ep                 →  epc     终点价        那天的收盘
ref + epc + d      →  ret     涨跌幅
ret + d            →  score   得分
score + 边界情形    →  note    状态
```

- 取价口径见 **01§9**，得分公式与六种状态见 **01§10**，周期档位表见 **01§6.1**。本步**不新增规则**
- **参考价由发帖时刻定，终点价由预测周期定** —— 两个价凑成一对，缺任一个 → `note` 判「待验证」
- `note` 为 `null` = **这条记录不归报告链管**（见 01§11.2）
- ⚠️ **待定 #37**：`note` 现在把「状态」和「日内」混在同一个键里，且计分行的 `note` 是空串而非 `计分`
- ⚠️ **待定 #38**：`ref_bar`（取价依据）是新增字段，值取人类可读串（`09-01 10:30 开盘`）还是拆成结构化几项

## 03§3 统计打分

**不调模型，纯算术。** 把上一步逐条算出的 `score` **汇总成指标**。

报告链特有的两条口径：

**① 指标只认上证指数。** 汇总指标、分类表、月度表、时间分布、榜单名次**全部只统计上证指数**的信号。

其余指数的计分行**仍留在逐条表里**（逐条标了目标指数），只是不进指标。

> 后果：报告里会出现**两个都叫「计分」的数字** —— 头部「信号总数」那一行的是**全部指数**的，「计分样本」是**只算上证**的。两者不等是正常的。**⚠️ 见待定 #27、#28**

**② 抄底 / 逃顶。** 拐点表里每个顶或底，取**拐点当天 + 前一个交易日**这 2 个交易日作为窗口：

- 落在**底部**拐点窗口内 → 抄底
- 落在**顶部**拐点窗口内 → 逃顶

窗口只有 2 个交易日，所以这两组信号数通常很小，**平均分波动极大，只能当线索看**。

## 03§4 输出报告

### 4.0 一页纸的八节

```
① 头部        评估时间 / 帖子总数 / 信号总数 / 评价口径
② 资格警告    （只有不满足资格时才出现）
③ 汇总指标
④ 四张分类表  按指数 / 按周期 / 按多空 / 按抄底逃顶
⑤ 月度表现
⑥ 时间分布与集中度
⑦ 逐条汇总表
⑧ 观察要点
```

**不满足资格的博主只出 ①⑥⑦ 三节**，中间全跳过，并在开头写明卡在哪一条。

### 4.1 头部四行

| 行 | 含义 |
|:---|:---|
| **评估时间** | 行情数据的最新交易日（**不是今天**） |
| **帖子总数** | 这位博主的帖子总数，**含 2026 年之前** |
| **信号总数** | 五类分列：计分 + 不计分 + 待验证 + 无效-过时 + 报错 |
| **评价口径** | 只有存在「上证以外」的计分信号时才出现 |

### 4.2 汇总指标

| 指标 | 衡量什么 |
|:---|:---|
| **计分样本** | 进入评价集的行数（**只算上证**） |
| **另有** | 不计分 / 无效-过时 / 待验证 / 报错 各几条（**是全部指数**的） |
| **方向正确 / 正确率** | 得分 > 0 的条数 ÷（总数 − 平局数）。**得分恰好 0 算「平」，从分子分母都拿掉** |
| **strong 正确 / moderate 正确** | 按强度切开的两组各自的正确率 |
| **平均分** | 核心指标：所有计分信号得分的平均值（单位就是 %） |
| **波动率** | 单条信号得分的离散程度；不足 2 条记 0 |
| **夏普** | 平均分 ÷ 波动率。波动率为 0 或不足 2 条显示 `—` |
| **最高分 / 最低分** | 单条信号的最好与最差 |
| **看多平均分 / 看空平均分** | 按方向切开的两组各自平均 |
| **抄底平均分 / 逃顶平均分** | 落在拐点窗口内的信号的平均 |

### 4.3 四张分类表

每张表列相同：**分类 / 信号数 / 平均分 / 正确率 / 波动率 / 夏普**。不足 2 条的组，波动率与夏普写 `—`；**空组直接不出现**。

| 表 | 怎么分 |
|:---|:---|
| **按预测指数** | 按目标指数分组 |
| **按预测周期** | 超短期（发帖日 → 验证终点隔 0–1 个交易日）/ 波段（隔 ≥2 个交易日） |
| **按多空** | 看多 / 看空，下面挂两行强度细分 |
| **按抄底逃顶** | 抄底 / 逃顶 |

### 4.4 月度表现

按月分组，列同分类表。用途是看**他的成绩是不是集中在某一个月**。

### 4.5 时间分布与集中度

**所有博主都出**（不管够不够资格）。先说覆盖区间与单月最高占比，再按阈值给警告：

| 条件 | 警告 |
|:---|:---|
| 有信号的月份 **< 3 个** | ⚠️ 覆盖不足 3 个月，样本期过短 |
| 单月占比 **≥ 50%** | ⚠️ 信号高度集中于单月 |
| 单月占比 **33%–49%** | 提示：存在轻度集中 |
| 相邻两月**隔 ≥ 4 个月** | ⚠️ 严重覆盖缺口 |
| 相邻两月**隔 2–3 个月** | 提示：缺 N 个月 |
| 都没有 | 分布均匀，无警告 |

### 4.6 逐条汇总表

**每一条信号一行**，包括不计分、待验证、报错、以及上证以外的行。十三列：

`# / 日期 / 内容 / 方向 / 强度 / 预测周期 / 目标指数 / 参考价 / 终点日 / 终点收盘 / return / 分 / 备注`

- 日期只到**月-日**（不带年份）
- 方向是箭头（↑ / ↓），强度写 `str`（强）/ `mod`（中）
- 没算出来的格子写 `-`
- **备注列的六种取值**：`—` / `日内` / `不计分` / `待验证` / `无效-过时` / `报错`

### 4.7 观察要点

把前面几张表里最扎眼的挑成几条：正确率结论、多空对比、抄底逃顶、最强/最弱的周期与指数、最大单条命中与失误、四类单列信号的条数。

**正确率的判词只有两档**：**≥ 55%** → 「具备统计优势」；否则 → 「接近抛硬币水平，没有统计优势」。

## 03§5 怎么跑

```bash
# ① 抓帖：全量（见 06§9）
python -m scripts.pipeline.crawl_posts <博主名> --from 2026-01-01
python -m scripts.utils.verify_posts <博主名>

# ① 行情数据补充
python scripts/utils/fetch_market_data.py        # 日线（与旧文件合并写回）
python scripts/utils/fetch_market_intraday.py    # 30 分钟线（增量合并）

# ② 抽取（调模型，要花钱）
python scripts/pipeline/extract_signals_direction.py <博主名>
#   --runs 1            跑几次（默认就是 1）
#   --limit N           小范围试跑：只跑最新的 N 条帖
#   --since YYYY-MM-DD  只处理这个日期之后的帖
#   --no-verify         跳过自查复核
#   --dry-run           只看会切多少批、不调模型
#   → data/direction_signals/<博主名>.json

# ③④ 统计打分 + 出一页纸（纯算数，不花钱）
python scripts/eval/run_direction.py <博主名>
#   → reports/<博主名>_direction.md
```

- ⚠️ **待定 #40**：`crawl_posts`（抓帖那一条命令）**尚未实现**。库里现在跑的是抓列表 + 另起一道工序补正文，与 06§7「同一条命令内部完成」不符
- 抽取需要模型密钥（`DEEPSEEK_API_KEY`），缺失就报错退出；**统计打分不需要密钥**
- 打分前会**自动检查 30 分钟线完整性**（7 只指数、覆盖全部交易日、每个交易日 8 根 K 线）。**只告警，不阻断**
