# 01 · 抓取

**管什么**：备料两件事 —— 把博主发的帖子搬进 `data/posts/`（§0–§9）、把行情搬进 `data/market/`（§10），并让全库数据保持齐。

**不管什么**：怎么从帖里读出观点（见 02）／拿这批帖做什么（见 03–06）。

---

## 01§0 边界

**输入**：博主的任意一条帖子的链接 ＋ 一个起始时间（参数名 `begin_date`）。链接用来定位博主本人；起始时间决定往回翻到哪。

**抓取永远是区间式的** —— 抓 `[起始时间, 至今]` 这一段。抓多少就解析多少，抓取与解析是同一个区间。

| 谁调 | 抓谁 | 起始时间从哪来 |
|:---|:---|:---|
| **单博主报告**（03）· 新博主 | 那一位 | 固定日期（如 `2026-01-01`） —— 全量 |
| **单博主报告**（03）· 旧博主 | 那一位 | 该博主 `scrape_time` 所在那一日的零点 —— 增量 |
| **推送**（06）· 每一档 | 池子里每位博主 | 同上 —— 增量 |
| **推送**（06）· 初始化 | 池子里每位博主 | 回看窗口起点 —— 只抓窗口内那几天（见 06§4） |
| **补齐**（手动） | 全库每一位 | 同上 —— 增量 |

**起始时间一律由调用环节算好传进来。** 抓取自己不看 `scrape_time`、不判断该抓多少 —— 决定「这次是全量还是增量、从哪儿增量」是调用环节的事。

起始时间是硬边界，但它在这里判一次就够。早于它的帖一律不入库（§4）；这一层做干净了，下游（03／06）拿到的主文件天然都在区间内，不必再筛一道。

**抓取从不自己发生**：由报告流程调、推送流程内部调、补齐手动跑。没有常驻的定时抓取。

## 01§1 一图流

```
博主链接 + 起始时间
   │
   ▼
① 翻列表（每页全收），逐条过四道关 ── 非本人 / 时间不实 / 列表页噪声 / 置顶帖 ──► 丢掉
   │
   ▼
② 收完统一过一遍：早于起始时间的帖丢掉
   │
   ▼
③ 逐帖进详情页取全文（视频帖不入库）
   │
   ▼
④ 按 post_id 去重，并入主文件 ── 旧帖原样保留，永不覆盖
   │
   ▼
⑤ 把这次抓取的时刻写进主文件
```

一次抓取只做三件事：抓、并、记。它不判断、不打分、不推送、也不管下次该从哪续。

**丢掉的东西一律不留痕**：不入库、不计帖数、不写占位标记。视频帖与置顶帖只记进已完成记录，下轮不再为它们取一次详情页。

## 01§2 三个时间

| 时间 | 是什么 |
|:---|:---|
| **起始时间** | 参数 `begin_date`：往回翻到哪。由调用环节算好传进来，抓取不自己判断 |
| **抓取截止** | 字段 `scrape_time`：这次抓取发生的时刻，写进主文件 |
| **重叠余量** | 规则：续抓时退到抓取截止所在那一日的零点（§5） |

- 起始时间既决定翻页什么时候停，也决定文件里留下什么（§4）
- 抓取截止是抓取那一刻的挂钟时间（形如 `2026-09-08 10:14:40`），不是最后一条帖的发布时间
- 抓取截止是调用环节算下次起点的依据（§5），也是判断谁的数据不齐的依据（§6）
- 重叠部分靠 `post_id` 去重，多抓没有副作用

## 01§3 入库四道关

列表翻回来的每一条，四关全过才入库。任何一关不过 → 丢掉，不入库、不计入帖数。

### 3.1 是本人发的

| 情形 | 处置 |
|:---|:---|
| 明确是本人在发 | 收 |
| 明确是他人 | 拒 |
| 认不出是谁 | 拒 |

**认不出身份的一律不收，不用任何旁证去补。**

### 3.2 发帖时间是真实的

**只认 `publish_time`，退而取 `create_time`。两个都没有 → 时间视为未知，这条丢掉。**

**绝不用 `behot_time`** —— 它是 feed 的热度游标，约等于抓取时刻。

> 上面三个是头条接口的字段名，落库时统一存成 `pub`（§7）。

### 3.3 不是列表页噪声

形如「`博主名`：发布了一篇内容-今日头条」的条目是列表页占位条，不是博主的帖子，丢掉。

### 3.4 不是置顶帖

**置顶帖按列表条目上的置顶标记（`is_stick`）识别，丢掉不入库。**

置顶帖是博主挂在主页顶上的那一条，可能有好几条，日期可以是任何一天 —— 它是一条真帖，但它是公告位，不在时间线上：

- 它会插在列表最前面，把「按时间倒序翻页」这件事搅乱
- 它会让 `time_range.earliest` 变成几个月前，看着像中段漏抓
- 下游按时间做的任何判断，都会被它带偏

**与视频帖同样处置**：判定即丢，只记进已完成记录，永不重抓；下游看不见它。

## 01§4 抓取＝合并，永不覆盖

**翻页时每页全收，收完再统一过一遍起始时间。**

- **翻页全收**：一页 12 条整页收下，不逐条判边界；停不停只看「本页最新的一条是否已早于起始时间」（§2）
- **收完统一过滤**：把这一轮收下来的帖整批过一遍，`pub` 早于起始时间的丢掉
- **过滤在取详情页之前做** —— 反正要丢，就不必为它们再取一次全文
- 因此边界那一页上早于起始时间的几条帖会一起丢掉 —— 这是有意的，不是漏洞

- 过滤后的帖按 `post_id` 去重后并入主文件；原有的帖原样保留
- 过滤只作用于这一轮收下来的帖，不作用于文件里已有的帖 —— 已经把历史带进来的博主，不会因为换了起始时间就被削掉
- 主文件的帖子数只增不减（除非博主自己删帖）
- 因此不存在「强制覆盖」这个开关
- 抓取幂等：同一位博主、同一个区间抓两次，结果完全一样

> 传一个很短的起始时间（如 `2026-09-01`）不会删掉历史；它只决定这一轮收进来的有哪些。

## 01§5 续抓

```
新起始时间 = 该博主 scrape_time 所在那一日的零点
```

举例：`scrape_time` 是 `2026-09-08 10:14:40` → 新起始时间取 `2026-09-08 00:00`。

- **这条规则由调用环节执行** —— 它读 `scrape_time`、算好起点、再调抓取。抓取自己不读这个字段
- 没有抓取记录的博主（新博主），退回用固定的起始时间
- 每位博主各记各的，互不影响。不存在一份全局的「抓到哪了」
- **抓取与解析共用这一个起点**：这一轮抓回来什么区间，就解析什么区间

## 01§6 对齐与补全

**对齐** = 把所有人的 `scrape_time` 放在一起，比距现在多久。有一个只读的查看命令打印总览，它不抓取、不修改任何东西。

```
博主              起始         抓取截止            帖数   距今
张大坤            2026-01-01   2026-09-08 10:14   2191   4 天
白猫财眼          2026-01-01   2026-09-10 18:40   1847   2 天
稀豹              2026-01-01   2026-08-28 09:12   1582   15 天
```

- 总览只显示时间差，不划落后线
- **补齐是手动动作，不自动触发**：把落后的博主从各自的 `scrape_time` 补到运行当日
- 补齐的起点就是续抓的起点（§5）。补齐环节负责算这个起点，算好再逐个调抓取 —— 抓取自己不看 `scrape_time`
- 补齐能点名补，也能一把扫全部（两者是同一个动作，只差有没有传博主）
- 补齐每补完一位就校验一次（§9） —— 用这位自己算出的起点调校验。起点是补齐算的，只有它知道该传什么；一把跑完直接报出「谁补齐了、谁硬失败」

## 01§7 主文件

主文件记这些：

- 文件名永远是 `<博主名>.json`，不含时间；`data/posts/` 下只放这个形态的文件

| 顶层字段 | 是什么 |
|:---|:---|
| `user_info` | `{name, user_id, description}` —— 博主本人 |
| `source_url` | 抓取入口地址 |
| `scrape_time` | 抓取截止，形如 `2026-09-08 10:14:40` |
| `stop_reason` | 翻页为什么停，只有四种取值：`since`（碰到起始时间了）／`no_more`（feed 真的翻到底了）／`capped`（翻到页数上限或条数收够，我们自己截断的）／`error`（接口异常中断） |
| `time_range` | `{earliest, latest}` —— 帖子的发布时间跨度，是内容的属性 |
| `posts` | 帖子数组 |

| 每条帖的字段 | 是什么 |
|:---|:---|
| `post_id` | 头条的帖子编号，去重与合并的唯一钥匙 |
| `title` | 帖子标题；只有文章类帖有（见 §8） |
| `content` | 帖子的文字全文，每条都有 |
| `pub` | 发帖时刻，形如 `2026-08-28 15:37`，精确到分钟 |
| `url` | 帖子链接 |
| `digg_count` / `comment_count` / `read_count` | 点赞数 / 评论数 / 阅读数 |

样例（字段已截断）：

```json
{
  "user_info": {"name": "张大坤", "user_id": "1308872855797657", "description": "天下大势，浩浩汤汤…"},
  "source_url": "https://www.toutiao.com/c/user/token/Ciz3Ytq…",
  "scrape_time": "2026-09-08 10:14:40",
  "stop_reason": "since",
  "time_range": {"earliest": "2025-12-31", "latest": "2026-09-08"},
  "posts": [
    {
      "post_id": "1874751803693056",
      "content": "缩量横盘别慌，九月行情可期！\n\n收盘啦！今天指数全天窄幅震荡，最终微跌0.11%…",
      "pub": "2026-08-28 15:37",
      "url": "https://m.toutiao.com/w/1874751803693056/",
      "digg_count": 12, "comment_count": 0, "read_count": 1703
    }
  ]
}
```

## 01§8 标题、正文与视频帖

**两个文字字段各管各的，在一条命令内部一次拿齐，不分步。**

| 字段 | 是什么 | 从哪来 |
|:---|:---|:---|
| `title` | 帖子标题 | 列表接口，翻列表时就有；文章类帖有，微头条没有 |
| `content` | 帖子全文 | 详情页，逐帖再取一次 |

- `content` 必填：取不到详情页时，退回用列表给的文字
- `title` 可选：微头条没有标题，此字段不出现
- **标题文字不在正文里**：全库有标题的帖中，85% 的标题文字在正文里根本找不到。所以 `title` 丢了就是永久丢了

**微头条**（链接形如 `m.toutiao.com/w/…`）不走详情页 —— 列表给的文字就是它的全文，直接落进 `content`。只花一次便宜的 info 接口请求做视频帖判定。

**文章类帖要逐级降级取详情页**：移动端 info 接口 → 移动端页面渲染 → 把页面里的段落拼起来。三条都不通（风控页，文案含「当前网络环境无法查看」）→ 这条帖算没抓到，重试。

**视频帖：不入库**

- **四条判据，任一命中即判定**：info 接口返回视频播放凭证／页面 HTML 里出现播放器标记／文字是「视频加载中」／链接域名是 `toutiaoimg`
- 一经判定直接丢掉，与置顶帖同样处置（§3.4） —— 不写进主文件、不计入帖数、`content` 不留占位标记
- 记进已完成记录，**永不重抓**
- **下游看不见视频帖**：它在入库前就被扔了，报告（03）与推送（06）都不必再判一次

## 01§9 抓完必须校验

抓取完成后、在把数据交给任何下游之前，**必须**跑一次完整性校验。

| 类别 | 含义 | 例子 |
|:---|:---|:---|
| **硬失败** | 该抓到的区间没抓全 | `post_id` 重复、关键字段为空、一条帖及其发帖时间都没有、翻页被上限截断、接口异常中断 |
| **仅提示** | 可能完全正常 | 博主停更造成的日期空档、帖子数变少、没碰到起始时间就翻完了 |

「该抓到的区间没抓到」看停止原因本身（§4）：

| `stop_reason` | 结论 |
|:---|:---|
| `since` | 覆盖到位 —— 它只在「本页最新的一条都已早于起始时间」时才盖，而页面按时间倒序、首尾相接，所以盖了 `since` 就等于「≥ 起始时间的帖一条不落」 |
| `no_more` | 仅提示 —— feed 真的翻到底了。起始时间之前 feed 里确实没有更早的帖 |
| `capped` | 硬失败 —— 翻页被自己设的上限截断。还拿得到更早的帖，只是没拿，调高上限后重抓 |
| `error` | 硬失败 —— 接口重试三次仍失败。这一轮的区间没收全，重抓一次 |
| 文件里最早的一条正好落在起始时间当天 | 覆盖到位 —— 本身就是铁证，不必再看停止原因 |

- 「帖子数变少」永远是仅提示
- 校验报出问题不等于抓取失败 —— 它只负责说清楚哪里可疑

## 01§10 行情备料

抓帖是第一件备料，这是第二件。两组行情搬进 `data/market/`。

### 10.1 两组数据各干什么用

| 哪一组 | 落在哪 | 干什么用 |
|:---|:---|:---|
| **日线** | `data/market/market_data.json` | 算交易日历（03§3.4） |
| **30 分钟线** | `data/market/intraday/<指数>_30min.json` | 算参考价与终点价（03§3） |

**七个主指数**：上证指数／沪深300／创业板指／上证50／中证500／中证1000／科创50。双创不单列，由创业板指与科创50 各半合成。

### 10.2 从哪来

**每个源依次降级**，一个不通就换下一个；每个源各自重试，间隔逐次拉长。

| 哪一组 | 降级顺序 | 为什么 |
|:---|:---|:---|
| **日线** | 东财 → 新浪 | 东财能按区间取；新浪只给全量，取回来自己截 |
| **30 分钟线** | 新浪 | 东财对分钟线按 TLS 指纹拦截 |

**源是外部事实，会变**（2026-09-13 东财整片不通），所以降级不是备选，是常态。

### 10.3 交易日历怎么定

**交易日历 = 官方日历**（`data/market/trade_cal.json`）。休市安排是交易所事先公布的，所以这份日历含未来（现覆盖到 2026-12-31）。全库共用这一份，口径归 03§3.4。

> **日历与行情是两件事，不许互相倒推。**
>
> | | 说的是 | 谁认它 |
> |:---|:---|:---|
> | **日历** | 哪天开市 | 数日子 —— 验证终点、交易日跨度 |
> | **行情** | 数据到哪天 | 算价 —— 参考价、终点价 |

日历取不到 → 硬失败。日历缺了整条链的日子都不可信，不许退回「只跳周末」凑合 —— 报错并指路 `python -m blogger.market`。

### 10.4 抓完必须核对

**该到哪天** —— 两条链口径不同：

| 谁在核 | 该到 |
|:---|:---|
| **报告链** | 交易日、且已过 15:00 → 运行当日；其余 → 运行当日或之前最近的一个交易日 |
| **推送链**（06§5.3） | 本档时刻：要覆盖到结束时刻不晚于本档时刻的最后一根 30 分钟线；当天一根都还没收出来（`09:30` 档）→ 上一交易日收盘 |

**推送链只比 30 分钟线这一样** —— 卡上不显示行情，日线对推送没有用处（06§5.3）。

**比两样**，逐项对上才算齐：

| 比什么 | 对着什么 |
|:---|:---|
| 每个指数的日线末根 | 该到哪天 |
| 每个指数的 30 分钟线末根 | 该到哪天 |

**不达标 → 硬失败**：差哪几个交易日逐个列名，非零退出码。

> **绝不「抓不到就当成功」。**

**日历取不到或已过期 → 硬失败**（10.3），不退回只跳周末。

## 01§11 怎么跑

```bash
# 抓取 —— 给链接、给起点。抓什么区间，下游就解析什么区间
python -m blogger.scrape <帖子链接> --begin_date 2026-01-01

# 对齐总览 —— 只读，不联网、不写盘
python -m blogger.scrape.align

# 补齐（手动）—— 每位从各自的 scrape_time 补到运行当日，补完逐个校验
python -m blogger.scrape.fill              # 全库
python -m blogger.scrape.fill <博主名>      # 只补这一位

# 校验（单个）—— 起始时间要与抓取时同一个
python -m blogger.scrape.verify <博主名> --begin_date 2026-01-01
```

抓取命令只有 `begin_date` 一个参数 —— 所有「该从哪续」的判断都在补齐环节，抓取本身不碰。

抓帖只有一条命令，标题与正文在内部一起取 —— 没有分步调的第二道工序。

推送那一档的增量由推送流程内部调用，不是手动跑的命令。

**备料行情**（§10）：

```bash
# 补到今天并核对 —— 差一天就非零退出，不静默通过
python -m blogger.market

# 只看不抓：打印各指数末根日期、距该到哪天还差几天。不联网、不写盘
python -m blogger.market --check
```

报告流程（03）内部会自己补一次行情，手动跑这个命令是为了单独核对。

## 01§12 可调参数

**本文每一条判据都不写死** —— 全部从仓库根的 `config.json` 的 `scrape` 与 `market` 两节读。改参数只改那一份文件，不碰代码。

| 键 | 管什么 | 本文哪一节 | 现值 |
|:---|:---|:---|:---|
| `scrape.begin_date` | 新博主入库的默认起始时间 | §2 | `2026-01-01` |
| `scrape.max_pages` | 翻页上限 | §3 | 400 |
| `scrape.target_posts` | 累计到这么多条就停 | §3 | 5000 |
| `scrape.empty_page_limit` | 连续这么多页没新帖就停 | §3 | 5 |
