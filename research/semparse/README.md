# semparse —— 跑两遍的那把尺子

**管什么**：把全库判两遍，量出「同一条帖、同一份行情、同一份规则，两次判断对不上」的帖占多少。
**不管什么**：不是产品代码。它不改 `blogger/` 一个字、不抓帖、不写判断缓存、不动调度。

**量的就是 02§10.3 那条规矩** —— 同一条帖跑 `parse.runs` 遍、按帖比三元组，对不上的才交模型定夺。两遍之间唯一的变量是模型自己，所以量出来的不一致率是这套读法的**抖动下限**：它进不了模型的错，只量模型自己跟自己不一致。

## 怎么跑

| 命令 | 干什么 |
|:---|:---|
| `python -m research.semparse.jitter run --out _pass1` | 全库判一遍，落到 `_pass1.json` |
| `python -m research.semparse.jitter run --out _pass2` | 再判一遍 |
| `python -m research.semparse.jitter cmp _pass1.json _pass2.json` | 比对，按争议分组报数 |
| `python -m research.semparse.jitter draft _pass1.json _pass2.json --out <路径>` | 出判例草稿，人填裁定 |

取帖与分批**照抄** `blogger.report.flow.judge_posts` —— 先按 `pub` 从新到旧排，再筛掉取不到行情注记的，再切批。不照抄的话，「分批不同」会混进差异里，量出来的就不是模型的抖动。

**没判到的帖不算差异** —— 失败批里的帖、取不到注记的帖，两遍里都不出现；`cmp` 只比两遍都在的帖，并把剔掉的条数报出来。

## 分组

按「规则问的是哪个问题」分，不按博主：

| 组 | 对不上的是 | 归哪一节 |
|:---|:---|:---|
| 甲 | 一遍产、另一遍一条不产 | 什么算一条观点信号（§6 与 §3.1） |
| 乙 | 帖内条数不等 | 一条帖能出几条（§7） |
| 丙1 | 周期档位 | 周期表与没给周期时（§4） |
| 丙2 | 指数 | 映射与「跟着这一处表述走」（§5） |
| 丙3 | 方向 | 方向（§3） |
| 丁 | 三元组相同、只差引文取哪一句 | 引文佐证（§9） |

**丁不算不一致。** 三元组逐项一样就是判断没有分歧 —— 引文取的是帖里哪一段，两遍截在不同处而已。`cmp` 把它单列在表末，供查。

## 基线

旧链条式流程在**三位博主、1834 帖**上量出 **343 条（18.7%）**，出处 [判例/第二轮.md](../../docs/判例/第二轮.md)；含丁 108 条，按同一口径扣除后是 **235 条（12.8%）** —— 与新的数对照时用的是后者。

**这条基线只作参考，不作验收**：语料是三位博主、规则是上一代（指纹 `601a685c4730d9b9`，已随换代作废）。要一个干净的对照，得在同一批帖、同一版规则上再量一遍。

**这个数不是「准不准」，是「稳不稳」。** 两遍是同一个函数调两次，不一致全部来自服务端。
