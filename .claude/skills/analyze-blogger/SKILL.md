# 博主分析 Skill（方向预测评估）

## 权威与改动流程

> **本文件是判层与周期口径的主档**，代码是它的实现、**须向本文件对齐**（2026-09-10 起；此前一轮以代码为准的反向对齐已结束）。
>
> **改动流程**：先改本文件 → 再据此改代码 → 跑 `opinion/tests/` → 同步 Windows。**不要**反过来"先看代码怎么写、再抄进文档"。
>
> **适用范围（别用过头）**：只覆盖**判层与周期口径**（哪句话算明确方向、`spec` 怎么编码、教义锚句）。**研究侧参数**——波段委员会名单、滞回阈值 / Q 值 / 决策窗口 `w`——仍**以 `research/config.py` 为准**。
>
> **唯一例外**：字段与 `spec` 的**合法域**（`idx` / `spec` / `cat` 取值域、`horizon` 词表）以 `opinion/schema.py` 为准——取值域抄进文档必然漂移。

**判层文本落在三处**，改本文件后须逐处同步：

| # | 落点 | 同步性质 |
|:--|:--|:--|
| ① | `opinion/prompts.py`：教义块 `DOCTRINE_NO_DIRECTION`、复核块 `DOCTRINE_REVIEW` | **真单源**——经 `.replace` 插值进 4 个 prompt（推送标注正文 / 报告提取后缀 / 推送复核 / 报告复核），改一处即四处同变 |
| ② | `opinion/prompts.py` 与 `scripts/pipeline/extract_signals_direction.py`：**prompt 正文本体**（周期编码细则、指数映射、`target` 口径） | **两份手写拷贝**（`ANNOTATION_SYSTEM_PROMPT` ↔ `_REPORT_EXTRACT_SUFFIX`）——改一处**不同步**另一处，**必须两处一起改** |
| ③ | `opinion/verify.py`：复核 prompt 骨架 | 教义条由 ① 插值进来，**骨架本身**单独同步 |

**缓存后果**：改 ② 中落在 `prompts.py` 那一半的任一字 → `annotation_fp_input()` 指纹变 → 推送侧 `rows_cache` **全量作废、下一档整窗重抽**，须避开推送档同步；只改 `DOCTRINE_REVIEW`（**不在**指纹域内）或只改本文档 → **零缓存影响**。

本文件 §1~§8 与附录是这套规则的**可读主档**——但 §1 是教义的**摘要、不逐条穷举**，判层的**完整**文本始终是 ① 的教义块（09-09 教义全文亦见 §1~§3）。回归：`python3 opinion/tests/test_prompt_doctrine.py`。

## 总览

**一句话定位**：全量读取博主帖子，逐条提取其中"对大盘未来的方向预测"（信号），用市场实际走势验证方向对错，并按 `方向 × 实际涨跌幅` 打分（score = direction × return × 100），最后汇总成个体报告与全博主横向榜单。

## 两条日常用法

**共用同一份教义与同一套字段域**（裁决锚句单源在 ① 的教义块；**周期编码等 prompt 正文是 ② 的两份手写拷贝**）：

- **逐人评估（出报告）**：本文件的重点——把单个博主 2026 年以来的帖子逐条判读、验证、打分，产出个体报告与全博主横向榜单（下文五环节表即此线）。
- **定时推送（每天出卡）**：每天定时扫 `briefing/` 名单里博主最近几天的帖子，把其中最新、仍有效的方向观点按预测周期分成两类——**超短**（今天/明天）与**波段**（近日/本周/下周/更长/**未提**）——各汇成一张卡片推到飞书群。窗口按交易日计：超短 = 决策日前 1 个交易日、波段 = 前 5 个交易日；**非交易日只推波段**。判读规则共用同一份教义，但两条线**选行口径不同**（报告按 `pub` 逐条取行；推送按 `quote_ts` 主序 + `HORIZON_RANK` 决胜，每博主每板一行），**周期编码细则又是两份拷贝**——所以同一句话在两条线上**不保证**落到同一行/同一档；**发现分歧以本文件为准，并回改 ② 的两处拷贝**。

（推送的名单、时刻、飞书与卡片格式属 `briefing/`，见 `briefing/README.md`；本文件只写判读与评估。）

## 五环节流水线（逐人评估）

| 环节 | 做什么 | 产物 |
|:---|:---|:---|
| ① 提取 | DeepSeek 读帖子，只拎出"明确对未来的方向预测"（方向+周期）；复盘/纯形态/模糊话术不提取 | 信号 `{方向、强弱、指数、周期 spec、摘要、类别 cat}` |
| ② 定参考价 | 发布时刻"当前最新价"：盘中=所处 30 分 bar 开盘价；盘前/午休/盘后/周末=上一根 bar 收盘价 | 参考价 |
| ③ 定验证终点 | 按博主说的周期精确锁死一个验证日——说"明天"就验证明天，不扩展不缩短 | 验证终点 ep |
| ④ 打分 | score = 方向 × 实际涨跌幅 × 100，方向对赚、错亏 | 每条信号一分 |
| ⑤ 汇总/排名 | 个体报告（汇总+四分类表+逐条表）+ 全博主横向榜单 | `reports/*.md` |

## 核心术语

| 术语 | 含义 |
|:---|:---|
| 信号 | 一条"对未来的明确方向预测"（方向+周期） |
| `spec` | 预测周期编码（`today`/`t1`/`t2`/…/`week`/`month`/`long` 等，见 §3）；旧抽取产过 `d:日期`，引擎仍解析、**新抽取不再产** |
| `cat` | 参与状态：`scored` 计分 / `unscored` 不计分（`spec=long` 恒不计分） |
| 参考价 | 发布时刻"当前最新价"，打分的基准价（§4） |
| 验证终点 | 按预测周期锁定的验证日（§3） |
| 单列 | 不计入分数的信号（unscored/待验证/无效-过时/报错），在汇总中单独列出 |
| 抄底/逃顶平均分 | 底部/顶部拐点当天+前一天窗口内计分信号的平均分（§6） |

**关键分类**（决定哪些进分数）：有方向+有明确周期 → 计分；周期过长 / 目标点位无时间承诺（"看到 4200"没说到哪天）→ `long`/`unscored` 不计分；无周期但有方向 → `t5`（验证终点 = 信号日之后第 5 个交易日，正常计分并参与多空/两档）；数据覆盖不到 / 过时 / 非交易日发布的"今天" → 单列不计分。

**三条铁律**：只验证不预测 · 严格按预测周期 · 诚实打分。

## 前置条件

**数据就绪 4 要素**：
- `data/posts/<博主名>.json`：已爬取全部帖子且 `content` 含完整正文。**判读只需 `content`**；`title` 非必需（实测 162 个博主文件里 **63 个**通篇无 title）——仅列表接口博主经 `merge_bodies_to_posts.py` 回填正文时才补写 title，缺 title 时 `opinion/text.resolve_post` 兜底（标题→正文首句/整段，微帖只显一次）。正文缺失时用 `scripts/utils/fetch_bodies_shard.py` 抓正文 + `scripts/utils/merge_bodies_to_posts.py` 回填（旧分片归档 `archive/<日期>-bodies-merged/`）
- `data/market/market_data.json`：7 指数日线，已更新到最新交易日（`python scripts/utils/fetch_market_data.py --start 20240601`）
- `data/market/intraday/<指数名>_30min.json`：7 指数 30 分钟线——所有信号的参考价与终点价来源（`python scripts/utils/fetch_market_intraday.py`）
- **DeepSeek API Key**：`export DEEPSEEK_API_KEY="sk-..."`，只经环境变量传入（**绝不写入文件、绝不提交 GitHub**）；依赖 `pip install openai`

**打分前先行检查**：① 先把行情刷到**最新交易日**再打分（日线 + 30 分钟线；报告头"评估时间=最新交易日"，行情落后会漏评最近几天的信号）；② 2026 年至今 7 指数的 30 分钟线完整（每指数覆盖 2026-01-01 至最新交易日全部交易日、无缺日）——`run_direction.py` 每次运行自动检查，有缺口先补齐再打分。

**运维要点**：
- **爬取**：`python scripts/pipeline/scrape_toutiao.py <链接> --name <博主名> --since 2026-01-01`（只爬 2026 至今，翻页到早于 since 自动停止）。⚠️ 今日头条风控可能弹验证码并重定向回首页——表现为"爬取成功"但内容是别人的新闻流。传了 `--name` 时身份过滤严格只认本人帖：feed 混入他人帖触发 `wrong_feed` **拒绝产出**。其余防护：token 从 URL 提取、0 条不保存、覆盖前备份到 `data/posts/_backup/`、异常提前停默认拒绝覆盖（确属完整重爬才加 `--force`）；`--out` 供简报增量窗口写临时文件再 merge。正文详情页由 `fetch_bodies_shard.py` 抓取：风控返回空正文时记**空串占位、下次重跑重试，绝不当作有效正文**。重爬后**必须校验内容是否为博主本人帖子**；风控未解除请间隔几小时重试或用登录态 cookie
- **爬取后校验**：`python scripts/utils/verify_posts.py <博主名> --since 2026-01-01`。退出码 0=无硬失败可评估、1=有硬失败需重爬/修数据，⚠️ 只是提示。判读前认准：
  - **硬失败（必须修）**：重复 id/空字段 → 数据损坏重爬；**覆盖 miss**（earliest 晚于 since）——仅在停止原因是**截断类**（api_empty/js_error/status_abnormal…）时才是硬失败，**自然停**（since/no_more…）说明 since 前确实无帖、判 ✅；**备份强回落**（since 后帖数 < max(10, 50%×最完整备份)，时间轨迹/稀豹事故即此型）→ 从备份恢复或重爬。
  - **仅提示（可能正常）**：标题型帖多（正文<60字占比高）→ 未合并正文，先抓正文再合并；按日缺口/数量略少 → 停更/删帖/纯视频属正常。
  - **任一硬失败未解决先修数据，不要带病评估**

## 评估工作流

### Step 1：加载数据

读入 `data/posts/<博主名>.json` 的全部帖子。之后按需从 `data/market/market_data.json` 中读取与验证日期对应的行情行（无需全量加载，按日期查找即可）。

### Step 2：自动提取信号（DeepSeek）

信号由 `scripts/pipeline/extract_signals_direction.py` 调用 DeepSeek flash 按 §1~§8 规则自动逐条提取（不再人工逐条标注）：

```bash
export DEEPSEEK_API_KEY="sk-..."   # 只经环境变量，绝不写入文件
cd <项目根目录>
python scripts/pipeline/extract_signals_direction.py <博主名>
```

脚本做的事：
1. 读 `data/posts/<博主名>.json` 帖子（过滤 `publish_date >= 2026-01-01`），每条以「标题：…\n正文：…」并列呈现（标题取 `bodies.title` → `title` 字段 → 无正文时的原 `content`），标题与正文同等重要
2. 分批（默认 15 条/批）调 DeepSeek，按 §1~§8 规则判定并标注 `d`/`s`/`spec`/`idx`/`cat`（schema 见 §2）
3. 脚本强校验：非法 `spec`/`idx` 丢弃、`cat` 归一、同帖重复与**同日同周期同方向同指数**去重（`dedup_and_sort` 去重键含 `idx`；unscored 行另按 `(date, d, idx, summary)` 精确去重，同帖多条不同长线表述各自保留）、`summary≤50字`
4. **信号自查**：把「已提取信号 + 原文」回喂 DeepSeek 独立审查（keep/fix/drop/补加），修掉漏结论（如 07-28 丢了"探底回升我看涨"）、周期误套等错误
5. 产出 `data/direction_signals/<博主名>.json`，随后运行 `python scripts/eval/run_direction.py <博主名>` 生成报告

> **`--runs` 默认 1**（新博主抽取用默认值即可）。DeepSeek 同 prompt 下每次运行有少量批间随机差异（信号数 ±3 量级）；只有需要**跨运行共识**时才显式加 `--runs N`（N≥2）：完整跑 N 次（提取+自查），只保留出现 ≥`N//2+1` 次的信号再合并，聚合指标（正确率/平均分）更稳（实测两组独立 3 次共识差异在 ±1 个百分点内）。运行元数据写 `data/direction_signals/_<名>_run.json`（gitignored，仅本地溯源）。
>
> **冒烟测试**：`--limit 30` 只处理前 30 条——⚠️ **`--limit` 会强制只跑 1 次、`--runs` 被忽略**（`runs_count = args.runs if args.limit == 0 else 1`），别用冒烟结果当共识产物；`--out /tmp/x.json` 写指定路径不动正式数据；`--dry-run` 不调 API；`--no-verify` 跳过自查。每次运行会覆盖目标文件（无增量续跑）。
>
> **质量边界**：自查能系统性修复"漏结论/周期误套/单列类缺失"，但**不能保证每条语义正确**——方向冲突帖（全文立场与单句结论相反）仍会偶发分歧，且每次运行有少量随机差异。聚合层面与人工标注一致；如需逐条精确可核查，需人工抽检。

## 打分规则（§1~§8）

**判层与周期口径的主档在本文件**（字段/`spec` 的合法域仍以 `opinion/schema.py` 为准）；判层文本的实际落点与同步纪律见文首「权威与改动流程」。§1~§8 是这套规则的**可读主档**，非模型直接读入的文本。整个过程**不能用关键词匹配或正则表达式筛选或标注**：每个标注字段都由 DeepSeek 理解帖子语义判定。打分与汇总引擎见 `scripts/eval/run_direction.py`（个体报告）与 `scripts/eval/comparison_all.py`（横向榜单）。**改动流程：先改本文件 → 再据此改代码 → 跑 `opinion/tests/` → 同步 Windows**。

### §1 提取为信号的核心原则

**核心原则**：信号 = 帖子中**明确对未来的方向预测**。不逐项机械检查，整体判断"这篇帖子表达了对大盘未来的明确方向预测吗？"。以下**不产行**：

- 模棱两可：方向不明、涨跌皆可（"可能涨也可能跌""不好说""边走边看""看市场情绪""不确定""即将变盘"）
- 纯复盘 / 对过去分析：回顾行情、评价已发生走势（"今天这波下跌说明……""这次探底回升很标准"）
- 仅仅描述形态："震荡""筑底""洗盘""蓄势""拉锯""考验X点支撑""探底回升""冲高回落"
- **条件式**：方向挂在一个**未兑现的前提**上，无方向承诺——"守住3900看反弹""破了3900就减仓""放量突破才追""冲高回落转守4000"（守/破/分水岭/否则转震荡）均不产行
- **周期词不救形态（R2）**：带 这周/今天/下周 等周期词的**形态句仍是形态句**——"这周高开低走""今天冲高回落""下周探底回升"即便有时间词也不算方向。R2 禁止的是**该周期只有形态、无任何净方向承诺**的情形；一旦该周期另有独立无条件净方向句（同句或另一句），该行即成立，见下条

**「先抑后扬」是本族最易误判的一例（2026-09-10 实盘补正）**：它只是**路径先后次序**（先跌后涨），与"探底回升/冲高回落"同族，**本身不含净方向**——单凭"先抑后扬/先跌后涨"（哪怕带周期词）→ **不产行**，**严禁**自行解读成看多、再在 summary 里写成"整体看多"。**放宽（2026-09-10 语料核验）**：该周期若另有**独立无条件净方向句**，或明确的**逢跌买入承诺**（"回踩就是机会""回踩就大胆的进就是了""回踩时注意机会""逢低加仓"——按"操作动词 = 方向同义"）→ 以那一句成行，quote 取该句。语料里「先抑后扬」是**高频表述**、绝大多数是"形态半句 + 回踩买入半句"的看多路径表述，**不得**因为"先抑后扬属形态"就整条漏掉

**同期形态 + 泛净方向句 = 产行（2026-09-10 裁决）**：同一周期内既有形态描述、又有该周期的独立无条件**泛净方向句**、且**该句逐字存在于原帖正文**（形如"<形态半句>；<净方向半句>"，如"震荡上行，大方向向上"）→ **该周期产一行**，档位取该周期句的时间词（下周→`nweek`/展示「下周」），方向取净方向句；quote **必须从净方向部分起逐字截取、含净方向词**（**不得**只截前半句形态）。**产行前逐字核对**：把要安上去的方向词拿去原帖正文里搜，**搜不到 = 该周期不产行**；**严禁**替博主补一个他没说的方向词，**严禁**把教义示例措辞搬进 quote/summary（示例只示形状，不是可复制原文）。反例①："下周探底回升"单独出现、全帖再无该周期方向句 → 仍不产行。反例②：原帖通篇无方向词、只有形态句 → **不产行**（2026-09-10 实盘：0 方向词帖被配上"整体看多"上卡多档）。复核侧同源（`DOCTRINE_REVIEW` 条目 6/7：此类行 keep/fix、**不 drop**；**条目 8：多周期各行独立复核、不跨周期 cross-fix**；**条目 10：方向词原帖找不到 → 编造，一律 drop**）。**正例**：2026-05-24 周日 A股王 帖（id=1866055285835784）——形态句"个人认为下周先抑后扬"＋同周期独立无条件净方向句"对于下周周线个人看涨"（另有"所以回踩时注意机会"）→ 产一行 `nweek`/下周、d=1，quote 取净方向句

> **溯源纪律（2026-09-10 立）**：本教义凡标注为"博主原话/实证"的引语，**必须能在语料 `data/posts` 里逐字搜到**——旧 Q4 正例实为模型捏造（"整体看多"这一措辞在全库语料里近乎检索不到），被写进教义后又被搬到别帖造成编造行。**引语的量级判断只写文字、不写死计数**，实际计数由 `opinion/tests/test_doctrine_provenance.py` 每次运行**从语料现算并打印**（该文件同时立闸禁止写死计数回流教义）；新增/改教义引语先跑它

- **「本周」已走完时说"本周" = 回顾还是前瞻**：先自问"说的是刚走完的那一周（复盘）还是要开盘的那一周（预测）"——复盘 → **不产行**；前瞻 → **必须编 `nweek`**。**详见 §3**（含"别过度应用"反例、复核侧条目 9 同源、量级依据）
- **一帖多周期各产一行（R1，必做）**：一帖可同时对多个周期/方向表态——"今天市场会大涨；综合看这周市场启动的判断不变" → 产 `today` 一行 + `week` 一行，quote 各自逐字截取，**不得只取近端/合并/丢弃远端周期**；各周期方向可一致也可相反
- 同一帖里既有复盘又有明确未来预测 → 只提取未来预测部分
- 整篇立场含糊但夹带明确预测句 → 提取该预测句（如"后市难料，但明天我看涨" → 提取"明天看涨"）
- "震荡"不代表明确方向；"震荡下跌/震荡上涨"才表示有明确方向
- 有明确的预测点位和预测周期 → 视作有明确方向预测：预期点位高于参考价=看涨、低于=看跌（例："今天下午能站上4000"→看涨）

**参与打分的核心原则**（针对已提取的信号，判定细节见 §2/§3）：
- 有明确的预测方向和预测周期（明天/本周/下周/短期等）→ `cat=scored`，按周期计分
- 有明确的预测点位和预测周期 → `cat=scored`，按周期计分
- 没有明确预测周期但有明确方向 → `cat=scored`，`spec=t5`（验证终点 = 信号日之后第 5 个交易日）
- 有方向但周期偏长（"中长期""未来几个月""三年"）或目标点位无时间承诺 → `spec=long`、`cat=unscored`，不计分（详见 §2）

**默认规则**：帖子中未写明任何指数或板块的名称，默认该帖子是对上证综指/大盘的判断，应提取信号。

**信号时间范围**：只提取 2026 年 1 月 1 日及之后发布的信号。

**参与打分的博主**：帖子跨度的时间 ≥ 6 个月、且 2026 年以来可提取的信号数量 > 10 条的博主才参与打分；不满足者不参与打分。

### §2 信号标注字段

信号写入 `data/direction_signals/<博主名>.json`（schema 见下表，引擎 `scripts/eval/run_direction.py` 直接读取）。本目录是**已冻结的上游真源**：推送 / 报告两链直接读它；`research/`（波段回测）读的是它的**派生副本** `research/signals/`（由 `python -m research.corpus` 生成，另补 `board`/`target`/`target_txt` 键）——改本文件的 schema 须同步重跑 `research.corpus`，口径见 `Swing_Timing.md` §1「数据来源」：

```json
{"blogger": "博主名", "signals": [{"pub": "2026-01-04 15:16", "d": 1, "s": 1, "idx": "上证指数", "spec": "t1", "summary": "指数开门红的概率大", "cat": "scored"}]}
```

| JSON 键 | 语义字段 | 取值 |
|:---|:---|:---|
| `pub` | `publish_time` | 帖子发布时间（posts JSON 中对应 `publish_date`，格式 `YYYY-MM-DD HH:MM`，用于定位参考价 bar） |
| `d` | `direction` | `1` = bullish 看多；`-1` = bearish 看空 |
| `s` | `strength` | `2` = strong（措辞坚决："一定""必将""满仓""清仓""坚决""毫无疑问"）；`1` = moderate（有方向判断但措辞温和："偏多""倾向于""大概率""有望"）。**用途**：不参与 `score = d × return × 100`，但驱动报告的 strong/moderate 分档（§6）与 §7 强度列（渲染为 `str`/`mod`）。**只有 `cat=scored` 的行有 `s`**，unscored 行不填；计分时缺省按 `1` |
| `idx` | `target_index` | 数据 key 名（默认"上证指数"）；帖子明确提到某指数/板块则按下方映射表标注 |
| `spec` | `time_horizon` | 预测周期编码，见 §3 表（`today`/`t1`/`t2`/`t3`/`t5`/`tN`/`week`/`nweek`/`nweek_first`/`month`/`nmonth`/`long`；`d:YYYY-MM-DD` 为**旧抽取的既有合法值**，引擎仍解析、**09-09 起新抽取不再产**）。**精准对应帖子中预测本身的时间周期**，不从宽泛分类中选取——LLM 必须从原文提取博主明确说的时间，按 §3 转换 |
| `summary` | 信号内容摘要 | ≤50 字的预测关键句概括 |
| `cat` | 参与状态 | 只有两个值：`scored` 参与打分；`unscored` 不计分（**spec=`long` 的信号一律 `cat=unscored`**）。**`待验证`/`无效-过时`/`报错` 不需 LLM 手写**：终点超出数据覆盖、或过时（终点 ≤ 发布日且已收盘）、或非交易日发布的"今天"，仍写 `cat="scored"` 且 `spec` 必填，由引擎计算时自动判定并单列 |

> **模型行 vs 入库行**：上表是**入库**的最小键集（report 侧 `normalize_signal` 产物）。**模型判读时产的行**（共享标注 prompt 输出、校验前）另含 `post_n`（帖序号）、`horizon`（推送展示词）、`quote`（预测原句逐字截取 ≤60 字，unscored 留空）——**入库时裁掉的是 `post_n`（`pub` 全文替换它）、`horizon`、`quote`**；另有可选 `target`（数值）**保留入库**（`extract_signals_direction.py:normalize_signal` 落 `sig["target"]`），用途是让提取脚本自校验 d 与目标位方向一致，**报告引擎不读它**（`run_direction.py` 只取 pub/d/s/idx/spec/summary/cat）。仅**无条件净方向的移动目标**才填 `target`——条件式/区间锚句不产行、不填 d、不填 target。

**⚠️ 语义理解原则（关键）**：预测周期必须通过**语义理解**提取，不是关键词匹配。帖子中出现"明天"二字不代表这就是对明天市场的预测：
- "明天会怎样，**先看4000反击**" → ❌ **条件/观察句**，不产行（出现"明天"≠有可提取的明天预测）
- "**明天开始**至本周五，两手准备" → 预测的是**本周**（"明天"只是起止描述）
- "本人**还剩4成**仓位" → ❌ 仓位**状态**自述（状态句≠方向）
- "**接下去**每跌50点加0.5成" → ❌ **条件式操作计划**（依赖未承诺前提）
- "**减仓为主**""下周一清仓""逢高减了半仓" → ✅ **无条件操作动作本身是方向**（减/清/止盈=看空同义、加/重/补/抄底=看多同义）——有周期按周期、无时间词按 t5，成行计分
- "**下个目标是4260点**" → ⚠️ 目标点位无时间承诺 → `spec="long"` + `cat=unscored` 单列

> LLM 必须先回答"这篇帖子预测了什么？"，再回答"这个预测针对什么时间周期？"

**目标点位 vs 时间预测**：博主常用的"目标是 X 点""看到 X 点""还有 X 点空间"是**目标点位**，只承诺方向、不承诺到达时间。**不能**当成"未来几天/下周"预测；无时间承诺的统一 `spec="long"` 单列（`cat=unscored`）；明确说"X 天内到 4260"才按对应周期正常打分。另注意**"守住3900看反弹""3900-3950震荡"这类条件式/区间锚句不是方向句**，不产行、不填 d、不填 target——`target` 只给"无条件净方向"的移动目标（"要摸4200"），条件式里的点位是前提不是目标。

**板块 → 指数映射规则**：帖子中提到具体板块/宽基指数时，只有**能映射到下表的指数**的预测才参与打分，其余忽略。**合法 `idx` 共 8 个**（`opinion/schema.py:VALID_IDX`）= 7 个单指数（上证指数/上证50/沪深300/中证500/中证1000/创业板指/科创50）+ 组合「双创」；下表未列全的写法走 `IDX_ALIAS`（上证综指/上证/综指 → 上证指数）：

### §3 验证终点

**核心原则**：帖子预测的时间窗口是什么，就验证那个窗口的终点——说"明天"就只看明天，说"下周"就只看下周，**不扩展、不缩短、不随意假设**。LLM 必须根据具体预测周期确定一个精确的验证日期，不能泛化到长度区间。

> **"信号日"指帖子发布的自然日**。下表所有"信号日之后第 N 个交易日"均从发布日往后数：周五盘后说"明天涨"→ 明天=周六 → 顺延验证周一；周日说"明天/星期一"→ 验证周一。参考价仍按 §4 定价。

| 帖子中的预测周期 | 编码 | 验证终点 |
|:---|:---|:---|
| "今天""今日""下午""今天尾盘" | `today` | 信号日当天收盘（必须交易日发布，否则报错） |
| "明天""明日""次日" | `t1` | 信号日之后第 1 个交易日 |
| "后天" | `t2` | 信号日之后第 2 个交易日 |
| "下周""下周一""下周五" | `nweek` / `nweek_first` / `t1` | 下一周的对应交易日。"**下周一按该日是否为发帖后首个交易日分叉（2026-09-10 编码纠正）**：是 → `t1`（周五/周六/周日发帖说"下周一"多属此类，下一交易日正是那个周一，与 `t1` 定义一致）；否 → `nweek_first`（周一~周四发帖，隔着一个整周）。"下周五"=`nweek`=下周最后一个交易日；"下周"未指明星期几 → `nweek` |
| "本周""本周内" | `week` | **发布自然日所在那一周**（周一~周日）的最后一个交易日——**非交易日发布不再顺延到下一周**（2026-09-10 周口径修正）：周末/节假日发帖时该周已收盘结束，故回顾句不产行、前瞻句须改编码 `nweek`，见下方说明 |
| "月底前""月末前" | `month` | 当月最后一个交易日 |
| "下个月""下月" | `nmonth` | 下个月的最后一个交易日 |
| "下半年""全年""今年""2026年"等年度预测 | `long` | **不参与打分**（`cat=unscored`） |
| "N天后""N日内"（N 为具体数字） | `tN` | 信号日之后第 N 个交易日（"3天后"→`t3`、"10天后"→`t10`） |
| "1-2天""3-5天"等"X-Y天" | `tY` | 信号日之后第 Y 个交易日（**取预测窗口的最后一个交易日**，如"1-2天"→`t2`、"3-5天"→`t5`） |
| "未来几天" | `t3` | 信号日之后第 3 个交易日（未给具体数字，默认 3 天） |
| "近期""短期"且无具体数字 | `t5` | 信号日之后第 5 个交易日（未给具体数字，保守默认） |
| "中长期""未来几个月""三年"等 | `long` | **不参与打分**（`cat=unscored`） |
| **"X月X日""X月X日之前""X月X日前后"（未来具体日期）** | `tN` | **按该日期距发帖日的自然日差落档**：日差 N≤30 → `tN`（如 8/10 发帖说"8月20日"→ 距 10 天 → `t10`）；自然日差 >30 或明显远期（跨下月以后/跨年/"某日见顶/见底"类远期节点）→ `long`/unscored 不计分。**不写 `d:YYYY-MM-DD`**——历法与交易日换算由引擎按发帖日做 |
| **"下周X""周五"等具体星期（未来）** | `week`/`nweek`/`nweek_first`/`t1`/`month`/`nmonth` | **有周/月词跟词，就近落已有档位**："下周一"→ 该日即发帖后首个交易日则 `t1`、否则 `nweek_first`；"下周五/下周X/下周"→ `nweek`；本周内"周五/周X"→ `week`；"月底前"→ `month`；下月词→ `nmonth`——引擎按交易日历取对应交易日，**不再单独编码成具体日期（不产 `d:date`）** |
| 无预测周期但有明确预测方向 | `t5` | 信号日之后第 5 个交易日（与"近期""短期"同一终点，正常计分并参与多空/两档） |
| **"目标是X点""看到X点""还有X点空间"（目标点位，无时间承诺）** | `long` | **不参与打分**（`cat=unscored`，详见 §2） |

> **⚠️ 区分未来日期与回顾日期**：帖子中出现日期不等于预测。必须判断该日期是**对未来的预测窗口**（"8月7日之前都是磨底"→ 预测到 8/7）还是**对过去的回顾**（"2月8日我还提醒了一次"→ 不提取）。同一日期只有在预测语境中才按日期规则落档。

> **周末/顺延处理**：验证终点当日若该指数无行情行（周末、长假、临时休市），一律顺延到下一个有行情行的交易日——如周五盘后说"明天涨"→ 验证周一。该规则用于 `tN` 与旧 `d:`（仅兼容解析）；`today` 类终点**必须发布于交易日**（非交易日发布的"今天"由引擎报错单列，不计分）；`week`/`nweek`/`nweek_first`/`month`/`nmonth` 本身按交易日历取周期内最后（或首个）交易日，不另行顺延。

> **⚠️ 「本周」已走完时发帖说"本周"——先自问"刚结束的那一周"还是"即将到来的那一周"（2026-09-10 周口径修正）**：`week` 终点 = **发布自然日所在那一周**的最后交易日，所以**只要发帖时那一周已经收盘走完（典型：周六/周日发帖；某周最后交易日为假期、其后发帖亦然），"本周"就必然指向一段已经结束的行情**。
> - **复盘**（总结已发生走势）→ **不产行**；
> - **前瞻**（预判下周怎么走/下周目标位/下周见底）→ 从发帖时点看那一周就是**下一周** → **必须编码 `nweek`**——**不得因为博主嘴上写"本周"就编 `week`**；
> - 此时产 `week` 必有错：终点落在发布日之前，会被引擎判"无效-过时"（报告侧）/过期门剔除（推送侧），等于把真预测丢掉。
> - **别过度应用（反例）**：本周**尚未**走完时说"本周"指当周、**正常 `week`**——周一~周五发帖都属此类，**周中假日亦然**；周五发帖说"本周"= 当天，也正常。
> - **复核侧同源**（`DOCTRINE_REVIEW` 条目 9）：此类 `week` 行若 quote/summary 指向下周 → **fix spec→`nweek`、horizon→下周**（编码错、不是观点错，**不 drop**）；确为复盘 → **drop**；无从判断 → **drop**（keep 下来也只是"无效-过时"的死行）。**不得仅因"发帖日非交易日"就 drop** 本周尚未走完的正常 `week` 行。
> - **复核侧同源**（`DOCTRINE_REVIEW` 条目 11）：**"下周一"落错格**——行内 quote/summary 载"下周一"（须原帖逐字可见）而 spec 落 `t1`/`nweek_first` 中错的那个 → **fix**：只改 `spec` 与 `horizon`，**d 与 quote 一字不动**（**不得 drop**）。**为什么必须靠复核兜**：`horizon_spec_ok` 对 `(明天,t1)` 与 `(下周,nweek_first)` **都判自洽**，落错格的行坍缩时**不会**被弃——编码错会静默上卡，只能靠这道复核纠。
> - 依据（2026-09-10 回溯 curated 语料）：非交易日发布的 `week` 行里**绝大多数**终点落在发布日之前，其中**又有大部分**的摘要原话写的就是"下周"——那是旧编码把一个前瞻句塞进了 `week` 档，不是博主在复盘；少数终点仍在发布日之后，属正常合法行。**具体条数不写死**，由 `opinion/tests/test_doctrine_provenance.py` 现算并打印。

> **周口径三份实现统一（2026-09-10）**：`week` = 发布日所在 ISO 周最后交易日、`nweek` = **发布日 +7 天**所在 ISO 周最后交易日、`nweek_first` = 发布日 +7 天所在 ISO 周首个交易日。此前推送侧对周末 `week`/`nweek` 走"博主视角周"（前瞻加 7 天），与打分引擎不一致、且周末"本周"与"下周"撞成同一天——现已三份归一（`opinion/tests/test_endpoint_consistency.py` 702 组网格全等、无豁免格）。

> **⚠️ 过时预测（通用）**：凡验证终点 ≤ 发布日（且发布日已收盘）的信号即过时——典型：周五盘后发"本周"、**周末/节假日发"本周"**、月末已无剩余交易日发"月底前"、把回顾日期误标为具体日期、盘后发"今天"。LLM 无需过滤，引擎侧防御：自动标注"无效-过时"单列，不计分（research 侧同判：`target < 投票日` 则该行不投票）。

> **数据覆盖检查**：验证终点必须不晚于 `market_data.json` 中对应指数的最后一行日期。若超出覆盖范围，引擎自动判定为"待验证"（LLM 仍写 `cat="scored"`、`spec` 必填），不参与打分与汇总，在 §7 汇总表中单列。

### §4 信号参考价

**信号参考价 = 当前所能获取的最新价格**。所有预测周期统一用此参考价：

| 信号时间 | 参考价 |
|:---|:---|
| **交易时间中**（9:30~11:30、13:00~15:00） | **所处 30 分钟 K 线的开盘价**（bar 时间 = 收盘时间，如 10:20 发布 → 所处 10:30 bar，取该 bar 开盘价）。**整点边界取严格大于**：取首根 bar 时间 **`t > 发布时刻`** 的 bar 开盘价——恰 10:00:00 发布取的是刚开盘那根 10:00 bar（= 该时刻现价），**不回落**上一根 09:30 bar（旧 `t >= hhmm` 会让 10:00 比 10:01 拿到更旧的价） |
| **非交易时间**（盘前 <9:30 / 午休 11:30~13:00 / 盘后 ≥15:00 / 周末假期） | **上一根 30 分钟 K 线的收盘价**（如 15:30 发布 → 15:00 bar 收盘价；盘前/非交易日 → 上一交易日 15:00 bar 收盘价） |

> **30 分钟线结构**（`data/market/intraday/<指数名>_30min.json`）：每指数每日 8 根 bar（10:00/10:30/11:00/11:30/13:30/14:00/14:30/15:00），bar 时间 = 收盘时间，首根 bar open≈9:30 开盘价、末根 bar close=当日收盘价。信号参考价与终点价均取自此。
>
> 终点价 = 验证终点日 15:00 bar 收盘价（= 当日收盘价）。`双创` 组合与无 30 分钟数据的日线降级口径同 §2。

### §5 打分规则

**score = direction × return × 100**

```
return    = 验证终点收盘价 / 信号参考价 − 1
direction = +1（看多）/ −1（看空）
```

> 参考价按 §4；终点收盘价 = 验证终点日 15:00 bar 收盘（即当日收盘价）。

**示例**：

| 情形 | 强度 | 参考价 | 终点收盘 | return | direction | 打分 |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|
| 看多，涨了 | moderate | 3800 | 4020 | +5.79% | +1 | **+5.79** |
| 看多，跌了 | **strong** | 3800 | 3760 | -1.05% | +1 | **-1.05** |
| 看空，跌了 | moderate | 4100 | 4072 | -0.68% | -1 | **+0.68** |
| 看空，涨了 | **strong** | 4100 | 4120 | +0.49% | -1 | **-0.49** |

### §6 汇总指标

对博主的所有预测信号汇总。**计分样本只认 `idx=上证指数`**（2026-09-08 起）；unscored/无效-过时/待验证/报错信号单列，不计入任何指标：

```
计分样本：N 条（idx=上证指数）　[上证以外计分 M 条不参与本组指标/排名]   # 博主无上证以外计分行时此头行写作"信号总数：N"——此 N = 上证计分行数，**不是**报告头部那行全量"信号总数"（见 §8）
  另有：unscored X 条（spec=long）/ 无效-过时 X 条 / 待验证 X 条 / 报错 X 条（单列，不计分）
方向正确：N（正确率 N% = score>0 的信号数 / (N − 平数)；score=0 计"平" X 条，平数不计入分子分母）
  - strong 正确：N/N（正确率 N%）
  - moderate 正确：N/N（正确率 N%）
平均分：+X.XX（= 单信号平均收益 %，核心指标）
波动率：X.XX（单信号 score 样本标准差）
夏普：+X.XX（= 平均分 / 波动率；信号 <2 条或波动率为 0 时显示 —）
最高分：+X.XX / 最低分：-X.XX
看多平均分：+X.XX（N 条）  看空平均分：+X.XX（N 条）
抄底平均分：+X.XX（N 条）= 底部拐点当天及前一天（共 2 个交易日）窗口内信号的平均分
逃顶平均分：+X.XX（N 条）= 顶部拐点当天及前一天（共 2 个交易日）窗口内信号的平均分
```

> **计分样本口径**：`scored`（全部指标/四分类表/月度/排名共同只用它）= 该博主 `idx=上证指数` 的计分行。若另有上证以外的计分行（创业板指/科创50/上证50/双创 等），只保留**全量计数展示**（头部"信号总数/评价口径"行 + 逐条表标注目标指数），**不参与本组任何指标、分类表与排名**。
>
> 抄底/逃顶的拐点（顶部/底部，含 Major + Intermediate）取自 `knowledge/market_analysis.md`（§5.1/§5.2）；窗口 = 拐点交易日 + 其前一交易日（共 2 个交易日），上证计分信号发布时间落在该窗口内的参与统计——**两个独立指标行分别输出**；窗口内无信号时显示 —（0 条）。

### §7 逐条汇总表

```
| # | 日期 | 内容(≤50字) | 方向 | 强度 | 预测周期 | 目标指数 | 参考价 | 终点日 | 终点收盘 | return | 分 | 备注 |
|:---|:---|:---|:---|:---|:---|:---|:---:|:---:|:---:|:---:|:---:|:---|
| 1 | 01-07 | 上攻已显疲态，将进入回调 | ↓ | mod | 明天 | 上证 | 4083 | 01-08 | 4072 | -0.27% | +0.27 | — |
| 2 | 01-09 | 明天A股绝地反击 | ↑ | str | 明天 | 上证 | 4120 | 01-12 | 4165 | +1.09% | +1.09 | — |
```

> **方向/强度列**：`↑` = d=+1（看多）、`↓` = d=−1（看空）；`str` = strong（`s=2`）、`mod` = moderate（`s=1`），映射见 `run_direction.py:S_TXT`，`s` 的语义见 §2。
>
> **备注列**：正常信号填 `—`；盘中"今天"（日内窗口计分）填 `日内`；spec=`long` 的不计分信号填 `不计分`；验证终点超出数据范围填 `待验证`；验证终点 ≤ 发布日且已收盘填 `无效-过时`；非交易日发布的"今天"填 `报错`（后三者均由引擎自动判定）。unscored/无效-过时/待验证/报错信号不参与打分与 §6 汇总。方向正确 = 验证终点收盘优于参考价（score>0）。

### §8 报告输出

**个体报告**：`python scripts/eval/run_direction.py [博主名]`（不传参数则跑全部博主）→ `reports/<博主名称>_direction.md`，含：
- 头部：评估时间（= 最新交易日）、帖子总数（posts 缺失时标"未知"）、**信号总数（= 全部信号行数，含不计分/待验证/无效-过时/报错）**；博主含上证以外计分行时另有一行「评价口径」注明只取上证样本
  - ⚠️ **两处「信号总数」同名不同义，引用时认准出处**：**头部**那行 = 全量行数（`run_direction.py:553`）；**§6 汇总块首行** = 上证计分样本数（`run_direction.py:574`，有上证以外计分行时改写为「计分样本：N 条（idx=上证指数）」）
- 汇总指标：按 §6
- **四个分类表**（每表只统计上证计分样本、含 信号数/平均分/胜率/波动率/夏普）：① 按预测指数；② 按预测周期两档归类（算法见本节末）；③ 按看多看空；④ 按抄底逃顶（口径同 §6）
- 月度表现：按信号发布月份统计
- 信号时间分布与集中度（⚠️ 必须提出警告）：覆盖 <3 个月 ⚠️覆盖不足；单月占比 ≥50% ⚠️高度集中、33%~50% 轻度集中；相邻月份缺 ≥3 个月 ⚠️严重缺口、缺 1-2 个月提示。典型场景：停更/减产、帖子数据缺失、标注未完成
- 逐条汇总表：按 §7
- 观察要点：正确率结论、多空对比、抄底/逃顶表现、最强/最弱档与指数、最大单条命中/失误、单列信号统计

**横向对比**：`python scripts/eval/comparison_all.py` → `reports/comparison_direction.md`，只需要各榜单（**榜单口径 = 上证计分信号** `idx=上证指数`，与个体报告同一收敛样本；上证以外计分仅作各博主 meta 计数展示、不入榜单）：
- **总榜**（全部计分信号；**按夏普排序**，附计分信号数/正确率/**平均分**/波动率/夏普/多空数）——**排名资格：计分信号 ≥ 30 条 且 平均分 > 0，仅取前 20 名上榜**，不足者不参与排名、单列注明（统计无意义）
- **按预测周期分类的两档归类，各档排名**（每档按平均分排序）——**各档资格：该档信号 ≥ 10 条 且 平均分 > 0.1，各档仅取前 20 名上榜；各档表格形式与总榜相同**（排名/博主/信号数/正确率/平均分/波动率/夏普/看多/看空）
- **方向榜单**：看多榜 / 看空榜（看多= d=1、看空= d=-1；资格与表格形式同各档排名；子集方向固定故不含看多/看空列）
- **信号覆盖/集中度警告**（同上述阈值，逐博主列出）

**预测周期两档归类的详细算法**（实现位置：`scripts/eval/run_direction.py` 的 `bucket_of()`，`comparison_all.py` 直接复用，与引擎共用同一交易日历与 prev_td 逻辑）：

```
交易日历 CAL = market_data.json 中"上证指数"的日期序列（升序）
基准日 base = pub_date 若 pub_date ∈ CAL，否则 = 其前最近一个交易日
跨度 span = CAL.index(ep) − CAL.index(base)     # 信号日→验证终点的交易日数量
分档：span ≤ 1 → 超短期（0-1个交易日）| span ≥ 2 → 波段（2个交易日及以上）

边界示例：
  - 周五发布"明天"→ ep=下周一，span=1 → 超短期
  - 周一发布"下周初"→ ep=下周一，span=5 → 波段
  - 周一发布"下周"→ ep=下周五，span=9 → 波段
  - 周六发布"明天"→ base=周五，ep=下周一，span=1 → 超短期
```

## 附录：各博主 LLM 阅读指导

逐条提取前，先按博主的帖子结构特征快速定位核心预测句。

**通用规则**：
- **有标题时标题与正文并列呈现、同等重要**（多数博主文件无独立 title，仅正文）——标题常直接给出预测结论（"明天看涨""站稳4130就能到4250"可直接提取）；疑问句/引流话术式标题（"明天A股会怎么走？""下周要变天？"）不代表预测，去正文找结论。标题里明确的方向/周期不要因正文冗长而漏掉
- 在**标题 + 正文**中快速提取方向与预测周期即可，行情回顾、纯复盘、投资理念、仓位自述不提取
- **一帖多周期各产一行（R1，必做）**——口径见 §1；每行各自按 §3 设验证终点，可计分行按 §5 打分、`long`/unscored 行只单列。**同一周期重复表述只记一条**
- 同一天发布的针对同一周期的相同方向预测只记一条（如一天内多帖都喊"明天中阳线"→保留当天最晚发布的一条）；同一天的不同周期（或同周期不同方向）分开记录；不同日期发布的信号都分开记录

## 注意事项

- **只验证、不预测**——你的任务是评估博主的过去预测准确率，不是对未来走势发表观点
- **严格按预测周期验证**——帖子说"明天"就只看明天，不扩展到 3 天
- **打分即收益**——方向对了赚 return、错了亏 return
- **诚实打分**——博主预测准确率低就说低，不要粉饰
- **代码与文档一致性**：本文件 §1~§8 + 附录对应判层契约与打分汇总引擎 `scripts/eval/run_direction.py` / `comparison_all.py`；**判层文本不是单一来源**，改动须同步全部落点（见文首「权威与改动流程」）。回归：`python3 opinion/tests/test_prompt_doctrine.py`、`python3 opinion/tests/test_doctrine_provenance.py`、`python scripts/eval/run_direction.py --selftest`
