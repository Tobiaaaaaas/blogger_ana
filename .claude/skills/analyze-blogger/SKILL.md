# 博主择时能力打分

## 总览

**一句话定位**：全量读取博主帖子，逐条提取其中"对某板块或某指数未来的方向预测"（信号），用市场实际走势验证方向对错，并打分，最后汇总成个体报告与全博主横向榜单（下文五环节表即此线）。

本文是已冻结的上游真源，不接受自动篡改。
Prompt和相关代码是基于SKILL.md生成，如语义或逻辑上有冲突，应以本文为基准，重新修改对应的py文件。

## 五环节流水线（逐人评估）

| 环节 | 做什么 | 产物 |
|:---|:---|:---|
| ① 提取 | DeepSeek 读帖子，定位核心预测句提炼出信号，详见§1。仅这一步需要LLM参与。 | 信号 `{pub、d、idx、spec、summary、cat}`，详见§2 |
| ② 定参考价 | 信号发布时刻pub对应的"当前最新价"：盘中=所处 30 分 bar 开盘价；盘前/午休/盘后/周末=上一根 bar 收盘价 | 参考价，详见§4 |
| ③ 定验证终点 | 按信号标注spec精确锁死一个验证日——说"明天"就验证明天，不扩展不缩短 | 验证终点 ep，详见§3 |
| ④ 打分 | score = direction × return × 100，方向对赚、错亏 | 每条信号产出一个分数，详见§5 |
| ⑤ 汇总/排名 | 个体报告（汇总+三个分类表+逐条表）+ 全博主横向榜单 | `reports/*.md` |

## 用法

```
/analyze-blogger <博主名称> [帖子链接]      # 例：/analyze-blogger 方向评估 奔走的股票
```

- 提供**帖子链接**：先爬取该作者 2026 年至今的帖子，再进入方向评估
- 提供**博主名称**（帖子已爬取）：直接进入方向评估
- 如未提供参数，Skill 会询问。

## 前置条件

**数据就绪 4 要素**：
- `data/posts/<博主名>.json`：已爬取全部帖子且 `content` 含完整正文+标题。有标题时标题与正文并列呈现同等重要。**判读只需 `content`**；`title` 非必需（多数博主帖子无独立title，仅正文）——仅列表接口博主经 `merge_bodies_to_posts.py` 回填正文时才补写 title，缺 title 时 `opinion/text.resolve_post` 兜底（标题→正文首句/整段，微帖只显一次）。正文缺失时用 `scripts/utils/fetch_bodies_shard.py` 抓正文 + `scripts/utils/merge_bodies_to_posts.py` 回填（旧分片归档 `archive/<日期>-bodies-merged/`）
- `data/market/market_data.json`：7 指数日线，已更新到最新交易日（`python scripts/utils/fetch_market_data.py --start 20240601`）
- `data/market/intraday/<指数名>_30min.json`：7 指数 30 分钟线——所有信号的参考价与终点价来源（`python scripts/utils/fetch_market_intraday.py`）
- **DeepSeek API Key**：`export DEEPSEEK_API_KEY="sk-..."`，只经环境变量传入（**绝不写入文件、绝不提交 GitHub**）；依赖 `pip install openai`

**打分前先行检查**：① 先把行情刷到**最新交易日**再打分（日线 + 30 分钟线；报告头"评估时间=最新交易日"，行情落后会漏评最近几天的信号）；② 2026 年至今 7 指数的 30 分钟线完整（每指数覆盖 2026-01-01 至最新交易日全部交易日、无缺日）——`run_direction.py` 每次运行自动检查，有缺口先补齐再打分。

**运维要点**：
- **爬取**：`python scripts/pipeline/scrape_toutiao.py <链接> --name <博主名> --since 2026-01-01`（只爬 2026 至今，翻页到早于 since 自动停止）。⚠️ 今日头条风控可能弹验证码并重定向回首页——表现为"爬取成功"但内容是别人的新闻流。传了 `--name` 时身份过滤严格只认本人帖：feed 混入他人帖触发 `wrong_feed` **拒绝产出**。其余防护：token 从 URL 提取、0 条不保存、覆盖前备份到 `data/posts/_backup/`、异常提前停默认拒绝覆盖（确属完整重爬才加 `--force`）；`--out` 供简报增量窗口写临时文件再 merge。正文详情页由 `fetch_bodies_shard.py` 抓取：风控返回空正文时记**空串占位、下次重跑重试，绝不当作有效正文**。重爬后**必须校验内容是否为博主本人帖子**；风控未解除请间隔几小时重试或用登录态 cookie
- **爬取后校验**：`python scripts/utils/verify_posts.py <博主名> --since 2026-01-01`。退出码 0=无硬失败可评估、1=有硬失败需重爬/修数据，⚠️ 只是提示。判读前认准：
  - **硬失败（必须修）**：重复 id/空字段 → 数据损坏重爬；**覆盖 miss**（earliest 晚于 since）——仅在停止原因是**截断类**（api_empty/js_error/status_abnormal…）时才是硬失败，**自然停**（since/no_more…）说明 since 前确实无帖、判 ✅；**备份强回落**（since 后帖数 < max(10, 50%×最完整备份)，时间轨迹/稀豹事故即此型）→ 从备份恢复或重爬。
  - **仅提示（可能正常）**：标题型帖多（正文<60字占比高）→ 未合并正文，先抓正文再合并；按日缺口/数量略少 → 停更/删帖/纯视频属正常。
  - **任一硬失败未解决先修数据，不要带病评估**

## 评估工作流

### Step 1：加载数据

读入 `data/posts/<博主名>.json` 的全部帖子。之后按需从 `data/market/market_data.json` 中读取与验证日期对应的行情行（无需全量加载，按日期查找即可）。

### Step 2：自动提取信号（DeepSeek）

信号由 `scripts/pipeline/extract_signals_direction.py` 调用 DeepSeek flash 按 §1~§8 规则自动逐条提取（不再人工逐条标注）：

```bash
export DEEPSEEK_API_KEY="sk-..."   # 只经环境变量，绝不写入文件
cd <项目根目录>
python scripts/pipeline/extract_signals_direction.py <博主名>
```

脚本做的事：
1. 读 `data/posts/<博主名>.json` 帖子（过滤 `publish_date >= 2026-01-01`），每条以「标题：…\n正文：…」并列呈现（标题取 `bodies.title` → `title` 字段 → 无正文时的原 `content`），标题与正文同等重要
2. 分批（默认 15 条/批）调 DeepSeek，按 §1~§8 规则判定并标注 `d`/`spec`/`idx`/`cat`（schema 见 §2）
3. 脚本强校验：非法 `spec`/`idx` 丢弃、`cat` 归一、同帖重复与**同日同周期同方向同指数**去重（`dedup_and_sort` 去重键含 `idx`；unscored 行另按 `(date, d, idx, summary)` 精确去重，同帖多条不同长线表述各自保留）、`summary≤50字`
4. **信号自查**：把「已提取信号 + 原文」回喂 DeepSeek 独立审查（keep/fix/drop/补加），修掉漏结论（如 07-28 丢了"探底回升我看涨"）、周期误套等错误
5. 产出 `data/direction_signals/<博主名>.json`，随后运行 `python scripts/eval/run_direction.py <博主名>` 生成报告

> **`--runs` 默认 1**（新博主抽取用默认值即可）。DeepSeek 同 prompt 下每次运行有少量批间随机差异（信号数 ±3 量级）；只有需要**跨运行共识**时才显式加 `--runs N`（N≥2）：完整跑 N 次（提取+自查），只保留出现 ≥`N//2+1` 次的信号再合并，聚合指标（正确率/平均分）更稳（实测两组独立 3 次共识差异在 ±1 个百分点内）。运行元数据写 `data/direction_signals/_<名>_run.json`（gitignored，仅本地溯源）。
>
> **冒烟测试**：`--limit 30` 只处理前 30 条——⚠️ **`--limit` 会强制只跑 1 次、`--runs` 被忽略**（`runs_count = args.runs if args.limit == 0 else 1`），别用冒烟结果当共识产物；`--out /tmp/x.json` 写指定路径不动正式数据；`--dry-run` 不调 API；`--no-verify` 跳过自查。每次运行会覆盖目标文件（无增量续跑）。
>
> **质量边界**：自查能系统性修复"漏结论/周期误套/单列类缺失"，但**不能保证每条语义正确**——方向冲突帖（全文立场与单句结论相反）仍会偶发分歧，且每次运行有少量随机差异。聚合层面与人工标注一致；如需逐条精确可核查，需人工抽检。

## 打分规则（§1~§8）

**判层与周期口径的主档在本文件**（字段/`spec` 的合法域由 `opinion/schema.py` 承载，以本文件 §2/§3 为基准）。§1~§8 是这套规则的**可读主档**，非模型直接读入的文本。整个过程**不能用关键词匹配或正则表达式筛选或标注**：每个标注字段都由 DeepSeek 理解帖子语义判定。打分与汇总引擎见 `scripts/eval/run_direction.py`（个体报告）与 `scripts/eval/comparison_all.py`（横向榜单）。

### §1 从帖子提取信号

1. 帖子有信号 = 帖子中有明确对某板块或某指数的方向预测。一条帖子有多个语句构成，要分开判断，逐条提取前，先按博主的帖子结构特征快速定位核心预测句（可能有0个或多个）。
2. 有标题时标题与正文并列呈现、同等重要（多数博主文件无独立 title，仅正文）——标题常直接给出预测结论（"明天看涨""站稳4130就能到4250"可直接提取）；疑问句/引流话术式标题（"明天A股会怎么走？""下周要变天？"）不代表预测，去正文找结论。标题里明确的方向/周期不要因正文冗长而漏掉
3. 在标题 + 正文中快速提取信号 {pub、d、idx、spec、summary、cat}，行情回顾、纯复盘、投资理念、仓位自述不提取
4. pub在交易日收盘后且spec=today，则视为回顾/复盘 → 不产生信号

5. pub时间晚于当周最后一个交易日收盘且spec=week，则视为回顾/复盘 → 不产生信号

6. pub时间晚于当月最后一个交易日收盘且spec=month，则视为回顾/复盘 → 不产生信号

7. 若 content 未合并进完整正文，先按「前置条件」补齐（分片抓取 + 合并）再标注；标题疑问句本身不代表预测。

8. 凡标注为"博主原话/实证"的引语，必须能在语料 `data/posts` 里逐字搜到。

9. 同一帖里既有复盘又有明确未来预测 → 只提取未来预测部分

10. 同一天发布的针对同一指数同一预测周期的同方向预测只记最新一条（如一天内多帖都喊"明天中阳线"→保留当天最晚发布的一条）

11. 同一天发布的不同预测周期的分开记录成不同信号：同一天发布的一条或多条帖子可同时对多个周期/方向表态——"今天市场会大涨；综合看这周市场启动的判断不变" → 产生 today 一条信号 + week 一条信号，quote 各自逐字截取，不得只取近端/合并/丢弃远端周期；各周期方向可一致也可相反

12. 同一天的相同预测周期的，如果针对的idx不同，分开记录成不同信号

13. 同一天，针对同样idx，相同预测周期的，如果方向d不同，分开记录成不同信号

14. 不同日期发布的信号都分开记录

15. 整篇立场含糊但夹带明确预测句 → 提取该预测句（如"后市难料，但明天我看涨" → 提取"明天看涨"）

16. "震荡"不代表明确方向；"震荡下跌/震荡下行/震荡上涨/震荡上行"才表示有明确方向

17. 有明确的预测点位 → 视作有明确方向预测：预期点位高于参考价=看涨、低于=看跌（例："今天下午能站上4000"→看涨），cat 与周期按 §3 表定

18. 严禁替博主补一个他没说的方向词，严禁把教义示例措辞搬进 quote/summary（示例只示形状，不是可复制原文）。

19. 语义理解原则（关键）：预测周期必须通过**语义理解**提取，不是关键词匹配。帖子中出现"明天"二字不代表这就是对明天市场的预测。
- "明天会怎样，**先看4000反击**" → ❌ **条件/观察句**，不产生信号（出现"明天"≠有可提取的明天预测）
- "**明天开始**至本周五，两手准备" → 预测的是**本周**（"明天"只是起止描述）
- "本人**还剩4成**仓位" → ❌ 仓位**状态**自述（状态句≠方向）
- "**接下去**每跌50点加0.5成" → ❌ **条件式操作计划**（依赖未承诺前提）
- "**减仓为主**""下周一清仓""逢高减了半仓" → ✅ **无条件操作动作本身是方向**（减/清/止盈=看空同义、加/重/补/抄底=看多同义）——有周期按周期、无时间词按 t5，产生信号计分
- "**下个目标是4260点**" → ✅ 无预测周期但有预测点位 → `spec=t5` 计分

注意以下语句不产生信号：

- 模棱两可：方向不明、涨跌皆可（"可能涨也可能跌""不好说""边走边看""看市场情绪""不确定""即将变盘"）
- 纯复盘 / 对过去分析：回顾行情、评价已发生走势（"今天这波下跌说明……""这次探底回升很标准"）
- 仅仅描述形态："震荡""筑底""洗盘""蓄势""拉锯""考验X点支撑""探底回升""冲高回落""先抑后扬"等
- **条件式**：方向挂在一个**未兑现的前提**上，无方向承诺——"守住3900看反弹""破了3900就减仓""放量突破才追""冲高回落转守4000"（守/破/分水岭/否则转震荡）
- 周期词不救形态：带"这周/今天/下周"等周期词的形态句仍是形态句——"这周高开低走""今天冲高回落""下周探底回升"即便有时间词也不算方向。这里强调的是该周期只有形态、无任何净方向承诺的情形。"先抑后扬"是易误判的一例：它只是路径先后次序（先跌后涨），与"探底回升/冲高回落"同族，本身不含净方向——单凭"先抑后扬/先跌后涨"（哪怕带周期词）→ 不产生信号，严禁自行解读成看多。

**同期形态 + 泛净方向句 = 产生信号**：同一周期内既有形态描述、又有该周期的独立无条件**泛净方向句**、且**该句逐字存在于原帖正文**，方向取净方向句；quote **必须从净方向部分起逐字截取、含净方向词**（**不得**只截前半句形态）。例：2026-05-24 周日 A股王 帖（id=1866055285835784）——形态句"个人认为下周先抑后扬"＋同周期独立无条件净方向句"对于下周周线个人看涨"（另有"所以回踩时注意机会"）→ 产生一条 `nweek`/下周、d=1 信号，quote 取净方向句。

**默认规则**：核心预测句未写明任何指数或板块的名称，默认该核心预测句是对上证综指/大盘的判断，应提取信号。

**信号时间范围**：只提取 2026 年 1 月 1 日及之后发布的信号。

**参与打分的博主**：帖子跨度的时间 ≥ 6 个月、且 2026 年以来可提取的信号数量 > 10 条的博主才参与打分；不满足者不参与打分。

### §2 信号标注字段

信号写入 `data/direction_signals/<博主名>.json`（schema 见下表，引擎 `scripts/eval/run_direction.py` 直接读取）。本目录是已冻结的上游真源，不接受自动篡改。

```json
{"blogger": "博主名", "signals": [{"pub": "2026-01-04 15:16", "d": 1, "idx": "上证指数", "spec": "t1", "summary": "指数开门红的概率大", "cat": "scored"}]}
```

| JSON 键 | 语义字段 | 取值 |
|:---|:---|:---|
| `pub` | `publish_time` | 帖子发布时间（posts JSON 中对应 `publish_date`，格式 `YYYY-MM-DD HH:MM`，用于定位参考价 bar）。**pub 由系统按帖子回填，LLM 不填写** |
| `d` | `direction` | `1` = bullish 看多；`-1` = bearish 看空 |
| `idx` | `target_index` | 数据 key 名（默认"上证指数"）；核心预测句明确提到某指数/板块则按下方映射表标注 |
| `spec` | `time_horizon` | 预测周期编码，见 §3 表（`today`/`t1`/`t2`/`t3`/`t5`/`tN`/`week`/`nweek`/`monday`~`friday`/`nmonday`~`nfriday`/`month`/`nmonth`/`long`/`d:YYYY-MM-DD`）。**精准对应帖子中信号预测的时间周期**，不从宽泛分类中选取——LLM 必须从原文提取博主明确说的时间，按 §3 转换 |
| `summary` | 信号内容摘要 | ≤50 字的预测关键句（博主原话） |
| `cat` | 参与状态 | 只有两个值：`scored` 参与打分；`unscored` 不计分（**spec=`long` 的信号一律 `cat=unscored`**）。**`报错` 不需 LLM 手写**（非交易日发布的"今天"由引擎判报错单列）；终点超出数据覆盖、或过时（终点 ≤ 发布日且已收盘），则 cat=unscored |

**板块 → 指数映射规则**：核心预测句中提到具体板块/宽基指数时，只有**能映射到下表的指数**的预测才参与打分，其余忽略。**合法 `idx` 共 8 个**（`opinion/schema.py:VALID_IDX`）= 7 个单指数（上证指数/上证50/沪深300/中证500/中证1000/创业板指/科创50）+ 组合「双创」；下表未列全的写法走 `IDX_ALIAS`（上证综指/上证/综指 → 上证指数）：

| 帖子提到的名称 | 映射指数 | 代码 |
|:---|:---|:---|
| 创业板 / 创业板指 / 创业板ETF | 创业板指 | 399006 |
| 科创 / 科创50 / 科创板 / 半导体 / 芯片 | 科创50 | 000688 |
| 双创 | 创业板指+科创50（各半）| 399006/000688 |
| 小盘 / 成长 / 中证1000 | 中证1000 | 000852 |
| 中证500 | 中证500 | 000905 |
| 上证50 / 50ETF | 上证50 | 000016 |
| 老登 / 大金融 / 银行 / 保险 / 券商 / 证券 / 白酒 / 酒 | 上证50 | 000016 |
| 沪深300 | 沪深300 | 000300 |
| 上证综指 / 上证 / 综指 | 上证指数 | 000001 |

> **老登板块映射到上证50**：博主口中的"老登"指大盘蓝筹（银行、保险、券商、白酒等），与上证50 高度相关，故映射到 000016。
>
> **其余不可映射的板块忽略，不参与打分**：有色、钢铁、医药、创新药、恒科、电池、航天、军工、房地产等。
>
> **双创 return 口径**：分别用创业板指和科创50 按同一发布时刻（同一参考价 bar）、同一终点日计算各自的 return，取两者算术平均作为该信号的 return（mean-of-returns）。

**7 指数数据表**（`idx` 取值 = `market_data.json` 中的 key）：`上证指数` 000001（大盘基准）/ `上证50` 000016 / `沪深300` 000300 / `中证500` 000905 / `中证1000` 000852 / `创业板指` 399006 / `科创50` 000688。

> **读取方式**：找到对应 key 后，查找 `日期` 字段等于验证日的行，取 `开盘`/`收盘`/`最高`/`最低`/`成交量` 字段。

### §3 验证终点

**核心原则**：信号预测的时间窗口是什么，就验证那个窗口的终点——说"明天"就只看明天，说"下周"就只看下周，**不扩展、不缩短、不随意假设**。LLM 必须根据具体预测周期确定一个精确的验证日期，不能泛化到长度区间

若信号的验证终点为非交易日则顺延至下一个交易日去验证。（编码为today例外）

> **"信号日"指信号发布的自然日**。下表所有"信号日之后第 N 个交易日"均从发布日往后数：周五盘后说"明天涨"→ 明天=周六 → 顺延验证周一；周日说"明天/星期一"→ 验证周一。参考价仍按 §4 定价。

| 信号里的预测周期 | 编码 | 验证终点 |
|:---|:---|:---|
| "今天""今日""下午""今天尾盘" | `today` | 信号日当天收盘（必须交易日发布，否则报错） |
| "明天""明日""次日" | `t1` | 信号日之后第 1 个交易日 |
| "后天" | `t2` | 信号日之后第 2 个交易日 |
| "下周""下周末" | `nweek` | 下周最后一个交易日 |
| "周一" | `monday` | 信号日当周的周一 |
| "周二" | `tuesday` | 信号日当周的周二 |
| "周三" | `wednesday` | 信号日当周的周三 |
| "周四" | `thursday` | 信号日当周的周四 |
| "周五" | `friday` | 信号日当周的周五 |
| "下周一""下周初" | `nmonday` | 信号日下周的周一 |
| "下周二" | `ntuesday` | 信号日下周的周二 |
| "下周三" | `nwednesday` | 信号日下周的周三 |
| "下周四" | `nthursday` | 信号日下周的周四 |
| "下周五" | `nfriday` | 信号日下周的周五 |
| **"X月X日""X月X日之前""X月X日前后"（未来具体日期）** | `d:YYYY-MM-DD` | 该日期本身（若为非交易日则顺延至下一个交易日） |
| "本周""本周内" | `week` | 发布自然日所在那一周的最后一个交易日 |
| "月底前""月末前" | `month` | 当月最后一个交易日 |
| "下个月""下月" | `nmonth` | 下个月的最后一个交易日 |
| "下半年""全年""今年""2026年"等年度预测 | `long` | **不参与打分**（`cat=unscored`） |
| "N天后""N日内"（N 为具体数字） | `tN` | 信号日之后第 N 个交易日（"3天后"→`t3`、"10天后"→`t10`；**N>30（明显远期）→ `long`/unscored 不计分**） |
| "1-2天""3-5天"等"X-Y天" | `tY` | 信号日之后第 Y 个交易日（**取预测窗口的最后一个交易日**，如"1-2天"→`t2`、"3-5天"→`t5`） |
| "未来几天""近期""短期"且无具体数字 | `t5` | 信号日之后第 5 个交易日（未给具体数字，保守默认） |
| "中长期""未来几个月""三年"等 | `long` | **不参与打分**（`cat=unscored`） |
| 无预测周期但有明确预测方向或预测点位 | `t5` | 信号日之后第 5 个交易日（与"近期""短期"同一终点，正常计分并参与多空/两档） |

> **⚠️ 区分未来日期与回顾日期**：帖子中出现日期不等于预测。必须判断该日期是**对未来的预测窗口**（"8月7日之前都是磨底"→ 预测到 8/7）还是**对过去的回顾**（"2月8日我还提醒了一次"→ 不提取）。同一日期只有在预测语境中才按日期规则落档。
> 如果pub晚于spec的验证终点的收盘时间，则视为回顾/收盘，不作为信号，也不计分。

> **数据覆盖检查**：验证终点必须不晚于 `market_data.json` 中对应指数的最后一行日期。若超出覆盖范围，cat="unscored"，不参与打分与汇总，在 §7 汇总表中单列。

### §4 信号参考价

**信号参考价 = 当前所能获取的最新价格**。所有预测周期统一用此参考价：

| 信号时间 | 参考价 |
|:---|:---|
| **交易时间中**（交易日的9:30~11:30、13:00~15:00） | **所处 30 分钟 K 线的开盘价**（bar 时间 = 收盘时间，如 10:20 发布 → 所处 10:30 bar，取该 bar 开盘价）。恰 10:00:00 发布取的是刚开盘那根 10:00 bar（= 该时刻现价），**不回落**上一根 09:30 bar |
| **非交易时间**（交易日盘前 <9:30 / 交易日午休 11:30~13:00 / 交易日盘后 ≥15:00 / 周末假期等非交易日） | **上一根 30 分钟 K 线的收盘价**（如 15:30 发布 → 15:00 bar 收盘价；盘前/非交易日 → 上一交易日 15:00 bar 收盘价） |

> **30 分钟线结构**（`data/market/intraday/<指数名>_30min.json`）：每指数每日 8 根 bar（10:00/10:30/11:00/11:30/13:30/14:00/14:30/15:00），bar 时间 = 收盘时间，首根 bar open≈9:30 开盘价、末根 bar close=当日收盘价。信号参考价与终点价均取自此。
>
> 终点价为验证终点日 15:00 bar 收盘价（= 当日收盘价）。
>
> 无 30 分钟数据时引擎退回日线口径（最新收盘价）。

### §5 打分规则

**score = direction × return × 100**

```
return    = 验证终点收盘价 / 信号参考价 − 1
direction = +1（看多）/ −1（看空）
```

> 参考价按 §4；终点收盘价 = 验证终点日 15:00 bar 收盘（即当日收盘价）。

**示例**：

| 情形 | 参考价 | 终点收盘 | return | direction | 打分 |
|:---|:---:|:---:|:---:|:---:|:---:|
| 看多，涨了 | 3800 | 4020 | +5.79% | +1 | **+5.79** |
| 看多，跌了 | 3800 | 3760 | -1.05% | +1 | **-1.05** |
| 看空，跌了 | 4100 | 4072 | -0.68% | -1 | **+0.68** |
| 看空，涨了 | 4100 | 4120 | +0.49% | -1 | **-0.49** |

### §6 汇总指标

对博主的所有预测信号汇总（计分样本 = 全部计分信号，不限于上证指数）；unscored/报错信号单列，不计入任何指标：

```
信号总数：N
  另有：unscored X 条（spec=long / 终点超出覆盖 / 过时）/ 报错 X 条（单列，不计分）
方向正确：M（正确率 M% = score>0 的信号数 / M，M = 计分信号数）
平均分：+X.XX（= 单信号平均收益 %，核心指标）
波动率：X.XX（单信号 score 样本标准差）
夏普：+X.XX（= 平均分 / 波动率；信号 <2 条或波动率为 0 时显示 —）
最高分：+X.XX / 最低分：-X.XX
看多平均分：+X.XX（N 条）  看空平均分：+X.XX（N 条）
```

> **计分样本口径**：`scored`（全部指标/三个分类表/月度/排名共同只用它）= 该博主的全部计分行，不限于上证指数。

### §7 逐条汇总表

```
| # | 日期 | 内容(≤50字) | 方向 | 预测周期 | 目标指数 | 参考价 | 终点日 | 终点收盘 | return | 分 | 备注 |
|:---|:---|:---|:---|:---|:---|:---:|:---:|:---:|:---:|:---:|:---|
| 1 | 01-07 | 上攻已显疲态，将进入回调 | ↓ | 明天 | 上证 | 4083 | 01-08 | 4072 | -0.27% | +0.27 | — |
| 2 | 01-09 | 明天A股绝地反击 | ↑ | 明天 | 上证 | 4120 | 01-12 | 4165 | +1.09% | +1.09 | — |
```

> **方向列**：`↑` = d=+1（看多）、`↓` = d=−1（看空）。
>
> **备注列**：正常信号填 `—`；盘中"今天"（日内窗口计分）填 `日内`；不计分信号（spec=`long` / 终点超出覆盖 / 过时）填 `不计分`（覆盖/过时由引擎改判 cat=unscored）；非交易日发布的"今天"填 `报错`（由引擎自动判定）。unscored/报错信号不参与打分与 §6 汇总。

### §8 报告输出

**个体报告**：`python scripts/eval/run_direction.py [博主名]`（不传参数则跑全部博主）→ `reports/<博主名称>_direction.md`，含：
- 头部：评估时间（= 最新交易日）、帖子总数（posts 缺失时标"未知"）、信号总数
- 汇总指标：按 §6
- **三个分类表**（每表统计全部计分信号、含 信号数/平均分/胜率/波动率/夏普）：① 按预测指数；② 按预测周期两档归类（算法见本节末）；③ 按看多看空
- 月度表现：按信号发布月份统计
- 信号时间分布与集中度（⚠️ 必须提出警告）：覆盖 <3 个月 ⚠️覆盖不足；单月占比 ≥50% ⚠️高度集中、33%~50% 轻度集中；相邻月份缺 ≥3 个月 ⚠️严重缺口、缺 1-2 个月提示。典型场景：停更/减产、帖子数据缺失、标注未完成
- 逐条汇总表：按 §7
- 观察要点：正确率结论、多空对比、最强/最弱档与指数、最大单条命中/失误、单列信号统计

**横向对比**：`python scripts/eval/comparison_all.py` → `reports/comparison_direction.md`，只需要各榜单（**榜单口径 = 全部计分信号**）：
- **总榜**（全部计分信号；**按夏普排序**，附计分信号数/正确率/**平均分**/波动率/夏普/多空数）——**排名资格：计分信号 ≥ 30 条 且 平均分 > 0.1 且 正确率 > 50%**，不满足条件者不参与排名、单列注明（统计无意义）
- **按预测周期分类的两档归类，各档排名**（**按夏普排序**）——**超短期档：该档信号 ≥ 30 条 且 平均分 > 0.1 且 正确率 > 50%；波段档：该档信号 ≥ 10 条 且 平均分 > 0.2 且 正确率 > 50%；各档表格形式与总榜相同**（排名/博主/信号数/正确率/平均分/波动率/夏普/看多/看空）
- **方向榜单**：看多榜 / 看空榜（看多= d=1、看空= d=-1；资格同超短期档排名；按夏普排序；表格形式与总榜相同）
- **信号覆盖/集中度警告**（同上述阈值，逐博主列出）

**预测周期两档归类的详细算法**（实现位置：`scripts/eval/run_direction.py` 的 `bucket_of()`，`comparison_all.py` 直接复用，与引擎共用同一交易日历与 prev_td 逻辑）：

```
交易日历 CAL = market_data.json 中"上证指数"的日期序列（升序）
基准日 base = pub_date 若 pub_date ∈ CAL，否则 = 其前最近一个交易日
跨度 span = CAL.index(ep) − CAL.index(base)     # 信号日→验证终点的交易日数量
分档：span ≤ 1 → 超短期（0-1个交易日）| span ≥ 2 → 波段（2个交易日及以上）

边界示例：
  - 周五发布"明天"→ ep=下周一，span=1 → 超短期
  - 周一发布"下周初"→ ep=下周一，span=5 → 波段
  - 周一发布"下周"→ ep=下周五，span=9 → 波段
  - 周六发布"明天"→ base=周五，ep=下周一，span=1 → 超短期
```
