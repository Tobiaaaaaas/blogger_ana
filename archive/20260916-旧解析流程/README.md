# 20260916-旧解析流程 —— 退役的两件

02 解析流程在 2026-09-16 换了读法（见 `docs/02-llm解析.md` §10）。这一份归档放的是**换之前那套读法自己带来的两件工具**：一把尺子、一环流程。它们不参与生产，但判例与旧基线是它们量出来的，留着才好对账。

## `jitter.py` —— 那把尺子

把全库在同一份输入上判两遍，逐帖比三元组，分「甲／乙／丙1／丙2／丙3／丁」六组。`docs/判例/第一轮.md` 与 `docs/判例/第二轮.md` 那 42 条裁定，就是它 `draft` 出草稿、人填出来的；旧基线「343 条（18.7%）」也是它量的。

**它还是跑得起来的** —— 它调的是 `blogger.parse.extract` 与 `blogger.report.flow`，那两个入口换代没改名，所以 `run`／`cmp`／`draft` 照常能跑。（目录名带连字符与中文，`-m` 走不通，要点名跑就直接 `python archive/20260916-旧解析流程/jitter.py cmp …`。）

**退役的理由是它量的东西没了。** 六组判定的前提是「一遍产出一个三元组、两遍摆在一起比」——旧流程里模型自己划表述的边界、自己写引文、自己给的档位与对象，所以两遍之间什么都可能不一样。新流程里切句、查表、切引文全归代码，模型只对**编好号的句子**给方向；能飘的只剩「这一句算不算」和「算的话往哪边走」。两个分量，不是六个。

**尺子退役，判例不退役。** 42 条裁定与新流程仍然逐条对得住 —— 尺子换了，被量的东西没换。所以 `research/semparse/compare.py` 里那份 `classify` 与 `GROUPS` 是**从这里原样抄过去的，一字未改**：判例与新基线既然是这把尺子量的，换一份实现就等于换了一把尺子，量出来的差说不清是流程的差还是尺子的差。

## `reconcile.py` —— 复核那一环

旧流程的第三轮：两遍对不上的帖，逐条判每个候选该不该算，算的留下、不算的丢掉并归格。**它不落地** —— 是一次实验（`_new3`／`_new4`），结论进了 `research/semparse/reports/第三轮-复核.md`，代码没有进 `blogger/`。

**这一份是快照，读得懂、跑不起来**：它 import 的 `research.semparse.{annotate,assemble,prompts,segment}` 与 `prompts.RECONCILE_PROMPT` 都已随这一轮删掉。留它是因为「候选只给编号、不给两遍的答案」这条取舍是从它身上实测出来的（见下）。

**为什么没有进。** 它的收益全在「把两遍的并集变成逐条审过的并集」，而新流程的 ② 本来就不是两遍取并集 —— 第二遍看得见第一遍的表态（复读，02§10.2），以最后一遍为准。复核那一环要回答的「这一句本身算不算」，新流程在第二遍就已经问过了。

**一处设计留了下来**：候选名单**只给句子编号，不给两遍的答案** —— 实测「框定会压过规则」，把旧答案摆在眼前模型多半照着抄。这条与复读是**相反**的取舍，两边都实测过：复核要的是「别被锚住」，复读要的正是「看一看锚住会怎样」。所以复读的第二遍是明知会锚、还要量它能纠多少错。
