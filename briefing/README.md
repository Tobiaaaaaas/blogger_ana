# 优质博主观点简报系统（briefing）

实时追踪两批已筛选博主（对大盘观点可靠）的帖子，把**超短板块**与**波段板块**各自的观点收敛成**各自一张速览卡**，交易日两卡统一节奏推进、非交易日只推进波段卡，各推各的飞书群。

**v13（2026-09-03）拆两群两卡** → **v14（2026-09-04）窗口改交易日口径** → **v15（2026-09-07）节奏统一 + 波段窗口 5 交易日** → **v17（2026-09-08）共享标注模块（opinion/）** → **v18（2026-09-08）逐帖标注缓存**（每帖读了即存，只标新帖/正文回填，旧帖永不重评分） → **v19（2026-09-08）解析加固**（到案契约 / quote 逐字门 / 上卡复核 / 失败回退，见「解析加固」节）：
- **⏱️ 超短卡**（21 人 · `今天/明天` 表态，扫 **前一交易日 00:00 至 now**）→ **旧群**。
- **🌊 波段卡**（30 人 · `近日/本周/下周/更长/未提` 可计分表态，扫 **前 5 个交易日 00:00 至 now**）→ **新群**（env `FEISHU_WEBHOOK_URL_SWING`）。
- **两板块同一节奏（v15 统一）**：交易日 **09:00–15:00 每 30 分钟**（含午休与 09:00 盘前）+ **16:00–22:00 每整点** → 每档**两卡都推**、各推各群；**非交易日只推波段卡**：09:00–21:00 每 3 小时（09/12/15/18/21）——周末博主常发下周观点，波段卡照常出。
- 窗口按**交易日**回看（非自然日）：周一早晨天然含上周五"看周一"的帖，消除 v13 已知取舍。无明确周期的波段表态（近日/更长/未提）如实标注、不编造目标日期。
- 两板块**各自读帖、各自锚定、各自计数、各自收敛总结**——卡尾只总结本板块观点，不存在"跨板块层叠/两层对立"措辞；两卡完全独立。
- **日期锚定（v12 保留）**：板块行头与引文时间一律绝对日期——超短行头=目标日（`看空 · 明天(09-03)`），波段行头=锚定周（`看多 · 本周 08-31~09-04`）。博主帖里 今天/明天/本周/下周 一律按其**发帖日**换算成绝对目标，目标已过（超短目标日≠今/下一交易日、波段目标周已整体过去）自动不再显示。
- **行头周期词 spec 固定显示**：每个博主观点行必带周期词、绝不缺省——超短=今天/明天（并列锚定目标日，如 `看多 · 明天(09-04)`）；波段 anchor 已含周词/周期词（本周+周段 / 近日 / 更长）；周期未提（波段"当前这波"无日历词）→ 行头显示 `周期未提`。
- **每档必发、无 🆕 标记**：有观点→整版全卡；本板块零表态→该板块最小卡；内容没变也照发。
- **帖子增量复用**：抓取水位 `fetched_at` 与推送水位 `last_run` 分离；行抽取缓存 `rows_cache.json`（v5：**逐帖**规范行，键 = post_id + 内容 hash，`opinion.cache`）——每帖只被标注一次：只有窗口里新出现/正文回填变 content 的帖才送 LLM（该博主新帖合成一个子批一次调用），旧帖（含跨交易日窗口滑动重叠帖）**永不重评分**；坍缩 `collapse_board` 每档确定性重算、只取本次窗口帖的行（v18）。

## 板块口径

- **两个固定名单板块**（口径/来源见 `briefing/scripts/config.py` docstring，勿在 README 复述）：
  - **⏱️ 超短(0-1日)** 21 人（2026-09-07 质量筛选换名单，旧 17 人已注释保留在 config）：每人取 **前一交易日 00:00 至 now**（交易日窗口）内的「今天/明天」表态，**只显示目标日 = 卡片当天或下一交易日**者，行头 = 周期词(今天/明天) + 目标日 MM-DD（如 `明天(09-03)`）；
  - **🌊 波段(2日+)** 30 人：每人取 **前 5 个交易日 00:00 至 now** 内**可计分**的波段周期表态（近日/本周/下周、近月窗口、当前这波/本轮波段阶段；口径同打分引擎 SKILL §3），本周/下周 按**发帖日**锚定到具体周一~周五周，**目标周已整体过去的剔除**，行头 = 周词（相对卡片日）+ 周日期段；近日/更长 用词如实标注；周期未提（讲"当前这波"无日历词）→ 行头显示 `周期未提`——均不编造目标日期。**不计分观点直接不上卡**（即使方向明确也不进多/空、不显示、不进收敛总结）：年度/跨年/超远期（今年/明年/2026年/未来N年…）、中长期/长期趋势断言（漫漫熊途/慢牛/长期…）、无时间承诺的目标点位（只说点位没说到哪天/哪个波段阶段）。
  - **窗口口径（v14 交易日；v15 波段 3→5）**：窗口按**交易日**回看（超短 前 1 个交易日、波段 前 5 个交易日，起点日 00:00 至 now；`config.WINDOW_TRADING_DAYS`，回看用 `calendar.n_trading_days_ago`），非自然日——周一早晨窗口天然含上周五帖，无 v13"周一漏帖"取舍。
  - **板上只认上证（2026-09-08）**：两卡行只取 `idx=上证指数`（`collapse_board` 门；创业板/科创50/上证50/双创 等他指行留缓存供报告侧）。同一帖对 上证/大盘 与他指有不同看法 → 标注按被预测指数拆成各 idx 行（见 `opinion/prompts.py`「同一帖多指数」节）；上证只作状态/背景（趋势之上/无顶背离/安心持股…）的句子不产生上证行。
- **只显示仍有本板块有效方向观点的人**（超短目标已兑现、波段目标周已过者自动不显示）；未表态者不点名、不占行、不计入表态数。板块头部计数带覆盖度：`4多/2空（6/21 表态）`。
- 板块某档零人表态 → 仍发一张该板块最小卡（区分「近窗口无人发帖」与「有人发帖但无该板块方向观点」）。
- 行 = 该博主**本板块最新一条该周期表态**，带**逐字原话**（系统回填真实发帖时间，绝对 `MM-DD HH:MM`）与**摘要**；摘要不含 今天/明天/本周 等相对时间词（系统侧剥离）；无编号，按名单顺序排。
- **总结只讲本板块**：同板块内真反向才算分歧；清一色同向/仅 1~2 人表态就直接陈述方向。同板块同方向但操作取向相反写"共识下的操作分化"。

## 解析加固（v19，2026-09-08 定稿 / 09-09 quote 门校准）

LLM 解析是全链路唯一有随机性的上游（打分/坍缩/锚定均已代码规范化）——v19 把**解析过程「每条帖必须到案」、解析结果「每条字段被强制进规范」**。分四根柱子，全部只在推送路径生效（报告侧有自身 verify+runs，不共享改动）：

- **A 逐帖到案契约**（`opinion/schema.py` `NO_VIEW_REASONS` / `opinion/annotate.py`）：协议增并列键 `no_view`（`复盘回顾/状态描述/转述他人/仓位或理念/无明确方向/仅他指或板块非大盘/无实质内容`），要求批内每条帖都交代去向——`rows[].post_n ∪ no_view[].post_n` 覆盖全部渲染帖，模型不许跳读漏判。缺到案 → 带错重试 1 次 → 仍缺 → 该博主本档按**失败**处理（走 D 失败回退，下档自动重试）。指令作 **user message 后缀**注入（`DISPOSITION_SUFFIX`），不进共享 system prompt——离线报告批不受影响，prompt 指纹口径不变。硬契约只一条（全覆盖）；rows∩no_view 重叠 / no_view 重复 / 理由出枚举 属结构小错，`_clean_no_view` 自动化解不拦成功。
- **B quote 逐字门 + spec 语义域**（`opinion/text.py` `split_quote/verbatim_in`、`opinion/schema.py` `spec_sane`）：scored 行 quote 必须**逐字出自该帖模型可见文本**（片段按序、允许 `…` 跨段桥接），不符 → 带错重试 1 次 → 仍不符 → 弃该行（不弃整博主）。门的能力边界是**字级**增删/改写/串帖/逆序（真伪校验）——**2026-09-09 校准**：匹配前对两侧做**版式归一**（去 空白 + CJK 句读），「一句一换行」散文帖被模型折成句读不再误判编造（Mac dry-run 实测 香满衣 整博主编造假失败即此因）；ASCII 小数/连字符不归（防 `3.5万→35万` 量级错位）。句首时间词被截（#J/#N 类，截后剩余片段仍连续、门照旧放行）由 prompt 句首纪律 + Pillar C 兜。`spec_sane`：`tN` 须 `N≥1`、`d:YYYY-MM-DD` 须真实历法日期，否则弃行。canonical quote 上限 `[:60]→[:90]`（展示截断改由 collapse 单独做，不再反噬缓存原文）。
- **C 上卡复核（只复核"会改卡的模型新产出"）**（`opinion/verify.py` + `briefing/scripts/summarize.py`）：坍缩后再对本 tick **新标注帖**产出、且**真上卡**的少数行跑一次 keep/fix/drop 复核（主结论句 doctrine，同报告侧 verify 结构）。fix → 按修正字段改展示行；drop → 剔该帖该板行重坍缩（更早仍在窗口的合格行按路过语义续显，无则置空）；复核调用失败/超时 → 保留候选行（不因复核故障吞正常行）。触发集严格控制：纯缓存命中的旧行、窗口滑动/过期等确定性变化**不触发**——每档复核量 = 实际改到卡面的少数博主。quote 逐字门挡字级伪，这里兜 **idx 对象/周期与主结论句的一致性**（如 房地产 帖被模型标成上证行、条件式"涨/跌/震荡都给"被当方向）。
- **D 失败回退旧行，"无观点"仍空**（`briefing/scripts/summarize.py` `extract_layers`）：区分 annotate 返回 `None`（调用失败/到案仍缺/结构异常）vs `rows`（可空=真无观点）。`None` → **不抹窗口内已缓存旧帖行**，坍缩回退续显（`quote_ts≥窗口下界` 门自动拦陈旧），不写缓存、记入 errors 下档重试；`rows==[]`（真无观点）→ 卡面空维持现状。v18"逐帖读了即存"不因失败把漏判帖缓存成 `[]` 粘住。

## 数据流（单档，v15）

```
节奏命中：交易日 config.in_trading_grid（09:00–15:00 每30分 / 16:00–22:00 整点）→
  两板块各一张卡；非交易日 config.in_restday_grid（09:00–21:00 每3小时）→ 只波段卡。
  离节奏伪 tick 在抓取/锁之前 exit 0（不碰锁不碰状态）
  → 各板块滚动窗口（v14 交易日；v15 波段 5 日）：short = 前一交易日 00:00 → now；swing = 前 5 个
    交易日 00:00 → now（config.WINDOW_TRADING_DAYS；起点日由 calendar.n_trading_days_ago）
  → 增量抓取新帖（since = fetched_at 爬虫水位，抓 ALL_BLOGGERS=40 去重全集）——
    抓取+merge 完成即写 fetched_at=wall（不等推送成败）
  → 行情背景（腾讯行情：上证/深成/创业板 + 两市成交额）一次，两卡共用
  → 逐板块：读窗口帖 → DeepSeek 行抽取（rows_cache 命中则跳过 LLM 复用缓存行；
    缓存行每档仍 resolve_anchors 重新锚定）→ 只保留 has_view 本板块周期行
  → resolve_anchors 日期锚定 + 过期剔除（行带 anchor）
  → board_counts 系统计数 → 有方向观点 → summarize_board 本板块收敛总结一段 + 全卡；
    零表态 → 本板块最小卡
  → 各板块渲染成独立 interactive 卡 → 各推各群（render.webhook_for 读
    WEBHOOK_ENV；该板块 webhook 缺失按失败处理，绝不回落 FEISHU_WEBHOOK_URL）
  → 全板块推完推进 last_run/last_slot 原子写 state；历史文件名
    {wall:%Y%m%d}_{HHMM}_{board_key}.json
```

## 运行

```bash
# 本机试跑（落盘预览，不推送、不改状态）：
python -m briefing.scripts.run_briefing --dry-run --time 09:30 --board both --no-scrape
python -m briefing.scripts.run_briefing --dry-run --time 11:00 --board swing --no-scrape --skip-calendar

# 生产调度（墙钟判定板块与档位；非交易日只推波段、离节奏自动 exit 0）：
python -m briefing.scripts.run_briefing --push

# 暖场/手动补推双群（跳过门禁）：
python -m briefing.scripts.run_briefing --push --time 09:30 --board both

# 冒烟：只抓前 3 位博主
python -m briefing.scripts.run_briefing --push --board short --max-bloggers 3
```

`--time HH:MM` 只覆盖**决策时刻**（窗口/锚定/标题措辞），state/历史文件名/水位一律用真实墙钟。依赖环境变量：`DEEPSEEK_API_KEY`（DeepSeek）、`FEISHU_WEBHOOK_URL`（超短群）、`FEISHU_WEBHOOK_URL_SWING`（波段群）。从 `briefing/.env` 或父仓库 `.deepseek_keys.env` 自动加载。

## 设计要点

- **两群两卡两总结**：名单固定分组，各自只谈各自板块周期；卡尾总结绝不掺另一板块，杜绝"跨板块层叠/对立"措辞。
- **两窗口分离**：展示 = 各板块滚动窗口（现读主文件）；抓取 = 增量 since `fetched_at`（40 人全集，共享博主只抓一次、按两板块各读各的窗口）。
- **每档必发**：有观点整版、空板最小卡；无 🆕 比较标记——统一节奏下"变化"由人眼对比上一卡。
- **增量省费**：行抽取缓存 rows_cache.json（v5 逐帖：键 = post_id + 内容 hash，含正文内容），每帖只标注一次——只有窗口里新出现/正文回填变 content 的帖才送 LLM（该博主新帖合成一个子批一次调用），旧帖永不重评分（引文时间落窗为二道防御）；缓存的是未锚定行，目标日随卡片日变 → 每档仍重新锚定。每档每板块仅一次本板块收敛总结（行情/措辞最新）。
- **水位分离**：`fetched_at`（抓完即写）与 `last_run`（推完才写）分开——推送失败下一档不重抓已抓过的增量；webhook 失败有错误心跳。
- **不编造**：LLM 失败 / 无该板块周期观点 → 本板块不显示不计数（log）；板块 webhook 缺失 → 该板块失败心跳，绝不误发另一群。
- 时段/日期/窗口全用北京时（`BEIJING_TZ`），独立于宿主机时区。
